# Phase 10 — UI Design Contract

> 작가의 API 키 등록·검증·삭제와 모델별 결제 주체 표시를 위한 시각·상호작용 계약. 검증 전 `10-CONTEXT.md`의 D-01~D-13을 고정 결정으로 따른다.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (`components.json` 존재) |
| Preset | `base-nova`, `neutral`, CSS variables; 기존 설정 페이지의 `max-w-2xl`, 테두리 카드, 폼 배치를 연장 |
| Component library | Base UI (`@base-ui/react`); 기존 `Button`, `Input`, `Badge`, `Select`, `Dialog` 재사용 |
| Icon library | lucide-react; 아이콘은 텍스트를 보조하며 상태를 아이콘만으로 나타내지 않음 |
| Font | Geist Sans (`app/layout.tsx`), 기존 `font-sans` |

**페이지 구조:** `/studio/settings/ai-providers`의 기존 제목과 `계정 기본값` 카드 바로 아래에 `내 API 키` 섹션을 둔다. 섹션 첫머리에 한 줄 설명과 `키 검증은 모델 목록 조회로 진행되며 생성 요금은 발생하지 않아요.`를 놓는다. OpenAI → Anthropic → Gemini 순서로 카드 3개를 한 열에 배치한다. 각 카드는 제공자명, 상태, 등록 정보 또는 입력 폼, 상태별 행동을 포함한다. 모바일에서도 한 열을 유지하고 입력·버튼은 좁은 폭에서 세로로 쌓는다. 기존 기본값 설정과 키 관리는 한 페이지에서 갱신되며 중복 페이지를 만들지 않는다. [출처: `10-CONTEXT.md` D-10~D-13, `09-CONTEXT.md` D-04, 기존 설정 페이지]

**화면에 표시할 정보:** 등록된 카드는 `OpenAI · 연결됨`, `끝 4자리 1234`, `등록일 2026. 9. 29.`처럼 제공자·끝 4자리·등록일·상태만 보여준다. 평문이나 앞자리, 키 길이, 복사/보기 버튼은 없다. `검증 실패` 카드에는 같은 마스킹 정보와 `다시 확인`, `삭제`를 유지하고 피커의 BYOK 항목은 숨긴다. 미등록 카드에만 키 입력과 `등록` 버튼을 표시한다. 키 교체 안내는 `키를 바꾸려면 기존 키를 삭제한 뒤 새 키를 등록하세요.`로 고정한다. [D-03, D-13]

## Spacing Scale

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 상태 배지와 글자, 짧은 도움말 간격 |
| sm | 8px | 라벨과 입력란, 카드 내 정보 행 |
| md | 16px | 카드 내부 요소 및 버튼 간격 |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label / button / provider name | 14px | 600 | 1.5 |
| Section heading | 18px | 600 | 1.2 |
| Page heading | 24px | 600 | 1.2 |

3개 크기(14/18/24px; 표의 Body·Label은 같은 크기), 2개 굵기(400/600)만 사용한다. 보조 설명도 14px을 유지해 오류·마스킹 정보를 읽기 쉽게 한다. 페이지 제목은 기존 `text-2xl`, 섹션 제목은 기존 `text-lg`에 맞춘다. [출처: 기존 설정 페이지; 줄높이·굵기 정리는 UI 기본값]

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` = light `oklch(1 0 0)`, dark `oklch(0.145 0 0)` | 페이지와 입력 바탕 |
| Secondary (30%) | `bg-card` = light `oklch(1 0 0)`, dark `oklch(0.205 0 0)`; `border-border`, `bg-muted` | 키 카드, 기본값 카드, 보조 표면 |
| Accent (10%) | `bg-primary` = light `indigo-600`, dark `indigo-500`; `text-primary` / `ring` | `등록`, `기본값 저장`, 포커스 링, 선택된 모델의 강조 |
| Destructive | `text-destructive` / `bg-destructive` = 기존 light `oklch(0.577 0.245 27.325)`, dark `oklch(0.704 0.191 22.216)` | 삭제 확인 버튼과 오류 문구 |

Accent reserved for: 주요 저장·등록 버튼, 키보드 포커스, 선택된 모델 표시. `BYOK` 배지는 기존 `Badge`의 `secondary`, `서비스 키`는 `outline`로 구분하며 두 배지 모두 문자 라벨을 필수로 넣는다. `연결됨`은 중립 배지와 텍스트, `검증 실패`는 오류색 텍스트와 라벨을 함께 쓴다. 색상만으로 결제 주체나 상태를 전달하지 않는다. 새 색 토큰이나 제3자 스타일을 추가하지 않는다. [출처: `app/globals.css`, `components/ui/badge.tsx`; 배지 배분은 UI 기본값]

| Loading | `키를 확인하는 중…` (등록·수동 재검증 중 각 버튼과 `role="status"`) |

| Recheck success | `{제공자} 키를 다시 확인했어요. 사용 가능한 모델 {N}개를 확인했어요.` |
| No catalog match | `키는 확인됐지만 현재 제공하는 모델은 없어요. 모델 목록이 업데이트되면 표시돼요.` (키는 연결됨; BYOK 항목 0개) |
| Delete success | `{제공자} 키를 삭제했어요.` 기본값이 바뀌었다면 `기본 모델이 {모델명} [서비스 키]로 바뀌었어요.`를 같은 상태 알림에 추가 |
| Replacement help | `키를 바꾸려면 기존 키를 삭제한 뒤 새 키를 등록하세요.` |
| Phase 10 BYOK send boundary | `BYOK 모델 호출은 아직 준비 중이에요. 지금 생성하려면 [서비스 키] 모델을 선택하세요.` |

**등록 오류는 입력란 바로 아래 `role="alert"`로 표시한다.** 원문 키, 요청 헤더, 제공자 응답 본문, 키의 앞자리, 벤더 원문 오류는 어떤 문구에도 넣지 않는다. 실패 시 입력값은 보안상 비우고, 재입력을 안내한다. [D-11, D-12]

| 원인 | 오류 문구와 다음 행동 |
|------|----------------------|
| 형식 오류 | `키 형식을 확인해 주세요. {제공자}에서 발급한 API 키를 다시 입력하세요.` |
| 401 무효 | `유효하지 않은 키예요. {제공자}에서 키를 확인하고 다시 입력하세요.` |
| 403 권한 부족 | `이 키로 모델 목록을 볼 권한이 없어요. {제공자} 계정의 권한을 확인하세요.` |
| 429 한도 초과 | `제공자의 요청 한도에 도달했어요. 잠시 뒤 다시 시도하세요.` |
| 제공자 장애·타임아웃 | `지금 {제공자}에 연결할 수 없어요. 잠시 뒤 다시 시도하세요.` |
| 저장·삭제 등 내부 오류 | `처리하지 못했어요. 잠시 뒤 다시 시도하세요.` |

**삭제 확인 제목:** `{제공자} 키를 삭제할까요?` 본문은 `BYOK 모델 {N}개가 모델 선택 목록에서 사라져요.`를 포함한다. 해당 키가 기본값이면 `기본 모델이 {대체 모델명} [서비스 키]로 바뀌어요.`를 추가한다. 끝에 `삭제한 키는 복구할 수 없어요. 다른 키를 사용하려면 삭제 후 다시 등록하세요.`를 붙인다. 버튼은 `취소`(초기 포커스)와 `삭제`(destructive)다. 기본값이 해당 키가 아니면 기본값 변경 문장을 표시하지 않는다. [D-08, D-09]

## Interaction Contract

1. **등록:** 미등록 카드에는 `type="password"` 입력과 `등록`을 둔다. 등록 중 해당 폼을 잠그고 버튼에 진행 상태를 표시한다. 검증 성공 후에만 카드가 `연결됨`으로 바뀌며 끝 4자리·등록일·확인된 카탈로그 모델 수를 갱신한다. 실패 시 카드는 `미등록` 그대로이고 입력란 밑에 위 원인별 문구를 표시한다. 제공자별 1개 제한으로 등록된 카드에는 입력 폼을 보여주지 않는다. [D-10~D-13]
2. **수동 다시 확인:** 등록된 카드의 `다시 확인`은 키 재입력 없이 모델 목록을 다시 조회한다. 작업 중 그 카드의 재확인·삭제 버튼을 잠그고 완료 후 상태와 피커 목록을 갱신한다. 401/403 등 키 자체의 검증 실패는 `검증 실패` 상태로 표시하고 BYOK 항목을 숨긴다. 일시 장애·429는 기존 저장 상태를 임의로 바꾸지 않고 오류를 알린다. 자동·주기 재검증은 없다. [D-03, D-05, D-12]
3. **삭제:** 삭제 버튼은 먼저 영향 안내 다이얼로그를 연다. 카드가 가진 BYOK 모델 수와 기본값 대체 결과를 확정된 정보로 표시한 뒤 `삭제`를 누를 때만 실행한다. 완료되면 카드는 `미등록`, 관련 BYOK 피커 항목은 제거된다. 기본값이 삭제된 BYOK 항목이면 같은 모델의 서비스 키 항목으로, 없으면 `Gemini 3.5 Flash [서비스 키]`로 바뀐다. 삭제 실패 시 다이얼로그 안에 오류를 띄우고 카드는 유지한다. [D-08, D-09]
4. **설정 페이지 기본값 선택:** 기존 `계정 기본값` 셀렉트에도 모델명과 `[BYOK]`/`[서비스 키]` 텍스트를 함께 표시한다. BYOK 기본값은 키가 `연결됨`이고 검증된 모델과 카탈로그가 교차하는 경우에만 선택할 수 있다. 저장 성공/실패 안내는 기존 페이지 패턴을 유지한다. [D-04~D-07]
5. **AI 패널 모델 피커:** 제공자 그룹은 기존 순서(Gemini → OpenAI → Anthropic)를 유지하되 그룹 경계를 뚜렷하게 나눈다: 각 그룹은 `bg-muted` 밴드의 헤더(`text-xs font-semibold`, 제공자 표시명 `Google Gemini` / `OpenAI` / `Anthropic` + 우측 `{N}개`)로 시작하고, 두 번째 그룹부터 위에 `border-t border-border` 구분선과 8px 위 여백을 둔다. 헤더는 선택 불가이며 `role="group"` + `aria-label`(제공자 표시명)로 묶는다. 새 색 토큰·브랜드 색·로고 이미지는 쓰지 않는다. 닫힌 트리거와 `계정 기본값:` 안내에는 모델명 앞에 제공자 표시명을 함께 표기한다(예: `OpenAI · GPT-4o mini [BYOK]`). 그룹 안에서는 카탈로그 순서대로 각 모델의 `[서비스 키]`를 먼저, 해당 모델이 BYOK로도 검증됐으면 바로 다음 행에 `[BYOK]`를 둔다. 같은 모델명이라도 별도 선택값이다. 닫힌 트리거, 열린 항목, `계정 기본값:` 안내 모두 모델명과 배지를 함께 보여준다. 검증 실패·미등록·카탈로그 밖 모델은 BYOK 목록에 없다. 계정 기본값이 아닌 항목 선택은 한 번 전송에만 적용되고 다음 전송은 기본값으로 돌아간다. [D-04~D-07, Phase 9 D-05]
6. **생성 경계:** Phase 10에서는 BYOK 생성·토큰 차감 우회를 구현하지 않는다. 이 단계에서 BYOK 항목을 선택했거나 기본값으로 복원됐다면 `보내기`를 비활성화하고 위 `BYOK 모델 호출은 아직 준비 중이에요…` 문구와 서비스 키 선택 경로를 제공한다. BYOK 선택을 서비스 키 호출로 조용히 바꾸지 않는다. 서비스 키 선택 시 기존 비용 추정과 생성 동작을 그대로 사용한다. Phase 11에서 BYOK 호출이 구현되면 이 임시 비활성 상태를 제거하고 비용·실패 UX를 그 단계의 계약으로 갱신한다. [Phase 10 경계, Phase 11 범위, BYOK 자동 폴백 제외]

**접근성:** 입력 라벨을 필드에 연결하고 오류는 `aria-describedby` 및 `role="alert"`로 연결한다. 비동기 성공은 `role="status"`, 키 검증 중 버튼은 `disabled`와 진행 텍스트로 알린다. 삭제 다이얼로그는 제목·설명에 접근 가능한 이름을 부여하고 닫힐 때 삭제 버튼으로 포커스를 돌린다. 배지 문구는 접근 가능한 선택 이름에도 포함한다. 키보드만으로 등록·다시 확인·취소·삭제·모델 선택을 수행할 수 있어야 한다.

## Checker Recommendations (non-blocking, 실행 시 반영)

- 제공자 카드 3개가 같은 버튼을 반복하므로 `aria-label`에 제공자명을 포함한다(예: `OpenAI 키 삭제`, `Anthropic 키 등록`).
- 초점: 설정 페이지에서는 `계정 기본값` 카드가 먼저, 그 아래 첫 미등록 카드의 `등록` 버튼이 시선을 끈다. AI 패널 피커에서는 선택된 항목과 그 배지가 먼저 보인다.
- 라이트 모드 `bg-background`와 `bg-card`가 같은 색이므로 구분은 `border-border`/`bg-muted`로만 하고 별도 표면색을 추가하지 않는다.
