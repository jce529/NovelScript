## Spacing / Typography

간격은 4의 배수 스케일(4·8·16·24·32·48·64)만 쓴다. 목업의 6px·10px·18px·28px·56px은 구현 시 8·8·16·24·56→48로 정리한다. 컨테이너 `max-width:1152px`, 좌우 패딩 16px, 섹션 간격 24px, 그리드 간격 16px.

글자 크기는 네 토큰: 12px(칩·보조·날짜), 14px(본문·버튼·카드 제목), 18px(소제목·빈 상태 제목), 24px(작가 이름 h1). 목업의 11/13/15/22px는 12/14/14/24px로 정리한다. 굵기는 400, 600 두 가지. 본문 line-height 1.5, 제목 1.2. 터치 영역은 모든 버튼·칩·카드 링크가 44px 이상(목업의 36px 필터·정렬 칩은 44px로 올린다).

## Color

60% dominant(페이지 배경 neutral), 30% secondary(프로필 카드·작품 카드·칩 흰 배경과 border), 10% accent(indigo).

accent 예약 목록(이 화면에서 accent를 쓰는 곳은 이것뿐):
1. `작가 알림 구독` 버튼의 구독 전 상태 배경(주 CTA)
2. 선택된 상태 필터·정렬 칩의 선택 표시(목업의 검정 채움 대신 기존 `Tabs`/세그먼트 선택 규칙을 따르되 accent 외곽선 또는 채움 중 하나로 통일)
3. 키보드 포커스 링
4. 작품 카드의 인기·연독률 강조 텍스트는 accent를 쓰지 않고 foreground를 쓴다

`구독 중` 상태는 accent 채움이 아니라 outline(흰 배경 + border + 체크 아이콘)으로 구분해 "이미 켜짐"이 주 행동처럼 보이지 않게 한다. destructive 색은 이 phase에서 쓰지 않는다(구독 해제는 파괴적 행동이 아니며 확인 팝업 없음). 연재 상태 칩(`연재중`/`완결`)은 색이 아니라 텍스트로 구분한다. 다크 모드도 기존 토큰을 그대로 따르며 새 색 토큰은 추가하지 않는다.

## 1·2. 작가 페이지 구성

주 화면 초점: 프로필 카드의 필명 h1과 구독 버튼, 그다음 작품 그리드.

위에서 아래 순서: 공용 독자 헤더(메인 탭은 내서재·랭킹 등 어디에도 활성화하지 않는다) → 뒤로 가기 링크 → 프로필 헤더 → 필터·정렬 바 → 작품 그리드 → 더보기 → 안내 문구.

### 뒤로 가기 링크
- 목업의 `‹ 검색 결과로`는 `document.referrer`에 의존하지 않고, 진입 경로를 모르면 `‹ 이전 화면으로`(`router.back()`, 히스토리 없으면 `/`)로 둔다. 진입이 검색이면 검색 결과로 돌아간다. 높이 44px.

### 프로필 헤더 (카드)
- 데스크톱: 가로 배치. 좌 아바타 원 84px(프로필 이미지 필드 없음 — 필명 첫 글자를 `font-size 24px 600`으로 중앙에 놓은 그라디언트 원, `aria-hidden`), 중앙 정보, 우 구독 영역(최소 폭 160px).
- 모바일: 세로 배치. 아바타 64px + 이름을 한 줄로, 소개, 통계 칩 줄, 구독 버튼은 카드 하단 전체 폭(높이 44px).
- 정보: `<h1>` 필명(`pen_name`, 24px/600, 길면 2줄 말줄임), 소개(`pen_name_bio`, 14px, 4줄 `line-clamp`(펼침 토글 없음), 접근성 트리에는 전체 텍스트가 있음), 비어 있으면 소개 줄을 아예 그리지 않는다.
- 통계 칩 4개(12px, `Badge`): `작품 N편` · `연재중 N편` · `완결 N편` · `구독자 N명`. 숫자는 천 단위 쉼표. 4개를 한 줄에 `flex-wrap`으로 둔다. 작품 수·연재중·완결은 공개 작품(`world_work_reader_visible`)만 센다. `연재중 + 완결 = 작품`이 항상 성립한다(그 외 상태 작품이 있으면 `작품` 수에서만 포함하지 말고 합계가 어긋나지 않도록 공개 작품은 두 상태 중 하나로 분류한다).
- 구독자 수는 `author_subscriptions`에서 `notify = true`인 행만 센다(CONTEXT 연동 확정). 실시간 count이며 낙관적 갱신 대상이다.

### 구독 버튼 상태 (APAGE-02)

버튼은 `Button` 하나이며 `aria-pressed`를 쓰는 토글이다. 버튼 아래 12px 보조 문구 `새 작품·새 회차 알림`을 항상 둔다.

| 상태 | 조건 | 표시 | 동작 |
|------|------|------|------|
| 비로그인 | 세션 없음 | `작가 알림 구독`(accent 채움), `aria-pressed` 없음 | 누르면 토스트·인라인 안내 `로그인하면 작가의 새 작품과 새 회차 알림을 받을 수 있어요`와 `로그인` 링크(`?next=` 현재 `/author/[uuid]` 복귀). 작품 알림 구독의 비로그인 동작과 동일 |
| 구독 전 | 로그인, 본인 아님, 구독 안 함 | `작가 알림 구독`(accent 채움), `aria-pressed="false"` | 누르면 즉시 `구독 중`으로 낙관적 전환, 구독자 수 +1, 서버 액션 호출. 성공 토스트 `작가 알림을 켰어요` |
| 구독 중 | `notify = true` | `구독 중`(outline + `Check` 아이콘), `aria-pressed="true"` | 누르면 즉시 `작가 알림 구독`으로 전환, 구독자 수 -1. 확인 팝업 없음. 토스트 `작가 알림을 껐어요` |
| 구독 껐지만 행 남음 | `notify = false`(내서재에서 끈 경우 포함) | 구독 전과 동일하게 표시 | 다시 누르면 `notify = true`로 복원 |
| 처리 중 | 서버 액션 진행 | 버튼 `disabled` + `aria-busy="true"`, 라벨 유지 | 중복 클릭 무시 |
| 본인 페이지 | 로그인 사용자 id == uuid | 구독 버튼과 보조 문구를 아예 렌더하지 않는다. 구독자 수 칩은 보인다. 그 자리에 `내 작가 페이지예요` 12px 안내와 `스튜디오로 이동` 링크(기존 스튜디오 진입 경로)를 보인다 | DB RPC도 자기 구독을 거부(이중 방어) |
| 정지 계정 | 서버가 write-access 거부 | 버튼은 구독 전/중 원래 상태로 되돌린다(낙관적 전환 롤백). 인라인 오류 `계정이 정지되어 알림 구독을 바꿀 수 없어요. 문의가 필요하면 고객센터를 이용해 주세요` (`role="alert"`) | 토스트 대신 버튼 아래 인라인 오류 유지 |
| 일반 실패 | 네트워크·서버 오류 | 낙관적 전환 롤백 + 인라인 오류 `구독 설정을 바꾸지 못했어요. 잠시 후 다시 시도해 주세요` | 다시 누르면 재시도 |

구독 토글은 행 삭제가 아니라 `notify` 갱신이라는 CONTEXT 결정(연동 절)을 UI가 전제한다. UI 상태 판정은 `notify` 값만 보며 행 존재 여부는 쓰지 않는다. 토글 반환값에 최신 `notify`와 구독자 수를 포함해 클라이언트가 서버 값으로 확정한다.

### 필터·정렬 바 (APAGE-01)
- 좌: 상태 필터 3개 `전체` · `연재중` · `완결` (`role="radiogroup"` 또는 `Tabs`, 기본 `전체`). 우: 정렬 3개 `업데이트순` · `신작순` · `인기순`(기본 `업데이트순`).
- 데스크톱은 둘 다 칩 줄. 모바일(<640px)은 필터 칩 줄은 유지하고 정렬은 `Select`(높이 44px)로 바꿔 한 줄에 둔다. 칩 줄이 넘치면 가로 스크롤하되 페이지 전체 가로 스크롤은 금지(STUDIO-04 기준).
- 정렬 기준: 업데이트=최근 발행 회차 일시 내림차순, 신작=작품 생성 일시 내림차순, 인기=Phase 23 랭킹과 같은 지표 어댑터 한 곳 재사용. 동률은 작품 생성 일시, 그다음 id.
- 필터·정렬은 URL 쿼리(`?status=ongoing|completed&sort=updated|new|popular`)로 유지해 공유·뒤로 가기가 동작한다. 변경은 `router.replace`(스크롤 위치 유지), 그리드 영역에 `aria-live="polite"`로 `N편 표시 중` 안내.
- 선택 변경 후 포커스는 눌렀던 칩에 남는다.

### 작품 그리드
- 열: 데스크톱 `repeat(auto-fill, minmax(200px, 1fr))`(1152px에서 5열), 모바일 2열(`minmax(0,1fr)`), 360px 미만도 2열 유지. 간격 16px.
- 카드(링크 전체가 `/works/[workId]`로 이동): 표지 3:4(표지 없으면 제목 기반 그라디언트 대체), 좌상단 연재 상태 칩(`연재중`/`완결`), 우상단 `연독률 N%` 칩, 제목(14px/600, 2줄 말줄임), 칩 줄(장르 · `N화` · `완독률 N%`), 날짜 줄(12px: `2026.09.20 연재 시작 · 어제 업데이트` / 완결은 `… · 완결`). 수치가 아직 없으면(회차 적음) 해당 칩만 숨기고 `-`는 쓰지 않는다. 표지 `img`의 `alt`는 `{작품명} 표지`.
- 상태 칩과 `연독률` 칩은 표지 위에서 대비 4.5:1 이상이 되도록 반투명 어두운 배경을 쓴다.
- 페이지당 12개를 먼저 불러오고, 12개를 초과하면 그리드 아래에 `작품 더보기` 버튼(전체 폭 아님, 높이 44px, 가운데). 누르면 12개씩 추가(`aria-live`로 `12편을 더 불러왔어요`), 추가된 첫 카드로 포커스. 마지막이면 버튼을 숨기고 카운트 줄 `공개 작품 N편을 모두 보여드렸어요`. 무한 스크롤은 쓰지 않는다. 더보기 실패 시 버튼 위 인라인 `작품을 더 불러오지 못했어요` + 같은 버튼으로 재시도.
- 안내 문구(그리드 아래, 12px): `공개된 작품만 보여드려요. 숨김 처리되거나 아직 회차가 공개되지 않은 작품은 나타나지 않아요.` 목업의 진입 경로 설명 문구는 개발 메모이므로 제품 화면에서 제거한다.

### 빈 상태·로딩
| 상황 | 표시 |
|------|------|
| 필터 결과 0편(작가는 공개 작품이 있으나 필터에 해당 없음) | 그리드 자리에 제목 `{연재중/완결} 작품이 없어요`, 보조 `다른 상태를 선택해 보세요`, 버튼 `전체 보기`(필터 초기화) |
| 로딩 | 프로필 헤더·통계·그리드 카드 6개 스켈레톤. 스켈레톤은 `aria-hidden`, 컨테이너 `aria-busy` |
| 불러오기 실패 | 16번 구성: 제목 `작가 정보를 불러오지 못했어요`, 보조 `잠시 후 다시 시도해 주세요`, 버튼 `다시 시도` |

공개 작품 0편 계정은 필터 빈 상태가 아니라 3번 화면(없는 작가 안내)으로 처리한다(CONTEXT 결정 1).

## 3. 존재하지 않는 작가 안내

조건: uuid 형식 오류, 해당 프로필 없음, `pen_name` 없음, `deleted_at` 있음, 공개 작품 0편. 이유를 구분해 노출하지 않는다(계정 존재 여부 유추 방지, 모두 같은 화면). HTTP 상태는 404(`notFound()` 계열 처리 후 공용 헤더를 유지한 안내 화면).

- 제목(18px/600): `작가 페이지를 찾을 수 없어요`
- 보조(14px): `주소가 바뀌었거나 아직 공개된 작품이 없는 작가일 수 있어요.`

## 접근성

- 페이지 제목 `<title>`은 `{필명} · 작가 페이지 - NovelScript`. `<h1>`은 필명 하나. 그리드는 `<ul>` 목록이며 카드 링크의 접근 이름은 `{작품명}, {연재중/완결}, {N}화`.
- 구독 버튼: `<button type="button" aria-pressed>`, 라벨은 상태에 따라 바뀌지만 `aria-pressed`와 이중으로 상태를 전달한다(라벨만 바꾸는 경우의 혼동 방지로 `aria-label` 추가 설명은 쓰지 않는다). 결과는 `aria-live="polite"` 영역(토스트 포함)으로 알리고 오류는 `role="alert"`.
- 구독자 수 변경은 시각 칩만 갱신하고 별도 라이브 안내는 하지 않는다(버튼 토스트가 대신 알림).
- 키보드: 헤더 → 뒤로 가기 → 구독 버튼 → 필터 → 정렬 → 카드 순 탭 순서. 칩 줄은 방향키 이동을 지원하는 `radiogroup` 패턴. 포커스 링은 accent 2px.
- 색에만 의존하지 않는다: 상태 칩은 텍스트, 구독 중은 체크 아이콘 + 라벨. 터치 영역 44px 이상. 텍스트 대비 4.5:1 이상(라이트·다크 모두).
- 모션: 낙관적 전환에 애니메이션을 쓰지 않으며 `prefers-reduced-motion`에서 스켈레톤 펄스를 끈다.

## Phase 22 내서재 소비 계약 (APAGE-03)

Phase 22는 `알림 구독` 탭의 `작가 알림` 영역을 그리며 이 phase가 제공하는 조회·토글을 소비한다.

- 조회: 내 `author_subscriptions` 행 전부를 `notify`와 관계없이 반환한다. 항목 필드는 `authorId`, `penName`, `notify`, `subscribedAt`만이다(공개 프로필 필드 외 노출 금지).
- 스위치: 항목마다 `notify` 스위치. 끄면 행을 지우지 않고 `notify=false`로 갱신해 **목록에 남는다**. 다시 켜면 `notify=true`. 같은 토글 액션을 작가 페이지 버튼과 공유한다.
- 이름 클릭: `/author/{authorId}`. 작가가 삭제·비공개가 되어 작가 페이지가 없어진 항목은 이름을 링크 없는 텍스트로 두고 `작가 페이지가 없어요` 보조 문구를 붙인다(스위치는 동작 가능).
- 작가 페이지에서 `구독 중` → 해제하면 내서재 목록에 `notify=false`로 남아 있고, 작가 페이지의 구독자 수와 구독 버튼은 `notify` 기준이다. 두 화면은 같은 값을 보므로 서로 어긋나지 않는다(서버 재검증으로 확정).
- 스위치 접근성·카피는 Phase 22 UI-SPEC 소관이며 이 phase는 데이터 계약과 URL만 보장한다.
- 설계 이슈: CONTEXT의 `notify boolean`(또는 `muted_at`) 중 plan 단계에서 하나로 확정한다. UI는 어느 쪽이든 `notify`(true/false)로 추상화된 값만 본다.

## 구현 시 검증 포인트 (ui-auditor용)

1. 360px에서 페이지 가로 스크롤이 없고 구독 버튼이 44px 이상으로 한 손에 닿는다.
2. 본인 페이지에 구독 버튼이 DOM에 없다. RPC 자기 구독 거부도 별도 확인.
3. 정지 계정 오류 후 버튼이 원래 상태로 롤백된다.
4. 내서재에서 끈 작가가 목록에 남고, 작가 페이지 버튼은 `작가 알림 구독`으로 보이며 구독자 수에서 빠진다.
5. 필터·정렬 URL 쿼리 복원과 `작품 더보기` 후 포커스 이동.
6. 공개 조회 응답에 이메일·역할·정지 상태가 없다.
