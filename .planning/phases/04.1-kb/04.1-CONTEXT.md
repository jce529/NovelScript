# Phase 04.1: 사용자 정의 폴더 기능 (KB 커스텀 폴더 + 회차 폴더 트리) - Context

**Gathered:** 2026-08-31
**Status:** Ready for planning

<domain>
## Phase Boundary

This is an urgent insertion (roadmap goal was originally "TBD"). Its scope, established through this discussion:

1. **Folder creation** is added to the KB tree — today the UI can only create documents (`components/studio/kb-node-dialogs.tsx` has no "새 폴더 만들기" action at all), even though `kb_nodes.node_type` already supports `'folder'`. Writers need a general "create folder" action usable throughout the tree.
2. **회차(chapters)** move into the same visual/organizational tree as a fixed "회차" folder per work — today chapters live entirely outside `kb_nodes` (separate `chapters` table, separate `/studio/[workId]/chapters` UI, no folder concept at all beyond a flat `order_index` list).
3. **Account-level KB space** becomes a real "계정 공유 폴더" root that can hold multiple top-level shared folders (not just the single `template` folder it holds today), so writers can keep cross-work reference material (e.g. a shared world-bible) separate from any one work but still reference it from every work.

Out of scope: drag-and-drop folder/file *movement* (still deferred per Phase 2 D-16), any change to chapter reader-facing behavior (publish/price/view-count), and merging chapters into generic KB documents (they stay a distinct, non-mentionable content type — see D-04 below).

</domain>

<decisions>
## Implementation Decisions

### Tree Structure
- **D-01:** Final structure, replacing Phase 2's D-14 (add 회차 as a 7th fixed work folder; add multi-child structure under the account-shared root):
  ```
  작품 폴더 (work root)
    회차/                          (fixed, locked — NEW)
      {episodes, or user-created sub-folders to group episodes}
    template/                      (fixed, locked — work-local templates)
    인물/ 장소/ 사건/ 세력/ 아이템/  (fixed, locked)
    {user-created custom top-level folders — NEW}

  계정 공유 폴더 (account-shared root)                (NEW as an explicit root)
    template/                      (fixed, locked — account-level templates)
    {user-created custom shared folders, e.g. 세계관}  (NEW)
  ```
- **D-02:** Both root containers (작품 폴더, 계정 공유 폴더) are each singular and fixed — a writer cannot create a new root or rename/delete an existing one. Every folder *below* a root (including the root's own direct children) supports creating new folders and new documents, with no depth limit — this applies uniformly at the work root's direct children level too (a writer CAN add a new top-level folder like "설정" directly beside 회차/template/인물/장소/사건/세력/아이템, confirmed explicitly — this is a reversal of the "these are the fixed top-level set" framing one might assume from Phase 2 D-15).
- **D-03:** The 7 structural folders (회차 + Phase 2's existing 6: `template`, `인물`, `장소`, `사건`, `세력`, `아이템`) remain fixed/locked (cannot rename/delete) exactly like Phase 2 D-15. User-created custom folders (at any level, including new top-level ones) are ordinary folders — freely renameable/deletable, no template auto-applied to them (confirmed: custom folders are always empty, no template-picker UI like the 5 KB categories get).

### Chapters / 회차 Folder
- **D-04:** 회차 folder is chapter-content-only — it holds 회차 items and user-created sub-folders (e.g. story arcs) for organizing them, but NOT generic KB documents. Chapters and KB documents stay architecturally distinct; there is no requirement to merge them into one node type. (The "no need to distinguish chapters from KB docs" framing that motivated this phase is about the *tree/folder mechanics* applying uniformly to both — not about mixing document types inside 회차.)
- **D-05:** The `chapters` table and all its existing fields/behavior (title, draft/publish state, `price_tier`, `view_count`, `order_index`-based reordering) are unchanged by this phase. Chapters gain a folder/grouping concept (which sub-folder, if any, a chapter belongs to inside 회차) — concrete schema approach (new column/table vs. reusing `kb_nodes` purely for the folder nodes) is Claude's/planner's call at research & planning time.
- **D-06:** Existing works must be backfilled with the new 회차 folder (and their existing chapters attached to it) — no writer should see missing/orphaned chapters after this phase ships. Same backfill obligation Phase 2 already applied when it introduced the 6 structural folders (`0002_studio.sql`'s `create_work`); this phase needs the equivalent for already-existing works.
- **D-07:** Chapters remain excluded from the `@`-mention system in this phase — no change to EDIT-01's mention search scope regarding chapters. (They were never mentionable before; this phase doesn't add that.)

### Account-Shared Folder & Cross-Scope Mentions
- **D-08:** Custom top-level folders under 계정 공유 폴더 (e.g. "세계관") behave like custom work-level folders — plain folders, no template auto-apply, freely nameable/deletable (only the `template` folder and the 계정 공유 폴더 root itself stay fixed).
- **D-09:** Documents anywhere inside 계정 공유 폴더 (including inside new custom shared folders, not just `template`) must be mentionable (`@`) while writing a chapter in ANY of that account's works — this is a real extension to `lib/ai/mentions.ts`'s `searchMentionNodes`, which today is hard-scoped to `work_id` and to `KB_CATEGORIES` (excludes `template` and would exclude any custom category entirely).
- **D-10:** Mention direction is one-way only: 계정 공유 폴더 → 작품. A specific work's own documents are never mentionable from another work or from the account-shared space. No reciprocal/bidirectional mention requirement.

### Claude's Discretion
- Concrete DB schema change for the `category` column's fixed CHECK constraint (`'template','인물','장소','사건','세력','아이템'`) to accommodate `회차` and arbitrary custom folder names — research/planning call.
- Concrete schema approach for chapter-folder grouping (D-05) — new column on `chapters`, a join table, or folder-only `kb_nodes` rows referenced by `chapters` — research/planning call.
- Whether/how the account-shared root (계정 공유 폴더) is materialized as an actual `kb_nodes` row vs. remaining an implicit UI grouping of `scope = 'account_template'` rows — research/planning call, but D-02's "root is fixed, one per account" behavior must hold either way.
- Visual differentiation between fixed/locked folders and user-created custom folders in the tree UI (icon, badge, etc.).
- Confirmation dialogs / name-collision handling on folder create — reuse the existing `kb_nodes_sibling_name_unique` pattern and `FRIENDLY_NAME_COLLISION` messaging already used for documents.
- Whether mention search result rows need a visual affordance to distinguish "from your shared folder" vs. "from this work" — nice-to-have, not blocking.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `lib/kb/tree.ts` — tree-building logic (`parent_id` → nested structure) already handles arbitrary depth; folder nodes need no new tree-walking logic, just new node rows.
- `lib/kb/actions.ts`'s `createNode` — already accepts `nodeType: 'folder'`; a folder-creation Server Action can reuse this directly (folders never get seed `content`, matching the existing `content = null` branch for non-file/non-template-content cases).
- `kb_nodes_sibling_name_unique` unique index + `FRIENDLY_NAME_COLLISION` error mapping — reuse verbatim for folder name collisions.
- `guard_locked_kb_node()` trigger — reuse verbatim to protect the new 회차 folder (and any other locked folder) from rename/delete.

### Established Patterns
- Locked vs. unlocked folders are already modeled via `kb_nodes.is_locked` + a DB trigger — no new mechanism needed, just seed the new 회차 folder with `is_locked = true` like the other 6.
- Two-tier scope (`work` vs `account_template`) already exists in `kb_nodes.scope` — the account-shared restructuring (D-08/D-09) extends this scope's shape rather than introducing a new one.

### Integration Points
- `create_work()` (0002_studio.sql) — needs a 7th `회차` folder in its seeding loop, plus a companion backfill migration for pre-existing works (D-06).
- `ensure_account_template_root()` — needs to become "ensure account-shared root exists" rather than "ensure template folder exists," to support multiple top-level shared folders (D-08).
- `/studio/[workId]/chapters/*` routes and `lib/chapters/actions.ts` — chapters keep their existing Server Actions/UI; this phase's tree UI needs to render 회차 folder contents by joining/reading from `chapters` (see D-05's schema question) alongside `kb_nodes`.

</code_context>

<specifics>
## Specific Ideas

- User's own words for the target structure:
  ```
  작품 폴더{
   회차 폴더 { 각종 회차 }
   template{ 각종 템플릿 }
   각종 폴더(인물, 사건 등)
  }
  계정 공유 폴더{
   각종 계정 공유 폴더 (템플릿, 여러 작품이 공유하는 세계관 등)
  }
  ```
  and: "가장 상위의 두 폴더(작품폴더, 계정 공유 폴더)를 제외한 모든 폴더에는 폴더, 문서를 새로 만들 수 있어야 돼" — clarified through follow-up (see D-02) to mean the two ROOTS themselves are fixed/singular, not that their direct children are restricted; new top-level folders ARE allowed directly under both roots.
- Motivating problem stated by the user: as a work (or an account, across works) accumulates more KB documents (사건, 세력, etc.) or more shared cross-work lore, having no folder-creation mechanism makes the KB unmanageable — this phase exists to fix that specific pain point, not to add new content types.

</specifics>
