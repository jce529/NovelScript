# Phase 04.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope covered:** KB sidebar tree only (`app/studio/[workId]/layout.tsx`, `components/studio/kb-tree.tsx`, `components/studio/kb-node-dialogs.tsx`) — splitting the single merged tree into two explicit sections (작품 폴더 / 계정 공유 폴더), adding folder creation (top-level and nested), folding 회차 into the tree as a fixed folder with chapter leaves, and extending `MentionAutocomplete`'s result rows for cross-scope (계정 공유 폴더) results. This phase makes **no visual changes** to the KB document editor, the chapter list/editor pages, or the AI panel beyond the mention-row extension noted above — those screens keep their Phase 2/Phase 4 contracts unchanged.

**This document extends `.planning/phases/02-studio-core-writer-loop-no-ai/02-UI-SPEC.md` — it does not replace it.** All spacing/typography/color tokens below are inherited verbatim from Phase 2 unless explicitly marked "NEW" or "CHANGED." Do not re-derive tokens already declared in Phase 2's contract.

## Spacing Scale

Inherited verbatim from Phase 2 (`02-UI-SPEC.md`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside tree rows, badge internal padding |
| sm | 8px | Compact spacing between tree action icons |
| md | 16px | Default spacing, tree indent-per-depth-level |
| lg | 24px | Section padding, gap between major regions |
| xl | 32px | Layout gaps between major Studio regions |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level empty-state padding |

Exceptions (inherited):
- Tree row height: 32px, icon 16px, per-depth indent 16px.
- Icon-only tree action buttons: 24px hit area, MUST carry a tooltip or `aria-label`.
- Chapter list row height: 44px (touch-safe, drag handle).

**NEW exceptions for this phase:**
- **Root section header row: 40px height, 16px horizontal padding** — matches the existing `work.title` header's `p-4` convention (unchanged), now applied identically to the new "계정 공유 폴더" header. Houses the header label (left) and a single 24px "새 폴더 만들기" icon button (right, flush end) for top-level folder creation.
- **Separator between the two tree sections:** shadcn `separator` component, `lg` (24px) vertical margin above and below, placed after the 작품 폴더 tree and before the "계정 공유 폴더" header.
- **회차 folder's chapter-leaf rows reuse the standard 32px tree row height** — no new row height introduced; chapters render as ordinary tree leaves, not as the 44px chapter-list rows used on the dedicated `/chapters` list page (that page's contract is unchanged).

## Typography

Inherited verbatim from Phase 2 (`02-UI-SPEC.md`):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 (regular) | 1.4 |
| Body | 14px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.3 |
| Display | 28px | 600 (semibold) | 1.2 |

**NEW role mapping for this phase:**
- **Root section headers ("작품 폴더" via `work.title`, "계정 공유 폴더" NEW label):** Body size (14px), weight 600 (semibold) — the only new usage of the semibold weight introduced by this phase. Distinguishes the two fixed section headers from ordinary Body-weight-400 tree row text without introducing a 5th font size.
- **Tree leaf rows for chapters (NEW — synthetic leaves under 회차):** Body (14px/400), identical to KB document file rows. Unpublished chapters use `text-muted-foreground` (color change only, not a size/weight change) to signal draft state — matches the existing convention of using `--muted-foreground` for non-primary/inactive indicators (Lock icon, timestamps).
- **Mention autocomplete result rows (`MentionAutocomplete.tsx`), extended for cross-scope results:** unchanged Body/Label split (item name at Body 14px, trailing category/scope text at Label 12px muted) — no new size introduced, only new trailing-text content (see Copywriting Contract).

## Color

Inherited verbatim from Phase 2 (`02-UI-SPEC.md`) — indigo accent (`--primary: var(--color-indigo-600)` light / `var(--color-indigo-500)` dark), destructive unchanged, dominant/secondary backgrounds unchanged. This phase introduces **no new color values.**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (unchanged) | Studio main content background |
| Secondary (30%) | `--secondary` / `--sidebar` (unchanged) | Tree sidebar panel background (now hosting two sections instead of one) |
| Accent (10%) | `--primary` indigo (unchanged) | Reserved EXCLUSIVELY for the same list as Phase 2, PLUS (new, same rule extended): the active/selected chapter leaf's left-border + icon tint (identical treatment to an active KB document file row — no new accent surface introduced, just the existing "active tree item" rule now also applying to chapter leaves) |
| Destructive | `--destructive` (unchanged) | Reserved EXCLUSIVELY for: existing delete-file/folder/chapter actions, PLUS (new) deleting a 회차 sub-folder (see Copywriting Contract for the folder-specific body copy) |

Accent reserved for: unchanged list from Phase 2 + active chapter-leaf indicator (explicitly listed above). Never applied to badges, section headers, or the new folder-creation icon buttons (those render in default `text-foreground`/`text-muted-foreground` like all other non-primary tree icon buttons).

**NEW — folder-type visual differentiation (resolves RESEARCH.md's "Claude's Discretion" item on locked vs. custom folder icon/badge):** Decision — **no new icon or badge for custom folders.** Locked structural folders (회차/template/인물/장소/사건/세력/아이템) keep the existing 12px `Lock` icon + `--muted-foreground` + tooltip (unchanged). Custom folders are differentiated purely by the *absence* of the Lock icon plus the existing hover-revealed rename/delete `IconButton`s (already the case for any `!node.is_locked` node today — no new mechanism needed). This keeps the tree scannable and avoids badge clutter beyond the two scope badges (계정 공용/이 작품 전용) Phase 2 already reserves for root-level template folders.

**NEW — 회차 folder icon:** uses the same `Folder` icon as every other structural folder (not a special icon) — consistency with the existing locked-folder set outweighs novelty. The distinguishing signal that a leaf is a *chapter* (not a KB document) is the leaf-level `BookOpen` icon (16px, reused verbatim from the now-removed `ChaptersNavLink`), not a folder-level icon change.

## Interaction Contract (new, phase-specific — not in the template's default sections, added because this phase's tree-action gating logic is load-bearing for the executor)

**Per-folder-row action buttons, by category (replaces the single "+"-button description in Phase 2's contract for this phase's affected rows only):**

| Folder category | Actions shown (in order, left to right, all 24px hit-area with tooltip) |
|---|---|
| `회차` (root or its custom sub-folders) | "새 회차 만들기" (Plus icon, navigates to `/studio/{workId}/chapters/new?folderId={id}`) → "새 폴더 만들기" (FolderPlus icon, opens `CreateFolderDialog`) → rename/delete (only if `!is_locked`, i.e. only on custom sub-folders, never on the 회차 root itself) |
| `template` (work-local or account-shared) | "새 폴더 만들기" only (unchanged: no "새 문서" on template folders, existing exclusion) → rename/delete (only if `!is_locked` — never true for the template root, may be true for a future nested custom folder under it) |
| `인물` / `장소` / `사건` / `세력` / `아이템` | "하위 문서 추가" (Plus icon, existing dialog) → "새 폴더 만들기" (FolderPlus icon, NEW) → rename/delete (only if `!is_locked`) |
| `custom` (any user-created folder, any depth, any root) | "하위 문서 추가" → "새 폴더 만들기" → rename/delete (always available — custom folders are never locked) |

**Root header actions (NEW — no existing row to attach to, since neither root is a real `kb_nodes` row):**
- 작품 폴더 header (`work.title`): add one "새 폴더 만들기" 24px icon button (FolderPlus), creates a folder with `parent_id: null`, server-derives `category: 'custom'`.
- 계정 공유 폴더 header (NEW): identical pattern — "새 폴더 만들기" 24px icon button, `parent_id: null`, `scope: 'account_template'`, server-derives `category: 'custom'`.

**Category is always server-derived, never trusted from the client** for folder creation (RESEARCH Pitfall 2) — the `CreateFolderDialog`'s Server Action looks up the resolved parent's `category` (or assigns `'custom'` at root) itself; this is a functional contract, called out here because it directly affects what the dialog does/does not need as a form field (no category picker in `CreateFolderDialog` — it never asks the writer to choose one).

**회차 root tree row click target:** the "회차" text itself is a `Link` to `/studio/{workId}/chapters` (list view) — same target as the removed `ChaptersNavLink`, styled identically to how KB file names are already links (folders today render as plain `<span>`, not `<Link>` — 회차 is the one folder-type exception to that rule, given it needs a landing page). Its children (chapter leaves + any custom sub-folders) always render expanded beneath it, matching the tree's existing no-collapse convention — clicking the row text navigates, it does not toggle expand/collapse (there is no collapse state in this tree today, for any folder).

**Chapter leaf rows (synthetic, not real `kb_nodes`):** `BookOpen` icon (16px) + chapter title as a `Link` to `/studio/{workId}/chapters/{chapterId}` (existing editor route, unchanged) + `text-muted-foreground` when `is_published === false`, default `text-foreground` (or `text-primary` when the active route) when published. No badge, no price-tier display in the tree (that information stays on the dedicated `/chapters` list page, unchanged) — keeps tree rows visually consistent with KB file rows (name + icon only).
