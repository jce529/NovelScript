## Phase Scope Definition

The roadmap entry for this phase had only a title (사용자 정의 폴더 기능: KB 커스텀 폴더 + 회차 폴더 트리) and a placeholder goal ("[Urgent work - to be planned]") — no description existed to derive gray areas from, so the first round of questions established the phase boundary itself rather than refining an existing one.

**Codebase findings shared with the user before asking:**
- KB already supports arbitrary nested sub-folders inside the 6 fixed Phase 2 folders (`kb_nodes.node_type = 'folder'`, Phase 2 D-15) — but the UI has no "create folder" action at all, only "새 문서 만들기" (`components/studio/kb-node-dialogs.tsx`).
- Chapters live entirely outside `kb_nodes`, in a separate `chapters` table with only a flat `order_index` — no folder concept.

| Option | Description | Selected |
|--------|-------------|----------|
| 회차에도 폴더(권/아크) 도입 | Add folder-based grouping to chapters; KB keeps existing folder capability | |
| KB에 새 최상위 커스텀 카테고리 도입 | Allow user-named top-level categories beside 인물/장소/사건/세력/아이템 | |
| 둘 다 필요 — 직접 설명할게요 | User provides a free-text description of the intended structure | ✓ |

**User's free-text description (verbatim, translated context preserved):**
> 회차와 기존 KB문서간의 구분이 있을 필요가 없음. 현재 UI 상으로는 문서를 만들 수는 있지만 유저가 원하는 폴더를 만들 수는 없음 — 사건/세력 등 문서 수가 늘어나거나 작품 간 공유 설정이 많아질수록 관리가 힘들어짐. 계정 공유 폴더와 작품 내 폴더는 분리하되 서로 멘션 가능해야 함. 계정 공유 폴더는 template만 있는 게 아니라, 계정 공유 폴더 자체가 있고 그 아래 template 폴더가 있는 구조.
>
> 최종 구조:
> ```
> 작품 폴더{ 회차 폴더{ 각종 회차 } template{ 각종 템플릿 } 각종 폴더(인물, 사건 등) }
> 계정 공유 폴더{ 각종 계정 공유 폴더 (템플릿, 여러 작품이 공유하는 세계관 등) }
> ```
> 가장 상위의 두 폴더(작품폴더, 계정 공유 폴더)를 제외한 모든 폴더에는 폴더, 문서를 새로 만들 수 있어야 돼.

**Notes:** This became the basis for CONTEXT.md's `<domain>` and D-01/D-02.

## Claude's Discretion

- Concrete DB schema change to the `category` CHECK constraint to admit `회차` and arbitrary custom folder names.
- Concrete schema approach for chapter-to-folder grouping (new column vs. join table vs. `kb_nodes`-only folder rows referenced by `chapters`).
- Whether 계정 공유 폴더's root is materialized as an actual `kb_nodes` row or stays an implicit UI grouping of `scope = 'account_template'` rows.
- Visual differentiation between locked/fixed folders and user-created custom folders in the tree UI.
- Folder name-collision handling — reuse the existing document pattern (`kb_nodes_sibling_name_unique` + `FRIENDLY_NAME_COLLISION`).

- Making chapters mentionable via `@` (not requested, explicitly confirmed unchanged).
- Bidirectional mentions (work → other work / account-shared) — explicitly declined.
