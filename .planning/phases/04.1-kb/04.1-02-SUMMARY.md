# Phase 04.1 Plan 02: KB Data Layer Split + createFolder Summary

Split `getKbTree`'s merged work+account flat-node query into explicit `getWorkKbNodes`/`getAccountSharedNodes`, and added `createFolder` — a new mutation supporting root-level and nested folder creation with category always derived server-side from the resolved parent (never trusted from the client).

## What Was Built

**Task 1 — `lib/kb/actions.ts`:**
- Removed the old `getKbTree` (merged `Promise.all` of work-scoped + account-scoped queries into one array).
- Added `getWorkKbNodes({ ownerId, workId })` — returns only `scope='work'` nodes.
- Added `getAccountSharedNodes({ ownerId })` — returns only `scope='account_template'` nodes.
- Added `createFolder({ ownerId, workId, scope, parentId, name })`:
  - `parentId: null` → `category: 'custom'` (new top-level folder directly under a root).
  - `parentId` set → looks up the parent row (scoped to `ownerId` + matching `scope`/`work_id`, `deleted_at IS NULL`), rejects if missing/not-a-folder/mismatched scope, and inherits the parent's `category` verbatim.
  - Rejects empty/whitespace-only names.
  - Inserted row always has `is_locked: false`, `content: null`.
  - Reuses the existing `23505` → friendly collision-message mapping.

**Task 2 — Server Action + tests:**
- `createFolderAction(workId, scope, parentId, name)` added to `app/studio/[workId]/kb/[nodeId]/actions.ts`, following the existing auth-check + `revalidatePath` convention. When `scope='account_template'`, the row's `work_id` is `null` even though the action's own `workId` argument (a real work id) is used only for revalidation.
- `tests/kb/custom-folder-create.test.ts` created — 6 integration tests covering: root-level folder under work root (`category='custom'`), root-level folder under account-shared root (`work_id=null`), nested folder inheriting parent's `category`, empty-name rejection, cross-owner `parentId` rejection (defense-in-depth), and full rename/delete freedom on a custom folder.
- `tests/kb/tree-query.test.ts` updated: import and `describe` block renamed, the old single "merges both scopes" test split into two scope-specific tests (`getWorkKbNodes` / `getAccountSharedNodes`), plus the existing cross-owner-leakage test retargeted at `getWorkKbNodes`.
