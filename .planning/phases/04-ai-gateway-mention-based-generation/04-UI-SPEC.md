# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope covered:** The AI panel added to the existing chapter editor (`app/studio/[workId]/chapters/[chapterId]/page.tsx`) — fixed right-side panel (D-01) containing a model-tier/tone-preset/genre control row (D-05/D-06/D-07/D-08), the 자유형 custom-instruction textarea (D-09), an in-editor `@`-mention autocomplete overlay (D-02) with removable context chips (D-03) and an inline "quick-add" KB-document-creation flow (D-04), a pre-generation token-cost estimate (D-12), a generate action with a spend-cap-aware partial-generation-and-stop behavior (D-13), and a preview-first accept/reject/regenerate flow (D-10/D-11) that never auto-inserts into the canvas. No 3-panel canvas, no ghost-text, no dedicated system-prompt modal, no color-gradient cost gauge — all explicitly out of v1 scope per REQUIREMENTS.md.

**Design system continuity:** This phase extends, not re-themes, the `base-nova` system locked in `.planning/phases/02-studio-core-writer-loop-no-ai/02-UI-SPEC.md` and reused unmodified through `.planning/phases/03-reader-core-reading-loop-no-payment/03-UI-SPEC.md`. All chrome (buttons, selects, dialogs, badges, toasts) reuses Phase 2/3's tokens verbatim. The AI panel is new surface area, but its visual language (spacing scale, typography roles, indigo accent, neutral badges) is inherited, not invented.

**No 04-RESEARCH.md exists yet for this phase.** The design-system stack itself (shadcn `base-nova`, base-ui primitives, `lucide-react`, Geist Sans) is already evident and locked from Phase 2/3's live implementation, so it is reused here without needing a research pass. Gemini-specific technical facts this spec deliberately does NOT fix — exact model-tier→Gemini-model-ID mapping, token-cost estimation formula, rate limits, per-request/per-user spend-cap numeric values — are non-visual concerns and must be confirmed in Phase 4's own technical research/planning pass, per `STATE.md`'s existing blocker note ("Phase 4 ... flagged by research as needing a dedicated research-phase pass ... Gemini rate-limit/pricing/context-window specifics").

## Spacing Scale

Declared values (must be multiples of 4) — identical base scale to Phase 2/3, reused for consistency:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between mention chips, icon-to-label gaps inside select triggers |
| sm | 8px | Gap between the 3 header selects (model tier / preset / genre), gap above the 자유형 textarea, form field internal padding |
| md | 16px | Default spacing between AI panel sections' internal content, preview block padding |
| lg | 24px | AI panel internal padding (all sides), gap between major panel sections (header row → chip list → cost estimate → generate button → preview) |
| xl | 32px | Layout gap between the editor pane and the AI panel |
| 2xl | 48px | Not used inside the panel itself (panel is a single continuous column, no section breaks this large) |
| 3xl | 64px | Not used this phase (no full-page empty-state screen introduced) |

Exceptions (phase-4-specific, mirrors Phase 2/3's precedent of naming component-size exceptions explicitly rather than forcing them onto the 8-pt token scale):

- **AI panel fixed width: 384px** (Tailwind `w-96`), full available editor-pane height, always visible per D-01 — not a toggle, not a breakpoint-collapsed drawer. This is consistent with Phase 2's existing "Studio is a desktop/pointer-first surface" declaration (D-18 there), so no mobile-collapse behavior is specified for this panel.
- **Mention autocomplete overlay: 320px wide, max-height 280px**, scrollable list, positioned as a `popover` anchored just below/near the caret with `xs` (4px) offset. Rows are 32px tall, matching Phase 2's existing tree-row-height precedent for dense, keyboard-navigable lists (not the 44px touch-safe convention, since this is desktop-first per the same D-18 rationale).
- **Mention chip: standard `Badge` sizing** (no new token) — `xs` (4px) gap between chips in a wrapping flex row.
- **자유형 custom-instruction textarea: min-height 96px**, expands inline directly below the 3-select header row per D-09 (no modal, no layout shift elsewhere in the panel).
- **AI preview block: max-height 400px**, scrollable, `md` (16px) internal padding, rendered on the panel's neutral secondary surface (see Color).
- **Cost-estimate row and Generate button: full panel width**, standard button height (shadcn default, 36px) — not an exception to a token, just noting no custom height is introduced.

## Typography

Reused verbatim from Phase 2/3 — no new font sizes or weights introduced:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 (regular) | 1.4 |
| Body | 14px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.3 |
| Display | 28px | 600 (semibold) | 1.2 |

**Exception — AI preview block:** renders generated prose at **Body size (14px/400) but line-height 1.7**, matching Phase 2's existing editor-textarea exception exactly — the preview should visually match how the text will read once accepted into the chapter canvas (which is that same 14px/1.7 textarea). Do not introduce a 5th font size for this; only the line-height changes, same discipline as Phase 2's own precedent.

**Role mapping for this phase's screens:**
- Label (12px): select trigger labels ("AI 모델"/"문체 프리셋"/"장르"), mention chip text, cost-estimate helper text ("예상 토큰"), mention-autocomplete row secondary text (template-type tag), tooltip text.
- Body (14px): mention-autocomplete row primary text (document name), custom-instruction textarea content, quick-add dialog field labels/inputs, all button labels, AI preview block content (at the 1.7 line-height exception above).
- Heading (20px): AI panel title ("AI 어시스턴트"), quick-add dialog title ("새 문서 만들기").
- Display (28px): not used this phase — no full-page empty-state screen is introduced (the panel's own "no mentions yet" state is an inline Label-sized hint, not a dedicated empty-state screen, since the panel is always-visible chrome, not a route with nothing to show).

## Color

Reuses Phase 2/3's token set and indigo accent override unmodified — no new global CSS variables, no re-theme.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (light `oklch(1 0 0)` / dark `oklch(0.145 0 0)`) | Chapter editor pane background (unchanged), AI panel background |
| Secondary (30%) | `--secondary` / `--card` (light `oklch(0.97 0 0)` / dark `oklch(0.269 0 0)`) | AI panel's preview block surface, mention-autocomplete popover surface, quick-add dialog surface |
| Accent (10%) | `--primary` = indigo-600 (light) / indigo-500 (dark), unmodified from Phase 2 | Reserved EXCLUSIVELY for: (1) the "생성하기" (Generate) primary CTA button when enabled; (2) the "본문에 삽입하기" (Insert into canvas) accept button in the preview block; (3) the active/keyboard-highlighted row in the mention-autocomplete list; (4) the quick-add dialog's "만들기" confirm button (same primary-action pattern as Phase 2's existing KB-document-create dialog). Never applied to mention chips (chips stay neutral `Badge`, matching Phase 2's "badges are informational, not primary actions" rule), never applied to the model-tier/preset/genre select triggers themselves (selects are neutral controls, not actions), never applied to the regenerate button. |
| Destructive | `--destructive`, unmodified | **Not used this phase.** No irreversible/data-destroying action exists in this phase's scope — removing a mention chip, rejecting/discarding an AI preview, and regenerating are all instant, reversible, and non-persisted until the writer explicitly accepts into the canvas. This matches Phase 2's own precedent of reserving destructive-red exclusively for actual data deletion with a confirm dialog, not for every negative-sounding action. |

Accent reserved for: Generate button, Insert-into-canvas accept button, active mention-autocomplete row, quick-add confirm button — explicitly listed above, never "all interactive elements."

**Balance-exhausted state (D-13) — deliberately neutral, not destructive or accent:** when a generation is capped by the writer's remaining spend and stops early, both the toast (sonner, default styling — same non-destructive treatment as Phase 3's existing generic-error toast) and an inline banner rendered below the truncated preview use `--muted` background + `--muted-foreground` text + a 16px lucide `AlertCircle` icon. This is a status notification, not an error and not a call-to-action, so it does not consume the accent or destructive budget — consistent with this spec's overall single-hue-accent discipline (same reasoning Phase 3 applied to reject a two-hue banner treatment).

**Mention-type iconography (new this phase, scoped to the mention-autocomplete list and the quick-add template selector only — does not retroactively change Phase 2's KB tree icons, which stay generic `Folder`/`FileText`):** each of the 5 `KB_CATEGORIES` gets a small 16px lucide icon at `--muted-foreground` tint (never accent) so writers can visually scan the autocomplete list by type: 인물 → `User`, 장소 → `MapPin`, 사건 → `Zap`, 세력 → `Shield`, 아이템 → `Package`.

**Primary visual anchor:** Inside the AI panel, the eye lands on the accent-colored "생성하기" button before generation, and on the accent-colored "본문에 삽입하기" button once a preview exists — matching this spec's discipline of exactly one accent-colored primary action visible per panel state, never two competing accent CTAs at once (before generation: only Generate is accent; after generation: Generate is de-emphasized to outline/secondary while Insert becomes the new accent focal point).
