  <behavior>GET 렌더는 approve/deny 부작용이 없다. 승인 시 client와 redirect 호스트·작가 상태·authorization_id를 다시 검증한다. 독자는 연결 없이 안내를 보고 `돌아가기` POST에서만 deny한다. 실패한 승인에는 토큰이나 내부 오류를 노출하지 않는다.</behavior>
  <action>`getAuthorizationDetails` 결과의 client_name/redirect_uri를 신뢰하지 않는 텍스트로 렌더링하고 호스트 allowlist(`claude.ai`, `claude.com`, localhost, 127.0.0.1; 스파이크에서 검증된 값)와 일치시킨다. 화면 판정 순서는 UI-SPEC Interaction 2를 따른다. 승인 액션에서 인증·작가 역할·미탈퇴·허용 호스트·authorization_id를 다시 확인한 뒤 내부 grant에 `read`와 `propose_draft`를 함께 기록하고 `approveAuthorization({skipBrowserRedirect:true})`가 반환한 URL로 이동한다. 거부 액션은 명시적 POST에만 `denyAuthorization`을 호출한다. 승인 실패로 선행 저장된 grant가 남아도 OAuth consent/session 검증으로 사용 불가여야 하고, 가능한 경우 보상 revoke한다. 정상 화면의 제목·범위 두 항목·해제 안내·출처·버튼 카피와 상태별 문구는 12-UI-SPEC Copywriting Contract A를 그대로 사용한다. 클라이언트명은 최대 60자/line-clamp-2, HTML 해석 금지. 카드/모바일 버튼 순서·h1/alert 포커스·중복 제출 방지·보안 헤더 `frame-ancestors 'none'` 및 `X-Frame-Options: DENY`는 UI-SPEC Interaction 1~7과 Layout Notes에 맞춘다. 라우트별 헤더 설정 전 Next 설치 문서를 확인한다(D-04~08, D-18, D-21).</action>
