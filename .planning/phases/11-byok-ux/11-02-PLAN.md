  <name>Task 1: provider별 structured failure allowlist</name>
  <files>lib/ai/providers/types.ts, lib/ai/providers/errors.ts, tests/ai/provider-errors.test.ts</files>
  <read_first>
    lib/ai/providers/types.ts (ProviderErrorKind, ProviderErrorCode, SanitizedProviderError)

  </read_first>
  <behavior>
    - OpenAI 401은 invalid_key, allowlisted spend-limit code를 가진 429는 credit_exhausted, 나머지 429는 rate_limited다.
    - Anthropic 401과 403은 BYOK 문맥에서 invalid_key, 402와 allowlisted enforced spend code는 credit_exhausted, 나머지 429는 rate_limited다.
    - Gemini 401/403은 invalid_key, 402 payment_required는 credit_exhausted, 429 RESOURCE_EXHAUSTED는 rate_limited다.
    - null/network/timeout/5xx는 unavailable이며 unknown 4xx는 config로 안전하게 degrade한다.
    - Anthropic 400 자연어 message는 분류 입력으로 사용하지 않는다.
  </behavior>
  <action>
    `ProviderErrorKind`와 client-safe failure 타입을 `invalid_key | rate_limited | credit_exhausted | unavailable | config`까지 확장한다. `toSanitizedProviderError(provider,err,context?)`가 status뿐 아니라 SDK가 제공한 allowlisted structured code만 읽도록 provider별 작은 판독 함수를 둔다. error 객체 spread, serialization, message substring, response body 접근을 금지한다. service-key config 오류와 BYOK authentication 오류를 구분할 수 있도록 호출 문맥을 명시적 인자로 전달하되 반환 객체에는 provider/status/kind/providerErrorCode만 남긴다. Anthropic 400 spend limit에 안정된 structured code가 없으면 config로 처리하고 fixture/live probe가 확인하기 전 message parsing을 추가하지 않는다. `logProviderFailure`의 필드 allowlist는 유지한다. (D-05)
  </action>
  <verify>
    <automated>npx vitest run tests/ai/provider-errors.test.ts --no-file-parallelism</automated>
  </verify>
  <acceptance_criteria>

    - 세 provider별 표의 status/code fixture가 네 UX kind로 분류되고 unknown/null fallback 테스트가 통과한다.
    - malicious error의 `message`, `headers`, `request`, `apiKey`, `prompt` 문자열이 result와 captured log에 나타나지 않는다.
    - `rg -n "message\.includes|includes\(.*spend|JSON\.stringify\(err|\.\.\.err" lib/ai/providers`가 분류 구현에서 매치하지 않는다.
  </acceptance_criteria>
