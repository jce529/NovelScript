## Color

60% dominant(`--background`), 30% secondary(패널·결과 행·칩 흰 배경과 border, 탭 비활성), 10% accent(indigo).

accent 전용 요소(이 목록 밖에 쓰지 않는다):
1. 키보드 포커스 링
2. 검색어 일치 부분 강조(`<mark>`): `--primary` 10% 배경 + `--foreground` 글자 + 600 굵기. 목업의 노란 `#fef08a`는 새 색 토큰이 되므로 **쓰지 않는다**
3. 작가 결과 행의 `작가 페이지 ›` 글자(`text-primary`)

활성 탭은 accent가 아니라 `--foreground` 배경 반전(21번 보드·목업 `gc.on`과 동일)으로 구분한다. 추천 검색어의 `운영`·`인기` 표시는 색이 아니라 텍스트이며 `--muted-foreground` 11px다(색만으로 구분하지 않음). destructive 색은 쓰지 않는다: 최근 검색어 삭제, 추천어 삭제, 태그 제거는 모두 되돌릴 필요가 낮은 소규모 행동이라 확인 팝업이 없고 빨간색도 쓰지 않는다. 오류 문구는 `--foreground` + 보더. 다크 모드는 토큰 자동 반전. 새 색 토큰은 추가하지 않는다.

## 1. 헤더 검색 진입 (SEARCH-01)

### 데스크톱 (≥768px)
- 헤더 윗줄: `로고` · **검색 입력창** · 토큰 잔액+충전 · 프로필(비로그인은 `로그인`). 기존 비활성 `검색 (준비 중)` 아이콘 버튼은 제거한다.
- 입력창: `<form role="search" action="/search" method="get">` 안의 `<input type="search" name="q">`. 좌측 `Search` 아이콘(장식), 우측 입력 있을 때만 `X` 지우기 버튼(`aria-label="검색어 지우기"`, 44px). `placeholder="작품, 태그, 작가 검색"`. `autocomplete="off"`, `enterkeyhint="search"`, `aria-label="검색어"`.
- `/search` 결과 페이지에서는 입력창에 현재 `q`가 채워져 있다.
- 헤더 구조(2단 + 서브 행)와 sticky는 유지한다. `/search`에서는 메인 탭 어느 것도 활성화하지 않는다(28 작가 페이지와 동일).

### 모바일 (<768px)
- 윗줄에는 입력창 대신 **검색 아이콘 링크**(`Search`, 44×44, `aria-label="검색"`)를 둔다. 누르면 `/search`로 이동하고 페이지의 검색 입력창에 자동 포커스한다(패널이 열린 상태).
- `/search` 페이지는 모바일에서 헤더 아래에 **페이지 자체 검색 입력창 행**(전체 폭, 높이 44px)을 그린다. 데스크톱에서는 이 행을 그리지 않는다(헤더 입력창이 담당, 입력창 중복 금지).
- 모바일 윗줄 요소가 많아 넘치면 기존 규칙(가로 스크롤)을 따른다.

### 실행 규칙
- 실행 트리거: 폼 제출(`Enter`, 모바일 키보드 `검색` 키), 최근/추천 검색어 항목 클릭. 입력만으로는 실행·이동하지 않는다(자동완성 없음, 입력 중 목록 변화 없음).
- 검색어 정규화(**제안, plan 확정**): 앞뒤 공백 제거 → 연속 공백 1칸으로 → 앞의 `#` 한 개 제거(태그 습관 입력 허용) → 최대 50자로 자름. 대소문자 구분 없음(ILIKE). 전각 공백도 공백으로 본다.
- 최소 길이(**제안, plan 확정**): 정규화 후 **2글자 이상**. 1글자 이하는 검색을 실행하지 않고 결과 영역에 안내(5절)를 보이며 `search_queries` 로그도 남기지 않는다. 근거: `pg_trgm` GIN 인덱스는 3글자 이상에서 효과가 크고 1글자 한국어 검색은 결과가 과도하다. 2글자는 전체 스캔이 될 수 있어 plan에서 성능을 확인한다.
- 빈 검색어 제출: 이동하지 않고 입력창에 포커스 유지, 패널을 열어 둔다(오류 문구 없음).
- URL: `/search?q={검색어}&tab=all|works|tags|authors` (`tab` 기본 `all`이면 생략, **후보**). 뒤로 가기·새로고침·공유가 동작한다. 알 수 없는 `tab` 값은 `all`로 처리한다. 검색 실행 시 `page`는 없다.
- 검색 로그 기록 시점(**제안, plan 확정**): 폼 제출·최근/추천 항목 클릭 때 1회(서버 액션 또는 route handler). 페이지 렌더·새로고침·탭 전환·더보기에서는 기록하지 않는다(인기 집계 부풀림 방지). 기록 실패는 화면에 영향을 주지 않는다(무시).

## 2. 검색창 포커스 패널 (SEARCH-02)

열리는 조건: 입력창 포커스·클릭, `/search`에 `q`가 없을 때 페이지 진입(모바일 자동 포커스). 닫히는 조건: `Esc`, 입력창·패널 밖 클릭, 포커스가 패널 밖으로 이동, 검색 실행. 입력 중에도 내용은 바뀌지 않는다(자동완성 없음).

패널 안내 한 줄(12px, 맨 아래): `입력하는 동안 자동완성은 제공하지 않아요.` — 목업의 운영 설명(`앞의 세 개는 운영에서 고른…`)은 개발 메모이므로 제품 화면에서 **제거**한다.

### 최근 검색어
- 제목 `최근 검색어`(14px/600) 우측 `전체 삭제` 텍스트 버튼(44px 히트 영역).
- 항목: 칩 하나 = [검색어 버튼] + [`×` 삭제 버튼]. 검색어 버튼은 클릭 시 해당 검색어로 즉시 검색(`q` 설정, 탭 `all`). `×` 버튼은 44×44, `aria-label="{검색어} 삭제"`, 해당 항목만 삭제.
- 저장: 브라우저 `localStorage`(키 후보 `ns.recent-searches`), 최대 **10개**, 최신순, 같은 검색어(정규화 후 동일)는 앞으로 끌어올려 중복 없음. 검색 실행(최소 길이 통과) 시 추가. 로그인과 무관하게 같은 브라우저에 남고 계정 동기화는 범위 밖.
- 저장소 접근 실패(사생활 보호 모드 등): 오류 표시 없이 비어 있는 것으로 동작한다.
- 하이드레이션: 서버 렌더에는 최근 검색어를 그리지 않고 마운트 후 채운다(깜빡임 방지로 영역 높이는 유지하지 않음, 비어 있으면 안내 문구).
- 비어 있을 때: 제목은 유지하고 `전체 삭제` 버튼은 숨기며 12px 문구 `최근 검색어가 없어요.`
- 삭제 후 포커스: 개별 삭제 → 남은 다음 항목의 검색어 버튼(없으면 이전 항목, 모두 없으면 입력창). `전체 삭제` → 입력창. `aria-live="polite"` 영역에 `{검색어}를 삭제했어요` / `최근 검색어를 모두 삭제했어요`를 알린다.
- 삭제에는 확인 팝업이 없다(로컬 목록, 즉시).

### 추천 검색어
- 제목 `추천 검색어`(14px/600). 칩 최대 **5개**(상수 `SUGGEST_SLOTS = 5`, 한 곳).
- 칩 구성: 순번(`1`~`5`) + 검색어 + 11px 표시 `운영` 또는 `인기`. 클릭 시 해당 검색어로 즉시 검색. 칩은 `button`, 접근 이름은 `{순번}번 {검색어}, {운영|인기}`.
- **운영:인기 비율 규칙**(D-04, 기본 3:2):
  - 운영 슬롯 수 `k` = 관리자 설정값(0~5, 기본 3), 인기 슬롯 수 = `5 - k`. 목업 3:2는 `k = 3`.
  - 표시 순서: 운영 선정어 `k`개(관리자가 정한 순서), 이어서 인기어 `5 - k`개(7일 집계 순위순). 순번은 이어서 1~5.
  - 운영 선정어가 `k`개보다 적으면 부족분을 **인기어로 채운다**. 인기어가 `5 - k`개보다 적으면 부족분을 **운영 선정어 중 남은 것으로 채운다**. 양쪽이 모두 모자라면 있는 만큼만 보인다.
  - 같은 검색어가 운영·인기 양쪽에 있으면 `운영`으로 표시하고 인기 쪽은 건너뛴다(중복 없음, 비교는 정규화 후).
  - 인기어는 `search_queries`의 **최근 7일** 집계 상위(D-03). 너무 적게 검색된 검색어가 노출되지 않도록 최소 검색 횟수 문턱을 둔다(**제안: 3회 이상, plan 확정**).
- 추천어가 하나도 없으면(운영 0개, 집계 없음) 제목과 12px 문구 `지금은 추천할 검색어가 없어요.`
- 추천 검색어 조회가 실패하면 영역만 `추천 검색어를 불러오지 못했어요.` 12px로 대체하고 최근 검색어·입력은 정상 동작한다(패널 전체를 막지 않음).

### 패널 키보드
- 포커스는 입력창에 있다. `Tab`으로 패널 항목 순서(최근: 전체 삭제 → 각 항목의 검색어/×, 추천: 칩 순서)로 이동한다. 방향키 이동은 구현하지 않는다(자동완성 목록이 아니므로 `combobox`/`listbox` 역할을 쓰지 않는다).
- `Esc`: 패널 닫고 입력창 포커스 유지. 패널은 `role="region"` + `aria-label="검색어 도우미"`, 입력창에 `aria-expanded`는 쓰지 않는다.

## 3. 결과 페이지 (SEARCH-01·03)

위→아래: 공용 독자 헤더 → (모바일만) 페이지 입력창 행 → 제목 블록 → 탭 → 결과 → 안내.

### 제목 블록
- `h1`(18px/600): `“{검색어}” 검색 결과`. 바로 아래 12px 건수 줄: `작품 {n}개 · 태그 {n}개 · 작가 {n}명`(`aria-live="polite"`). 길이 미달·빈 검색어면 5절 사용.
- 검색어 일치 부분은 결과 텍스트 안에서 `<mark>`로 강조한다(제목·필명·태그명). 강조는 시각 보조이며 의미는 텍스트로 이미 전달된다.

### 탭 (`전체` · `작품` · `태그` · `작가`)
- 라벨에 건수 포함: `전체 {합}`, `작품 {n}`, `태그 {n}`, `작가 {n}`. 기본 `전체`.
- URL 기반 이동이므로 `Tabs`(role=tab)가 아니라 **`<nav aria-label="검색 결과 구분">` 안의 링크**로 만들고 현재 탭에 `aria-current="page"`. 모양은 목업의 칩 줄(`gc`), 활성은 `--foreground` 반전, 높이 44px, 가로 스크롤 가능(scrollbar 숨김).
- 탭 전환은 `router.push`(검색어 유지, 스크롤 맨 위로 이동하지 않음, 포커스는 눌린 탭에 유지).
- 건수 상한: 각 건수는 정확한 값을 쓰되 계산 비용이 크면 `99+`로 표기한다(**제안, plan 확정**).

### 전체 탭
- 섹션 순서: 작품(제목 `작품` 14px/600) → 태그 → 작가. 결과가 0건인 섹션은 제목째 숨긴다.
- 전체 탭 미리보기 개수(**제안**): 작품 5개, 태그 10개, 작가 5개. 더 있으면 섹션 아래 링크 버튼 `작품 결과 더 보기`/`태그 결과 더 보기`/`작가 결과 더 보기`(44px)로 해당 탭에 이동한다.

### 작품 결과 행 (`SearchWorkRow`) — 작품 탭·전체 탭
- 행 전체가 `<a href="/works/{workId}">`(SEARCH-03). 한 행이 탭 정지 하나.
- 구성: 좌 표지 60px 폭 3:4(없으면 회색 배경 + `표지 없음` 11px, `alt`는 `{작품명} 표지`), 중앙 [제목 14px/600 말줄임 2줄] [12px 보조 줄 `{작가} · {장르} · {n}화 · {연재중|완결}`] [태그 Badge 최대 3개, `#{태그}` 11px], 우 `연독률 {N}%` Badge(수치가 없으면 Badge만 숨김, `-` 쓰지 않음).
- 작가 이름: `profiles.pen_name`, 없으면 `작가`. `{n}화` = 공개·미삭제 회차 수(21과 동일).
- 모바일: 표지 56px, `연독률` Badge는 보조 줄 아래로 내려 줄바꿈, 태그는 1줄 말줄임.
- 노출 조건: **발행·공개 작품만**(`world_work_reader_visible` 계열 공개 규칙). 숨김·삭제·회차 0편 작품 제외.
- 매칭(**제안, plan 확정**): 제목에 검색어 포함 OR 작품 태그에 검색어 포함. 작가 필명 일치는 작가 탭이 맡는다(작품 탭에 섞지 않음). 정렬(고정, 사용자 정렬 옵션 없음): 제목 일치 → 태그만 일치 순, 같은 그룹 안에서는 현행 인기 점수 내림차순, 동률은 작품 생성일 최신순, 그다음 id.

### 태그 결과 (`SearchTagChip`) — 태그 탭·전체 탭
- 칩 줄(`flex-wrap`): `#{태그명} {n}편`(14px + 12px 보조 숫자). n = 그 태그가 붙은 **발행·공개 작품 수**. 0편인 태그는 노출하지 않는다.
- 매칭: 태그명에 검색어 포함. 정렬: n 내림차순 → 이름 오름차순. 태그 탭 최대 30개(더보기 없음, **제안**).
- **칩을 누르면(제안, plan 확정)**: 그 태그를 가진 작품 목록으로 필터한다 — `/search?tag={태그명}`. 이 화면은 같은 결과 페이지 구조에서 `h1`을 `#{태그명} 태그 작품`으로, 건수 줄을 `작품 {n}개`로 바꾸고 **작품 행 목록만** 보인다(탭 줄 숨김, 검색어 입력창은 비워 두고 안내 없음). 태그 일치는 정확 일치(정규화 후). 목업의 `Ranking.dc.html` 연결은 랭킹 태그 필터 화면이 없는 현 시점에 맞지 않으므로 쓰지 않는다. 뒤로 가기는 원래 검색 결과로 돌아간다.
- 칩은 `<a>`, 접근 이름 `#{태그명}, 작품 {n}편`.

### 작가 결과 행 (`SearchAuthorRow`) — 작가 탭·전체 탭
- 행 전체가 `<a href="/author/{profiles.id}">`(SEARCH-03). **Phase 28이 확정한 경로**이며 임시 가정이 아니다. 단 Phase 28 구현 전에는 이 링크가 404일 수 있다(구현 순서 28 → 27 또는 같은 웨이브, plan 명시).
- 구성: 아바타 원 56px(프로필 이미지 필드 없음 → 필명 첫 글자를 14px/600로 중앙에 둔 그라디언트 원, `aria-hidden`; 28 작가 페이지와 동일 규칙), 중앙 [필명 14px/600] [12px `작품 {n}편 · 대표작 {작품명}`], 우 `작가 페이지 ›` 12px `text-primary`.
- 매칭: `pen_name`에 검색어 포함. **공개 작품이 1편 이상인 작가만** 노출(28 없는 작가 안내 조건과 일치시켜 404 방지). 정렬: 필명 앞부분 일치 → 포함, 같은 그룹은 공개 작품 수 내림차순, 그다음 `pen_name` 오름차순. 작가 탭 최대 20명(**제안**).
- 대표작 = 그 작가의 공개 작품 중 현행 인기 점수 최고. 작품 수 `{n}`은 공개 작품 수. 접근 이름 `{필명} 작가 페이지, 작품 {n}편`.
- 작가 필명은 공개 필드이므로 이메일 등 다른 프로필 필드를 결과에 내려보내지 않는다.

### 더보기
- 작품 탭만 페이지가 길어질 수 있다: 한 번에 20개, 누적 `page`(`?page=2`는 40개 서버 렌더, 21의 누적 페이지 규칙과 동일), `더보기` 버튼(전체 폭 아님, 44px, 가운데), 클릭 중 `불러오는 중…` + `disabled`. 새 항목 추가 후 포커스를 새로 추가된 첫 행으로 이동하고 `작품 {n}개 더 불러왔어요`를 `aria-live`로 알린다. 태그·작가 탭은 상한이 있어 더보기가 없다.

## 7. 스튜디오 작품 설정 `태그` 입력 (D-01 최소 UI)

- 위치: 스튜디오 작품 설정 화면의 작품 기본 정보 아래 별도 섹션. 21의 `SerialStatusField`와 마찬가지로 **섹션 컴포넌트 `WorkTagsField` 하나로 독립**시켜 Phase 19 작품 홈 등 어느 화면에도 끼울 수 있게 한다(위치 확정은 plan).
- 구성: 섹션 제목 `태그`(14px/600) + 12px 설명, 입력창 1개(`Input`, `Label` 연결) + `추가` 버튼(44px), 입력된 태그는 칩 줄(`Badge`형 칩 + 우측 `×` 제거 버튼 44px, `aria-label="{태그} 제거"`), 하단 `태그 저장` 버튼.
- 태그 규칙(**제안, plan 확정**): 작품당 최대 **10개**, 태그당 **1~20자**(정규화 후), 앞의 `#` 제거, 앞뒤 공백 제거, 내부 공백 허용 안 함(공백이 있으면 입력 시점에 `-` 없이 거부하고 오류 문구). 이모지·`#`·쉼표·따옴표 등 기호 불가(한글·영문·숫자·`_`만). 영문은 소문자로 저장. 같은 태그 중복 입력은 무시하고 `이미 추가한 태그예요.` 안내.
- 입력: `Enter` 또는 `,`로 추가(입력창은 폼 제출을 막음), `추가` 버튼도 동일. 입력창이 비어 있을 때 `Backspace`는 마지막 칩을 제거하지 않는다(실수 방지).
- 저장: 명시적 `태그 저장` 버튼(여러 개를 한 번에 편집하므로 21의 즉시 저장과 다르다). 변경 없으면 `disabled`. 저장 중 `disabled` + `저장 중…`. 성공 시 토스트 `태그를 저장했어요.`, 실패 시 칩 상태 유지 + 토스트 `태그를 저장하지 못했어요. 다시 시도해 주세요.`
- 노출 안내(12px): `발행한 작품의 태그만 독자 검색에 노출돼요.` 미발행(초안) 작품도 태그는 편집·저장할 수 있다.
- 작가 본인 작품만 편집(RLS/서버 검증). 다른 작품 장르는 건드리지 않는다: 장르(`lib/works/genres.ts`의 8종)는 태그와 별도 필드이며 이 phase에서 장르 UI는 바꾸지 않는다.
- 접근성: `fieldset` + `legend`(`태그`), 칩 목록은 `ul`, 추가·제거 결과는 `aria-live="polite"`(`#{태그} 추가했어요` / `#{태그} 제거했어요`), 오류는 입력창 `aria-describedby` 연결 + `role="alert"`.

## 8. 관리자 `검색어 운영` 편집 (D-04 최소 UI)

- 위치: 관리자 메뉴의 신규 항목 `검색어 운영`(경로 후보 `app/admin/search/page.tsx`). 관리자만 접근(기존 관리자 레이아웃·권한 가드 재사용).
- 구성 2개 섹션, 같은 페이지:
  1. **비율 설정** — 제목 `추천 검색어 비율`, 12px 설명, `Select`(`aria-label="운영 선정어 개수"`) 하나. 옵션은 총 슬롯 5개를 나누는 6가지: `운영 0 : 인기 5`, `운영 1 : 인기 4`, `운영 2 : 인기 3`, `운영 3 : 인기 2`(기본), `운영 4 : 인기 1`, `운영 5 : 인기 0`. 값이 합 5를 어길 수 없다. 선택 즉시 저장하지 않고 `비율 저장` 버튼으로 저장한다.
  2. **운영 선정어** — 입력창 + `추가` 버튼, 목록(순서가 곧 노출 순서). 각 행: 순번, 검색어, `위로`/`아래로` 이동 버튼(각 44px, `aria-label="{검색어} 위로 이동"` 등), `삭제` 버튼. 드래그 정렬은 만들지 않는다(키보드 접근성·최소 UI).
- 선정어 규칙(**제안, plan 확정**): 2~20자(독자 검색 최소 길이와 같음), 7절과 달리 공백 허용(`무협 완결`), 정규화는 독자 검색어와 동일(공백 정리·`#` 제거), 같은 정규화 결과 중복 불가, 최대 20개(노출은 앞의 `k`개만). 저장 시 그 자리에서 목록에 반영하고 서버 저장은 항목별 즉시(추가·삭제·이동 각각 토스트).
- 미리보기: 하단에 12px로 `독자에게는 이렇게 보여요` + 현재 설정으로 구성한 추천 칩 줄(인기어는 실제 집계 결과 포함)을 읽기 전용으로 보여 준다(편집 결과 확인용, 클릭 동작 없음).
- 비어 있는 상태: 선정어 목록 `아직 운영 선정어가 없어요. 추가하면 추천 검색어 앞쪽에 노출돼요.`
- 접근성: 목록 `ul`, 이동·삭제 결과 `aria-live="polite"`, 맨 위/맨 아래 항목의 이동 버튼은 `disabled`(+ 이유는 `aria-label`로 충분), 삭제 후 포커스는 다음 행(없으면 입력창).

## 9. 접근성 요약

- 모든 인터랙티브 요소(헤더 입력창, 지우기, 패널 칩·삭제 버튼, 탭, 결과 행, 더보기, 스튜디오·관리자 버튼) 최소 **44×44px**. 칩 안의 `×` 버튼도 44×44.
- 포커스: `focus-visible` 2px indigo(`--ring`), `outline-offset: 2px`. 결과 행·칩 전체에 링이 보이도록 `overflow:hidden`에 잘리지 않게 한다.
- 구조: 입력창 폼 `role="search"`, 결과 페이지 `h1` 하나, 작품·작가 행은 `ul/li`, 탭은 `nav aria-label="검색 결과 구분"` + `aria-current`.
- 결과 건수·삭제 알림·더보기 알림은 `aria-live="polite"`, 오류는 `role="alert"`, 로딩은 `aria-busy`.
- 색만으로 구분하지 않는다(`운영`/`인기`/연재 상태/탭 활성은 텍스트 병기, 활성 탭은 반전 + `aria-current`).
- 텍스트 대비 4.5:1 이상(라이트·다크). `<mark>` 강조도 4.5:1 이상 유지.
- 모션: 패널 열림/닫힘에 애니메이션 없음, `prefers-reduced-motion`에서 스켈레톤 pulse 끔.
- 터치 키보드: `enterkeyhint="search"`, `type="search"`, `autocapitalize="off"`, `spellcheck="false"`.

## 구현 시 검증 포인트 (ui-auditor용)

1. 입력만 해서는 아무 요청·이동·목록 변화가 없다(자동완성 없음).
2. 최근 검색어 개별 삭제·전체 삭제 후 새로고침해도 유지되고(localStorage), 중복 없이 최대 10개.
3. 추천 검색어가 `운영`·`인기` 텍스트와 함께 3:2로 나오고, 운영어가 모자라면 인기로 채워진다.
4. 비공개·초안·삭제 작품이 작품·태그·작가 어디에도 나오지 않는다. 공개 작품 0편 작가가 작가 탭에 없다.
5. 작가 결과가 `/author/{profiles.id}`로, 작품 결과가 `/works/{workId}`로 이동한다.
6. 결과 없음에서 자동 이동이 없고 `랭킹 보러 가기`·`검색어 지우기`가 동작한다.
7. 360px에서 가로 스크롤이 페이지에 생기지 않고(탭 줄만 내부 스크롤) 모든 대상이 44px 이상.
8. 스튜디오에서 저장한 태그가 발행 작품에서만 태그 탭에 나온다.
9. 관리자만 `검색어 운영`에 접근 가능하고, 비율 변경이 독자 패널에 반영된다.
10. `search_queries`에 `user_id`가 저장되지 않고, 탭 전환·새로고침으로 로그가 늘지 않는다.
