# Phase 14 — UI Design Contract

> MCP 쓰기 도구로 도착한 '제안'을 작가가 검토하는 스튜디오 화면의 시각·상호작용 계약. `14-CONTEXT.md` D-P14-01~09를 고정 결정으로 따르고, `12-UI-SPEC.md`(토큰·타이포·색·카드·배지·다이얼로그·카피 톤)를 그대로 상속한다. 새로 추가되는 부분만 정의한다. 자동 수락, 호출 로그, 새 회차 생성, 여러 대기 초안 비교는 범위 밖이다.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (`components.json` 존재, style `base-nova`, baseColor `neutral`) |
| Preset | `base-nova` — 변경 없음 |
| Component library | Base UI (`@base-ui/react`). 기존 로컬 `Button`, `Badge`, `Dialog`, `Tabs`, `Select`, `Sheet`, `Separator`, `Label`, `Input`, `Textarea`, `ScrollArea` 재사용. 신규 설치 없음 |
| Icon library | lucide-react (`Inbox`, `GitCompare`, `Check`, `X`, `Undo2`, `AlertTriangle`, `AlertCircle`, `Clock`, `FolderOpen`, `Lock`). 항상 `aria-hidden`, 텍스트 보조용 |
| Font | Geist Sans (`font-sans`) |

**신규 컴포넌트(로컬 조립, 레지스트리 설치 없음):**
- `ChunkRow` — 변경 덩어리 1개 행(체크 + 상태 라벨 + 비교 본문). 선택 컨트롤은 네이티브 `<input type="checkbox">`에 `accent-primary`·`size-5`(터치 영역은 `<label>` 전체 44px)를 쓴다. shadcn `Checkbox`는 설치되어 있지 않으며 새로 설치하지 않는다.
- `ProposalCard` — 큐 목록 카드.
- `PendingProposalBadge` — `대기 n건` 배지(홈·회차·문서 공용).

**대상 화면 (신규 4곳 + 기존 3곳 수정):**

| # | 라우트 / 위치 | 종류 |
|---|---------------|------|
| 1 | `/studio/[workId]/review` — 작품별 리뷰 큐 | 신규 |
| 2 | `/studio/[workId]/review/[proposalId]` — 제안 검토 상세. 제안 종류에 따라 본문 영역만 달라진다: (a) 회차 초안, (b) 설정집 수정안, (c) 설정집 신규 생성안 | 신규 |
| 3 | 수락 후 되돌리기 상태(상세 화면 안의 상태, 별도 라우트 없음) | 신규(상태) |
| 4 | 스튜디오 홈 `app/studio/page.tsx` 작품 카드 `대기 n건` 배지 | 수정 |
| 5 | 작품 사이드바(`app/studio/[workId]/layout.tsx`)에 `리뷰 큐` 항목(+대기 건수), 회차 화면·설정 문서 화면 상단 `대기 제안 n건` 줄 | 수정 |

상세는 모달이 아니라 **페이지**다(덩어리 비교는 넓은 영역과 스크롤이 필요하고, 새로고침·뒤로가기·링크 공유가 되어야 한다). 확인이 필요한 파괴적 동작만 Dialog를 쓴다. 토스트 의존 피드백은 만들지 않고 인라인 `role="status"`/`role="alert"`를 쓴다.

## Spacing Scale

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 배지와 글자, 아이콘-텍스트 간격 |
| sm | 8px | 버튼 간격, 카드 안 메타 행 간격, 덩어리 헤더 요소 간격 |
| md | 16px | 카드 내부 요소 간격, 덩어리 본문 안쪽 여백(`p-4`), 모바일 페이지 여백 |
| lg | 24px | 카드 안쪽 여백(`p-6`), 큐 카드 사이 간격, 섹션 간격 |
| xl | 32px | 데스크톱 페이지 바깥 여백(`md:p-8`) |
| 2xl | 48px | 빈 상태 위아래 여백 |
| 3xl | 64px | 사용하지 않음 |

Exceptions: 터치 타깃은 모바일에서 `min-h-11`(44px) — 덩어리 체크 `<label>`, `수락`/`거절` 버튼, 필터 탭, 하단 고정 일괄 반영 바의 버튼(`Button size="default"`, `sm` 금지). 상세 화면 하단 고정 바는 `pb-[env(safe-area-inset-bottom)]`를 더한다. 그 외 4의 배수만 사용. [출처: 12-UI-SPEC]

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption (출처 호스트·시각·건수 보조·상태 안내) | 12px (`text-xs`) | 400 | 1.5 |
| Body / Label / button / 비교 본문 | 14px (`text-sm`) | 400 (본문) / 600 (라벨·버튼·클라이언트명·덩어리 번호) | 1.5 (비교 본문은 한국어 가독성을 위해 `leading-7` = 28px 허용, 문단 사이 `gap-2`) |
| Section heading (카드 제목·제안 대상명) | 18px (`text-lg`) | 600 | 1.2 |
| Page heading | 24px (`text-2xl`) | 600 | 1.2 |

크기 4종(12/14/18/24), 굵기 2종(400/600). `font-medium`(500) 금지. 시각·건수는 `tabular-nums`. 본문·제목 `break-keep`, 클라이언트명·호스트는 `break-all min-w-0`. **비교 본문은 `whitespace-pre-wrap break-words`**(문단 구분 보존, 원고에 `break-keep`을 강제하지 않는다). 사용자·AI 텍스트는 React 텍스트로만 렌더링하며 HTML로 해석하지 않는다.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` | 페이지 바탕, 비교 본문 영역 |
| Secondary (30%) | `bg-card`/`bg-muted`, `border-border` | 제안 카드, 덩어리 카드, 원문 쪽 패널(`bg-muted`), 고정 바 |
| Accent (10%) | `bg-primary`(indigo-600)/`ring` | 아래 reserved 목록만 |
| Destructive | `text-destructive`, `border-destructive/40`, `variant="destructive"` | 아래 목록만 |

Accent reserved for: (1) 상세 화면 확정 버튼 `선택한 n개 반영하기` / `설정집에 저장하기`(화면당 1개)와 그 확인 Dialog의 `반영하기` 버튼, (2) 덩어리 체크박스의 선택됨 상태(`accent-primary`), (3) 키보드 포커스 링. 그 외(클라이언트명, 링크, 상태·건수 배지, 추가/삭제 하이라이트, 변경 표시 보더, 빈 상태)에는 accent 금지.
시각 중심(focal point): 큐는 `검토 대기` 카드, 상세는 첫 미선택 덩어리와 하단 고정 바의 확정 버튼.
상태 배지에 `되돌림`(되돌리기 성공 직후 표시)을 추가한다. Dialog 닫기 버튼 라벨은 `취소` 대신 거절 Dialog `제안 유지하기`, 되돌리기 Dialog `닫기`, 되돌리기 확정 버튼은 `반영 되돌리기`로 쓴다.

Destructive reserved for: Dialog 안 `거절하기` 확정 버튼, Dialog 안 `되돌리기` 확정 버튼, 실패 알림 카드(`role="alert"`)의 제목·아이콘·테두리, `적용할 수 없는 덩어리` 라벨 텍스트.

**변경 표시(새 색 토큰 없이):**
- 원문 패널: `bg-muted`, 제거될 문단은 `line-through decoration-muted-foreground`.
- 초안(수정안) 패널: `bg-background`, 추가·바뀐 문단은 좌측 `border-l-4 border-foreground/40` + 라벨 `바뀜`/`추가`/`삭제`. **색만으로 구분하지 않는다** — 모든 덩어리에 문자 라벨(`바뀜`·`추가`·`삭제`·`적용할 수 없음`)이 항상 붙는다.
- 초록/빨강 diff 색은 쓰지 않는다(색각 이상 및 신규 시맨틱 색 금지).

**상태 배지(`Badge`, 색 대신 변형 + 문자):**

| 상태 | 라벨 | variant |
|------|------|---------|
| pending | `검토 대기` | `default`가 아닌 `outline` + 굵게(600) — 큐에서 가장 눈에 띄되 accent 면 채움은 쓰지 않음 |
| accepted | `반영됨` (일부만이면 `일부 반영됨`) | `secondary` |
| rejected | `거절함` | `secondary` |
| superseded | `새 초안으로 대체됨` | `secondary` + `text-muted-foreground` |
| expired | `만료됨` | `secondary` + `text-muted-foreground` |

## Copywriting Contract

해요체. 클라이언트명·호스트·제안 본문은 공격자 입력으로 취급해 텍스트로만 렌더링한다. 토큰·grant ID·내부 오류 원문·해시값은 표시하지 않는다. '제안'(AI가 보낸 것)과 '반영'(본문에 들어간 것)을 일관되게 구분한다. `승인`은 12 동의 화면 전용 단어이므로 여기서는 `수락`/`반영`을 쓴다.

### A. 리뷰 큐 `/studio/[workId]/review`

| Element | Copy |
|---------|------|
| 사이드바 항목 | `리뷰 큐` (+ 대기 건수 배지 `n`, 0이면 배지 없음. 접근성 이름 `리뷰 큐, 대기 n건`) |
| 페이지 제목 (h1) | `리뷰 큐` |
| 페이지 설명 | `연결된 AI가 보낸 초안과 설정집 제안이에요. 내가 수락한 부분만 작품에 반영돼요.` |
| 필터 탭 | `대기 중 n` · `처리됨` · `전체` (기본: `대기 중`) |
| 종류 라벨 | `회차 초안` / `설정집 수정안` / `설정집 새 문서` |
| 카드 제목 (h3, 18px) | 회차 초안: `{회차 제목} 초안` · 수정안: `{문서 제목} 수정안` · 새 문서: `{제안 제목}` |
| 카드 메타 1 | `{클라이언트명}` (600) + `{출처 호스트}` (caption, 항상 함께 표시) |
| 카드 메타 2 | `도착 {YYYY. M. D. 오후 h:mm}` (KST, `tabular-nums`). 24시간 이내 `n시간 전`, 1분 이내 `방금 전` |
| 카드 메타 3 | `만료까지 n일`(대기 중이고 7일 이하일 때만, caption) |
| 카드 요약 | 회차 초안: `바뀐 부분 n곳` · 수정안: `바뀐 부분 n곳` · 새 문서: `카테고리 {카테고리명}` |
| 카드 액션 | `검토하기` (outline, `aria-label="{카드 제목} 검토하기"`). 처리된 카드는 `내용 보기` |
| 연결 해제된 출처 | 클라이언트명은 스냅샷 그대로 표시, 호스트 옆 caption `연결 해제됨` |
| 정지 계정 안내(해당 시, 큐 상단 caption) | `지금은 계정이 제한되어 AI가 새 제안을 보낼 수 없어요. 이미 도착한 제안은 검토할 수 있어요.` |
| 대기 상한 도달 안내(해당 시) | `대기 중인 제안이 가득 찼어요. 오래된 제안을 처리하면 새 제안을 받을 수 있어요.` |

**빈 상태 (대기 중 0건):**

| Element | Copy |
|---------|------|
| Heading | `검토할 제안이 없어요` |
| Body | `연결된 AI가 초안이나 설정집 제안을 보내면 이곳에 도착해요. 제안은 도착한 지 30일이 지나면 만료돼요.` |
| 보조 링크 | `AI 커넥터 관리` (→ `/studio/settings/mcp-connections`, 링크 스타일, 버튼 아님) |

`처리됨`·`전체`가 비었을 때: Heading `처리한 제안이 아직 없어요`, Body `수락하거나 거절한 제안이 여기에 쌓여요.`

**로딩 / 오류:**

| 상태 | Copy |
|------|------|
| 로딩 | 카드 모양 스켈레톤 3개(`aria-busy="true"`, 영역 `role="status"` 숨김 텍스트 `제안 목록을 불러오는 중이에요`) |
| 목록 오류 | `제안 목록을 불러오지 못했어요. 잠시 뒤 새로고침해 주세요.` (`role="alert"`, destructive 톤) + `다시 불러오기` (outline) |
| 작품 없음/남의 작품 | 기존 스튜디오 동작과 동일(404 처리). 별도 문구 없음 |

### B. 회차 초안 검토 (상세 a)

| Element | Copy |
|---------|------|
| 뒤로 링크 | `리뷰 큐로 돌아가기` |
| 제목 (h1) | `{회차 제목} 초안 검토` |
| 출처 줄 | `{클라이언트명} · {호스트}에서 {도착 시각}에 보냈어요` |
| 설명 | `원본과 달라진 부분을 문단 단위로 나눴어요. 반영할 부분만 골라 수락하세요. 고르지 않은 부분은 지금 본문 그대로 남아요.` |
| 덩어리 헤더 | `{n}번째 변경 · 바뀜`(또는 `추가`/`삭제`) |
| 패널 라벨 | `지금 본문` / `AI 초안` |
| 덩어리 선택 라벨 | 체크 `<label>`: `{n}번째 변경 반영` |
| 덩어리 상태 | 선택 안 함 caption `반영 안 함`, 선택함 `반영함` (체크와 함께 문자로 표시) |
| 일괄 컨트롤 | `전체 선택` · `전체 해제` (둘 다 outline `size=default`, 토글 아님; 현재 선택 수 `n/m개 선택` `role="status"`) |
| 변경 없는 문단 | 접힌 줄 `변경 없는 문단 {k}개` (펼치기 버튼, 기본 접힘, 앞뒤 1문단 맥락만 보임) |
| 확정 CTA (accent, 하단 고정 바) | `선택한 {n}개 반영하기` (n=0이면 `disabled`, 옆 caption `반영할 부분을 하나 이상 골라 주세요.`) |
| 보조 | `이 제안 거절하기` (outline → 거절 Dialog) |
| 반영 확인 Dialog 제목 | `선택한 {n}개를 본문에 반영할까요?` |
| 본문 1 | `{회차 제목}의 본문이 바뀌어요. 선택하지 않은 {m}개는 지금 본문 그대로 남아요.` |
| 본문 2 (caption) | `반영한 뒤에는 한 번 되돌릴 수 있어요. 되돌리기는 이 제안 화면에서 할 수 있어요.` |
| 버튼 | 취소(outline, 초기 포커스) / `반영하기`(accent) |
| 진행 중 | `반영하는 중…` (`role="status"`, 두 버튼 `disabled`) |
| 성공 | 화면이 완료 상태로 전환: `{n}개를 본문에 반영했어요.` (`role="status"`) + `회차 열기`(outline 링크) + `반영 되돌리기`(outline) + caption `되돌리기는 한 번만 할 수 있어요.` |
| 실패 | `반영하지 못했어요. 본문은 바뀌지 않았어요. 잠시 뒤 다시 시도해 주세요.` (`role="alert"`) — 부분 반영 없음(전부 또는 전무) |

**원본이 바뀐 경우 (D-P14-04):**

| Element | Copy |
|---------|------|
| 경고 카드 제목 (`role="alert"`, destructive 톤 테두리, `AlertTriangle`) | `원본이 바뀌었어요` |

## Interaction Contract

**큐**
1. 큐는 서버 렌더. 정렬: 대기 중 → 도착 최신순. 처리됨 → 처리 최신순. 필터는 URL 쿼리(`?status=pending|done|all`)로 유지하고 `Tabs`로 전환(`role="tablist"`, 방향키 이동, 활성 탭 `aria-selected`). 자동 폴링 없음.
2. 만료 집행은 조회 시 서버가 기준을 적용한다. 만료된 대기 제안은 `처리됨`에 `만료됨`으로 보이고 `검토하기`가 아니라 `내용 보기`만 제공(반영·거절 불가).
3. 카드 1개 = `<li>`, `<ul aria-label="제안 목록">`, 카드 `aria-labelledby`로 제목 연결. 메타는 `<dl>`/`<dt>`/`<dd>`(클라이언트·출처·도착 시각). 상태 배지는 문자 라벨 필수. `검토하기` 버튼은 제목을 포함한 `aria-label`.

**상세 – 덩어리 선택**
4. 덩어리는 `<ol>`의 `<li>`(`aria-label="{n}번째 변경, {바뀜|추가|삭제}"`). 각 덩어리는 `<fieldset>`이 아니라 단일 체크 `<label>`(체크박스 + `{n}번째 변경 반영`)을 헤더로 하고, 비교 본문은 `aria-describedby`로 체크박스와 연결한다.
5. 선택 상태는 클라이언트 상태. `n/m개 선택`을 `role="status"`(polite)로 갱신. 전체 선택/해제는 적용 불가 덩어리를 건너뛴다. CTA는 선택 수 0이면 `disabled`.
6. 수락은 **선택한 덩어리를 한 번의 Server Action으로 원자적 반영**(전부 성공 또는 전부 무변경). 서버는 제출 시점에 해시를 다시 비교하고, 다르면 반영 없이 '원본이 바뀌었어요' 상태로 되돌려 재비교 결과를 반환한다(UI 신뢰 금지). 이중 제출 방지: 진행 중 모든 컨트롤 `disabled`.
7. 거절은 **제안 전체**에 대한 동작이다. 덩어리 단위 거절은 '체크하지 않음'으로 표현한다(별도 거절 버튼을 덩어리마다 두지 않는다). 따라서 파괴적 확인은 `이 제안 거절하기`와 `반영 되돌리기` 두 곳에만 둔다.
8. 확정(반영) Dialog와 거절·되돌리기 Dialog는 `ByokKeyCards`/12 해제 다이얼로그 패턴: 초기 포커스 `취소`, 닫힐 때 트리거로 복귀, Esc로 닫기, 진행 중 닫기 불가.
9. 반영 성공 후 포커스는 상태 메시지 영역(`tabIndex={-1}`)으로 이동한다. 거절 성공은 큐로 이동하고 큐 상태 메시지 영역으로 포커스. 상세 진입 시 `h1`에 `tabIndex={-1}` 포커스.
10. 키보드: 체크는 Space, 덩어리 간 이동은 Tab(체크 → 변경 없는 문단 펼치기 → 다음 덩어리). 고정 하단 바는 DOM상 본문 뒤에 두어 포커스 순서가 읽기 순서와 같게 한다. 비교 본문 패널은 스크롤 영역이 아니라 페이지 스크롤을 따른다(중첩 스크롤 금지; 긴 덩어리도 펼쳐 표시).
11. 새로고침·재진입 시 상세는 항상 서버의 현재 상태(대기/반영됨/거절됨/만료됨)를 그린다. 이미 처리된 제안은 체크 UI 없이 읽기 전용 결과(반영된 덩어리 `반영함`/`반영 안 함` 라벨)를 보여준다.

**데스크톱(≥ md) 레이아웃**
12. 상세: `max-w-5xl` 중앙. 덩어리마다 `grid grid-cols-2 gap-4`: 좌 `지금 본문`(`bg-muted`), 우 `AI 초안`. 두 열은 같은 덩어리 안에서 행 정렬(문단 단위라 높이 맞춤 불필요, `items-start`). 하단 고정 바는 `sticky bottom-0 border-t bg-card`에 `n/m개 선택`(좌)·`이 제안 거절하기`(outline)·`선택한 n개 반영하기`(accent)(우).
13. 큐: `max-w-2xl` 단일 열 카드 목록(12 관리 페이지와 동일 `mx-auto flex max-w-2xl flex-col gap-6 p-4 md:p-8`).

**모바일(≤ 375px) 레이아웃 – 나란히 비교의 접기 규칙**
14. `grid-cols-2`는 `md` 미만에서 **세로 쌓기**로 바뀐다: 덩어리 안에서 `지금 본문`(라벨 caption + `bg-muted`) → `AI 초안`(라벨 caption + 좌측 보더) 순으로 위아래 배치. 가로 스크롤·미니 2열 금지. 각 패널 라벨은 항상 보이고(스크린리더 순서도 동일), 추가/삭제 덩어리는 해당 패널이 없으면 `없음` 텍스트 대신 패널을 생략하고 라벨에 `추가`/`삭제`를 표시한다.
15. 모바일 덩어리 본문은 기본 6줄(`line-clamp-6`)로 접고 `전체 보기`/`접기` 버튼(44px, `aria-expanded`)을 둔다. 단, 적용 불가 덩어리와 추가/삭제로 한쪽만 있는 덩어리는 접지 않는다.
16. 하단 고정 바는 모바일에서 `fixed inset-x-0 bottom-0`, 2행: 1행 `n/m개 선택`, 2행 버튼 세로 쌓기(`반영하기` 위, `거절하기` 아래; DOM 순서도 거절 → 반영이므로 12 UI-SPEC 4번과 같이 `flex-col-reverse`로 시각만 뒤집고 포커스 순서 차이를 구현 시 확인). 본문 하단에 바 높이만큼 `pb` 확보(콘텐츠 가림 금지). `전체 선택`/`전체 해제`는 목록 상단(바 아님).
17. 큐 카드: `flex-col`, 메타는 세로, `검토하기`는 전폭(`w-full sm:w-auto`, 44px). 필터 탭은 3개가 375px에 한 줄로 들어가도록 라벨을 짧게 유지(`대기 중 n`/`처리됨`/`전체`); 넘치면 가로 스크롤 없이 균등 폭.
18. 설정집 폴더 `Select`는 모바일에서 전폭. Dialog 푸터 버튼 세로 쌓기, 초기 포커스 `취소`.

**모션·접근성 공통**
19. 장식 애니메이션 없음. 접힘/펼침은 `motion-reduce:transition-none`. 모든 아이콘 `aria-hidden`. 포커스 링은 기본 `ring`. 대비는 기존 토큰 기준(본문 4.5:1 이상).
20. 오류 알림(`role="alert"`)이 뜨면 해당 알림 카드로 포커스 이동. 성공·진행 메시지는 `role="status"`.

## Layout Notes

- **큐:** `h1/설명 → (정지·상한 안내 caption) → 필터 Tabs → 카드 목록 또는 빈 상태`. 카드: 상단 행 `종류 라벨(caption) + 상태 배지`, 제목(h3), 메타 `<dl>`, 요약 한 줄, 하단 `검토하기`.
- **회차 초안 상세:** `뒤로 링크 → h1 → 출처 줄 → 설명 → (원본 바뀜 경고) → 전체 선택/해제 + 선택 수 → 덩어리 목록(앞뒤 변경 없는 문단은 접힌 줄) → 하단 고정 바`.
- **설정집 수정안 상세:** 위와 동일. 잠금·삭제 시 설명 아래에 안내 카드가 들어가고 하단 바는 `거절하기`만 활성.
- **신규 생성안 상세:** `뒤로 링크 → h1 → 출처 줄 → 카테고리 줄 → AI가 제안한 내용 → 저장할 폴더(Select) → 하단 고정 바`.
- **반영 완료 상태:** 체크 UI와 하단 바 제거, 상단에 성공 메시지 + `회차 열기`/`문서 열기` + `반영 되돌리기`. 아래에 읽기 전용 결과 목록.
- 스튜디오 홈 카드와 사이드바는 기존 레이아웃을 바꾸지 않고 배지 한 줄만 추가한다.

## 추가 계약 (discuss 이후 확정, 2026-11-04) — D-P14-10·11

목업 Artifact: https://claude.ai/artifact/8zBNvn8jTMTP7fT6GjdkoW (보드별 화면이 본 계약의 시각 기준)

**덩어리 거절 = A안:** 덩어리마다 체크박스 하나. 체크하지 않으면 반영되지 않고 별도 거절 버튼·상태는 없다. 하단 바 문구는 `선택한 변경 n개`, 확정 버튼 `선택한 n개 반영하기`, 보조 문구 `체크하지 않은 변경은 반영되지 않아요.`

**직접 고치기 (덩어리 헤더):**
- 버튼 `직접 고치기` ↔ `고치기 닫기`(`aria-expanded`). `추가`·`바뀜` 덩어리에만 있다. `삭제`·`적용할 수 없음` 덩어리에는 없다.
- 열리면 AI 초안 칸이 `textarea`(라벨 `반영할 내용을 직접 고쳐요`)로 바뀌고, 안내 `고친 내용이 AI 초안 대신 본문에 들어가요.` + 버튼 `AI 초안으로 되돌리기`. 원문과 달라지면 헤더에 `직접 고침` 라벨.
- 서버는 고친 텍스트를 신뢰하지 않고 길이·소유권·원본 해시를 수락 시 재검증한다.

**AI와 다듬기 (덩어리 사이드 채팅):**
- 버튼 `AI와 다듬기` ↔ `AI 닫기`(`aria-expanded`). 같은 덩어리 종류에만 노출. 열리면 덩어리 아래에 패널(`section`, `aria-label="변경 n AI와 다듬기"`).
- 패널 안내: `이 덩어리만 AI와 다듬기` / `대화는 이 화면에서만 보이고 저장되지 않아요.` / `앱 AI 사용량이 차감돼요(내 키를 등록했다면 내 키로 호출해요). AI 답은 본문에 바로 들어가지 않아요.`
- 말풍선(나/AI), 입력(라벨은 시각적으로 숨김, placeholder 예시 문구), `보내기`. AI 답마다 `이 내용을 직접 고치기에 넣기` 버튼 — 누르면 직접 고치기 입력란이 열려 채워진다. 수락 체크는 별개 단계.
- 실패(잔액 부족·키 오류·한도)는 AiPanel의 원인별 오류 문구·재시도 패턴을 재사용하고 패널 안에 `role="alert"`로 표시한다. 모든 터치 타깃 44px.

**추가 화면 (목업 보드):** 리뷰 큐 목록, 모바일 375px 상세, 설정집 수정안 비교, 설정집 신규 생성안(폴더 선택), 확인 Dialog 3종(반영/거절/되돌리기), 스튜디오 홈·회차 대기 표시.
