# 14-13 패치 형식(사용자 호칭 "14-10") — CONTEXT

작성: 2026-11-10 · 브랜치 `claude/phase14-merge` · 상태: discuss 완료, research/plan 진행. **구현은 plan 승인 전까지 하지 않는다.**
번호: 사용자가 "14-10"이라 불렀지만 14-10은 다중 초안·상한·정규화(0043)로 이미 배정돼 이 기능은 **14-13**이다. 문서·보고에서는 "패치 형식(사용자 호칭 14-10)"이라고 병기한다.

## 문제
`propose_kb_document`(수정)와 `save_draft`는 문서 **전체 텍스트**를 받는다. 설정집 한 줄만 고쳐도 외부 AI가 전체를 출력해야 한다. 사용자 Claude 계정의 출력 토큰이 낭비되고 느리며, AI가 다른 문단을 의도치 않게 바꿀 위험이 있다. 문서를 읽는 입력 토큰은 줄일 수 없고, 줄일 대상은 출력이다.

## 사용자 확정 결정 (2026-11-10, 이 세션에서 직접 답)
| ID | 결정 |
|---|---|
| D-PATCH-01 | 연산은 **3종을 한 번에**: `replace{find,replace}`, `replace_range{start_text,end_text,replace}`, `replaceAll{content}` |
| D-PATCH-02 | **설정집 수정(`propose_kb_document` edit)과 회차 초안(`save_draft`) 둘 다** `edits[]`를 받는다 |
| D-PATCH-03 | AI가 읽은 뒤 문서가 바뀌어 `base_hash`가 맞지 않으면 **거절하고 최신 해시를 돌려준다**(재탐색해 적용하지 않음) |
| D-PATCH-04 | 기존 "문서 전체 `content`" 입력은 **`replaceAll`로 흡수**한다(병행하지 않음). 신규 생성안(`mode: create`)은 원본이 없으므로 `content` 유지 |

## 다른 세션 설계안(`local_6a321077…`, 메모 `mcp-patch-design-memo.md`)에서 받아들인 것
- 한 요청 = 한 트랜잭션, 전부 성공 또는 전부 취소. 적용은 제안 RPC 안에서 원본을 읽는 같은 트랜잭션에서.
- `base_hash` 필수. 범위 겹침 금지. `replaceAll`은 다른 연산과 병용 불가.
- (문단, 문장) 좌표는 신뢰 근거가 아니다. 선택 힌트(`hint_para`)와 오류 메시지의 "근처 문단 N" 용도로만.
- 오류는 실패 edit 번호, 사유(0회/N회 일치/겹침/순서 오류), 후보 위치와 앞뒤 20자 문맥, 최신 해시를 돌려준다.
- 성공 응답에 변경 구간 앞뒤 1~2문단을 돌려준다(재읽기 왕복 제거, 이음새 점검).
- 도구 설명에 "수정 구간의 앞뒤 문장과 연결되는지 확인" 한 줄. 도구 설명은 길게 쓰지 않는다.
- 제안 행에 표시용 `anchor_meta jsonb`(선언 범위)를 둘지는 plan에서 정한다. 범위 밖 변경 경고 UI는 후속.

## 코드 대조에서 확인된 사실 (research 참고)
- 제안 RPC 3개는 이미 원본을 같은 트랜잭션 안에서 읽어 `base_content`/`base_hash`를 서버가 저장한다. 수락 RPC(0042)는 전체 `content`와 현재 원본 해시만 쓰므로, 패치를 제안 시점에 전체 제안본으로 풀면 **수락·되돌리기·덩어리 비교는 바뀌지 않는다**.
- 읽기 도구(`get_kb_document`, `get_chapter`)는 **내용 해시를 돌려주지 않고** offset/maxChars로 쪼개서 읽는다. `base_hash`를 받으려면 읽기 응답에 전체 문서 해시 필드를 **추가**해야 한다(기존 필드는 유지).
- OAuth 토큰은 테이블을 직접 읽지 못한다(D-17 경계). 패치 적용은 TS가 아니라 SQL(제안 RPC 안)이 원자성과 정규화 일관성에 맞다.

## 미정 (plan에서 확정할 값)
- 최대 `edits` 개수, `find`/`start_text`/`end_text` 최소·최대 길이, 결과 본문 길이 상한(기존 회차 100,000자 / 설정 50,000자 유지), `replace_range` 최대 삭제 길이.
- 일치 판정에 쓰는 텍스트(원본을 LF로 본 사본 vs 원문 그대로), NFC 정규화 여부, 반복 어구 처리.
- 일괄 치환(`replace_every`)은 이번 범위가 아니다(필요하면 후속).
- 토큰 절감 측정 방법(실제 사용 로그로 손익분기 재측정 — 메모의 수치는 가정치).
