# Phase 18 Plan 14: World-tree Eligibility DB and Reader-visibility Helper Summary

Migration 0033 now defines the one shared answer to "can a reader see this work" (`world_work_reader_visible`), the rule-22 policy block generated by 18-13, and one evaluator. Both the owner-only lookup and the internal assert that 18-02 calls go through that evaluator. A parent that readers cannot see is rejected as `parent_not_visible` before any chapter or KB query runs.

## What was built

- **`world_work_reader_visible(uuid)`**: `language sql stable security definer set search_path = public`. Returns false for a missing work, a null id, a deleted work, a branch draft, a work-wide admin blind, or a work with no live published chapter. It reads only the base columns of the work itself. It never calls can_view or the read RPCs and does not rely on `works_public_read`, so 0036 can build on it without recursion. It has no owner, admin, parent or count exceptions. PUBLIC is revoked, and anon, authenticated and service_role get EXECUTE explicitly.
- **Generated block**: the output of `renderEligibilityPolicySql()`, pasted unchanged between the BEGIN/END markers. Outside the markers no threshold number appears; the static test enforces this. service_role is revoked on the three generated functions as well.
- **`world_tree_evaluate_branch_eligibility(p_source_work_id, p_lock)`**: an internal SECURITY DEFINER function with no API grants. It builds the 18-01 `BranchEligibilitySummary` JSON.
  - When the work is not reader-visible it returns `readerVisible=false`, `eligible=false`, `unmetReasons=['parent_not_visible']` and zero counts. `isPublished` keeps the real fact, so a blinded published parent reports true.
  - When it is visible, it counts alive published chapters, and work-scope `file` documents of the same work in the counted categories that are not deleted, reach the minimum length after `world_tree_eligibility_body`, and are not untouched seeds according to `world_tree_eligibility_is_untouched_seed` joined with `kb_template_seed_catalog`.
  - Unmet reasons come out in the same order as the TS evaluator.
- **`get_world_branch_eligibility(uuid)`**: owner-only. It calls the evaluator with `p_lock=false`. Revoked from PUBLIC, anon and service_role; granted to authenticated. Auth and ownership failures raise errors; they are never turned into an "ineligible" result.
- **`world_tree_assert_branch_eligible(uuid)`**: calls the evaluator with `p_lock=true`. When the work is not eligible it raises `branch_ineligible` with `DETAIL = {"unmetReasons":[...]}`. No caller has EXECUTE; it is meant for 18-02's SECURITY DEFINER begin and first confirm, inside the same transaction.

## Deviations from Plan

- **[Rule 2 - Correctness] service_role revoke on the generated helpers.** Supabase grants EXECUTE on new public functions to service_role by default, and the 18-13 block only revokes public, anon and authenticated. I added explicit service_role revokes outside the markers instead of editing the generated block.
- **[Rule 2 - Correctness] Lock-mode write check.** In lock mode the evaluator also requires `user_can_write(auth.uid())` (`write_access_denied`). The read-only lookup does not, so a suspended writer can still see their status. 18-02 may still run its own check.
- **[Rule 3 - Blocking] Static test literal.** `vitest.config.ts` sends any file containing the DB env-var name to the db project. The source test builds that string in pieces so it stays in the unit project.
- The plan's "bodies are never returned" rule is enforced in two places: a static whitelist of jsonb keys, and DB checks that a secret body, a document name and a blind reason never appear in the response.
