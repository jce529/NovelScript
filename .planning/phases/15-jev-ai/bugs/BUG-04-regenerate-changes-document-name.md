# BUG-04: 템플릿 재생성 시 문서 이름이 바뀌어 저장된다

## 증상
"새 인물 강진욱에 대한 인물 설정 문서를 만들어줘"로 만든 제안(이름 "강진욱")에서 템플릿을 "기본 인물 템플릿"으로 바꿔 재생성·저장하자, 문서가 "강시후"라는 다른 이름으로 인물 > 서브인물 폴더에 저장됐다. 본문 제목도 `# 👤 강시후`. 사용자에게 알림이나 확인 없이 이름이 바뀐다.

## 재현
1. 인물 문서 제안 생성(이름 "강진욱") → 저장 모달.
2. 템플릿을 추천값과 다른 "기본 인물 템플릿"으로 변경 → 저장 → "다시 생성하기".
3. 저장된 서버 액션 로그의 `saveDocumentProposalAction`에서 `proposal.name`이 "강시후", `regenerated: true`.

(UAT 중에는 lite 모델 `gemini-3.5-flash-lite`로 임시 전환해 재현했다. 원래 모델에서도 같은지는 미확인.)

## 기대 / 실제
- 기대: 템플릿만 바꿔 다시 정리하므로 문서 이름과 사실은 원본 제안을 유지한다.
- 실제: 모델이 낸 이름이 원본 이름을 덮어쓴다.

## 원인
`document-regenerate.ts:94-95`가 모델 출력의 `parsed.proposal!.name`을 그대로 반환하고, 모달(`SaveDocumentPlanModal.tsx:102`)은 `override.name || proposal.name`으로 재생성 이름을 우선 사용한다. 프롬프트(`document-regenerate.ts:72`)는 "여기에 없는 사실을 새로 확정하지 말 것"이라고만 하고 이름 유지를 명시하지 않으며, 결과 검증(`validateDocumentAgainstPlan`)도 이름 일치를 확인하지 않는다.

## 수정 방향
확정 — 사용자 결정: C안(A + B 병행).
1. **이름 서버 강제(A)**: `regenerateDocumentWithTemplate`가 반환하는 `name`을 `parsed.proposal!.name`이 아니라 `input.proposal.name`으로 고정한다(`document-regenerate.ts:95`). 모달의 `override.name || proposal.name`은 그대로 두어도 결과가 원본 이름이 된다.
2. **프롬프트 명시(B)**: `contents`(`document-regenerate.ts:72`)와 시스템 지시에 "문서 이름은 `${input.proposal.name}` 그대로 유지하고, 본문 제목과 링크의 이름도 바꾸지 말 것"을 추가한다.
3. **본문 검증(B)**: 재생성 결과 본문의 이름이 원본과 다르면 `REGENERATION_FAILED`로 처리해 재시도를 유도한다. 이름 강제 고정만으로는 `# 👤 강시후` 같은 본문 제목 불일치가 저장되므로 이 검증이 필요하다. 구현은 `validateDocumentAgainstPlan`에 선택 인자(`expectedName`)를 추가하거나 재생성 전용 검사로 두되, 판정 기준은 (a) 본문 첫 제목 줄에 원본 이름이 포함되는지, (b) 원본 본문에 있던 `[[링크]]` 이름이 결과에서 사라지거나 바뀌지 않았는지로 한다. 템플릿 제목이 `<% tp.file.title %>` 치환 형태(`substituteTitle`)라 이름 포함 여부 검사가 안전한지 구현 시 확인한다.
4. 원래 모델(lite가 아닌)에서 재현되는지는 미확인이나, 1번은 모델과 무관한 안전장치이므로 그대로 적용한다.

### 확정 및 적용 (2026-09-29)
사용자 확정: **C (A+B 병행)**, 본문 제목도 검증. `lib/ai/document-regenerate.ts`:
- 반환 `name`을 모델 출력이 아닌 원본 `input.proposal.name`으로 강제.
- 프롬프트(`contents`)에 원본 이름 유지 + 본문 제목에 같은 이름 사용 지시 추가.
- 본문 첫 H1이 원본 이름을 포함하지 않으면 `REGENERATION_FAILED`.
- 재생성 본문의 모든 `[[링크]]` 대상이 원본 `proposal.content`에 있던 대상인지 검증하고, 원본의 `[[문서 이름]]` 링크도 유지되지 않으면 `REGENERATION_FAILED` 처리.
- 테스트: `tests/ai/regenerate-document.test.ts`에 이름 유지/제목 불일치 및 링크 대상/자기 이름 링크 검증 추가.
- **브라우저 UAT 필수 — 미실시.** 아래 "검증"의 브라우저 UAT를 통과하기 전에는 `/bug-complete`로 넘어가지 말 것(status: open 유지).

## 검증
- 단위 테스트: 모델이 다른 이름을 반환하는 픽스처에서 반환 `name`이 원본으로 고정되는지.
- 단위 테스트: 본문 제목/링크가 다른 이름이면 `REGENERATION_FAILED`가 되는지, 이름이 같으면 통과하는지.
- 단위 테스트: 프롬프트(`contents`)에 원본 이름 유지 문구가 포함되는지.
- 브라우저 UAT: 템플릿 변경 재생성 후 문서 이름이 원본과 같은지 확인.

## 브라우저 UAT 진행 (2026-09-29, 테스트 DB, localhost:3000) — 부분 통과
- **통과 (1~3단계)**: "새 인물 강진욱…"으로 만든 제안(본문에 `[[링크]]` 없음)을 추천 "인물"과 다른 링크 없는 템플릿(`UAT링크없음`)으로 "다시 생성하기" → 저장. 저장된 문서 이름 "강진욱", 위치 `인물`(최상위), 첫 제목 `# 👤 강진욱`, 링크 없음. 채팅에 "문서로 저장됨 ✓" 표시.
- **미확인**: 링크 가드(4), 반복 시 이름 변경 사례(5), 이름 변경 응답의 실패 안내(6). Gemini 503, 이어서 무료 티어 하루 20회 쿼터 소진(429)으로 진행하지 못했다.
- **관찰 — 가드 오탐 가능성**: `기본 인물 템플릿`으로 재생성했을 때 제공자는 응답했는데 `문서를 다시 생성하지 못했어요`(`REGENERATION_FAILED`)로 거부됐다. 작품·계정·기본 인물 템플릿 3종 모두 예시 `[[엑스칼리버]]`, `[[원탁의 기사단]]`, `[[색슨족]]`, `[[인물A]]`, `[[인물B]]`, `[[사건 링크]]`, `[[드래곤 토벌전]]`, `[[부모님 사망]]`를 포함한다. 원본 제안에 이 링크가 없으면 템플릿 구조를 따른 재생성 결과의 링크가 모두 "원본에 없던 대상"으로 걸려 스톡 템플릿 재생성이 거의 항상 실패할 수 있다. 다만 이 거부가 링크 가드 때문인지(제목 불일치·`validateDocumentAgainstPlan` 실패일 수도 있음)는 확정하지 못했다. `regenerateDocumentWithTemplate`가 세 경우 모두 같은 `REGENERATION_FAILED`만 반환하고 사유를 로그로 남기지 않는다.
- **다음에 확인할 것**: (a) `기본 인물 템플릿`으로 재생성을 다시 시도해 결과가 일관되게 거부되는지, (b) 거부 사유를 구분하려고 임시로 사유별 로그를 남기거나 함수를 픽스처로 직접 호출해 확인, (c) 예시 링크를 템플릿 자리표시자로 보고 가드에서 제외할지(수정 방향) 결정. 링크 가드 정책 변경은 동작 변경이라 사용자 확인 후 `/bug-plan`으로 방향을 갱신한다.
- 5번(lite 아닌 모델)은 현재 설정에서 `pro`도 `gemini-3.5-flash`(`lib/ai/providers/models.ts`)라서 결제를 켜 `gemini-3.1-pro-preview`로 옮기기 전에는 확인할 수 없다.

## 브라우저 UAT 진행 (2026-10-02, 테스트 DB, localhost:3000) — 추가 결과
- **통과**: 추천 템플릿이 인물 카테고리 후보 중에서 선택된다(BUG-03 2-5). 템플릿 목록은 작품/계정/기본 3그룹, 인물용 4건만 나온다.
- **가드 오탐 의심 → 원인 확인(임시 진단 로그, 커밋 안 함)**: `기본 인물 템플릿`으로 재생성이 거부되는 이유는 이름·구조 검증이 아니라 **링크 가드**다. 원본 제안(서하준, 링크 없음)에서 모델이 템플릿의 "연관된 세력/주요 인물 관계" 칸을 채우며 `[[세현그룹]]`, `[[채아]]`, `[[강진욱]]`을 새로 넣었고, `originalLinks=[]`라서 `REGENERATION_FAILED`가 났다. 이름 유지·본문 제목("# 👤 서하준")·`validateDocumentAgainstPlan`은 모두 통과했다. 즉 BUG-04 4번(새 링크 대상이 있으면 실패 안내)은 의도대로 동작했다. 반대로 링크 섹션이 있는 기본 인물 템플릿은 **링크 없는 원본에서는 거의 항상 거부**되는 부작용이 있다 → 정책 결정 필요(아래).
- **추가 관찰 — 재시도 문구**: 가드 거부(유료 생성 결제 처리 후 실패) 뒤 같은 템플릿으로 다시 "다시 생성하기"를 누르면 같은 idempotency 키가 재사용돼 "같은 요청이 두 번 전송돼 한 번만 처리했어요."가 먼저 뜬다(그다음 시도에서 키가 초기화돼 정상 진행). `SaveDocumentPlanModal.tsx`의 `regenKeyRef`가 `already_processed`에서만 초기화되기 때문이다. 제공자 503처럼 결제가 확정되지 않은 실패에서는 같은 키 재시도가 정상 동작했다.
- **미확인**: 이름이 바뀐 응답의 실패 안내(6번, 이번 호출들에서는 모델이 이름을 유지함), 원래 모델 반복 재현(5번), 링크 있는 원본 제안에서의 재생성(4번 전반부).
- **[해결됨 — 15-05]** 아래 정책 결정은 3안(KB 존재 허용)+프롬프트 목록으로 확정·구현돼 `.planning/fixed/15-05 …`로 이관됨(2026-10-02). 원래 질문:
- **정책 결정 대기(과거)**: 링크 가드를 (a) 유지, (b) "원본 링크가 없으면 새 링크를 제거해 통과", (c) 새 링크 대상이 KB에 실제 존재하는 문서면 허용 중 무엇으로 할지. 결정 전에는 `/bug-complete` 금지.
