# Phase 14 — UI Design Contract

> MCP 쓰기 도구로 도착한 초안·설정집 제안을 작가가 검토하는 스튜디오 리뷰 큐의 시각·상호작용 계약. `14-CONTEXT.md` D-P14-01~18을 고정 결정으로 따르고, `12-UI-SPEC.md`(토큰·타이포·색·Dialog 패턴)와 기존 스튜디오 셸(SiteHeader, SidebarGroup/KbTree, StudioPane, 모바일 탭 3개)을 상속한다. 새로 추가되는 부분만 정의한다.
>
> **표기 규칙:** `[확정]` = CONTEXT/사용자 승인 결정. `[목업 확인 대기]` = 사용자가 아직 확정하지 않았으므로 오케스트레이터는 잠그지 말고 목업으로 확인받는다. `[플래너 재량]` = plan에서 정해도 되는 값.

## Spacing Scale

Phase 12와 동일(4의 배수만).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 배지-글자, 아이콘-텍스트 간격 |
| sm | 8px | 버튼 간격, 행 내부 요소 간격, diff 줄 사이 |
| md | 16px | 카드 내부 요소 간격, 행 패딩, hunk 간격 |
| lg | 24px | 카드 안쪽 여백(`p-6`), 목록-상세 사이 gap |
| xl | 32px | 페이지 바깥 여백(`md:p-8`) |
| 2xl | 48px | 사용하지 않음 (트리 들여쓰기는 기존 `paddingLeft` 값 그대로) |
| 3xl | 64px | 사용하지 않음 |

Exceptions: 모바일(`< md`)에서 인박스 행 링크, 필터 탭, `거절`/`에디터로 가져오기`/`선택한 변경 적용`/hunk 수락·건너뛰기 버튼은 `min-h-11`(44px) 보장(`Button size="default"`, `sm` 금지). 트리 배지는 기존 트리 행 높이(`h-8`, 모바일 `h-10`) 안에 들어가므로 별도 터치 타깃을 만들지 않고 행 전체 폭을 유지한다. 모바일 하단 고정 액션바는 `safe-area-inset-bottom`을 더한다. ## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption (출처 시각, 보조 안내, 배지 숫자, diff 행 번호) | 12px (`text-xs`) | 400 (숫자 배지는 600) | 1.5 |
| Body / Label / Button / 초안 본문 / diff 본문 | 14px (`text-sm`) | 400 (본문) / 600 (라벨·버튼·행 제목·클라이언트명) | 1.5 고정 (초안 본문 미리보기 포함, `whitespace-pre-wrap`) |
| Section heading (카드·섹션 제목) | 18px (`text-lg`) | 600 | 1.2 |
| Page heading | 24px (`text-2xl`) | 600 | 1.2 |

크기 4종(12/14/18/24), 굵기 2종(400/600). `font-medium`(500)은 신규 요소에 쓰지 않는다(기존 `SidebarGroup`의 500은 건드리지 않음). 시각·숫자는 `tabular-nums`. 한국어 `break-keep`을 제목·안내에, 초안·diff 본문은 `break-words` + `whitespace-pre-wrap`(`break-keep` 금지, 긴 줄 가로 스크롤 금지). 클라이언트명·작품명·문서 경로는 `truncate`(행) / `break-all`(상세) + `min-w-0`. diff 본문은 모노스페이스를 쓰지 않는다(설정집은 산문). ## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` | 페이지 바탕, 초안 미리보기 |
| Secondary (30%) | `bg-card`/`bg-muted`, `border-border` | 목록 행, 상세 카드, diff 패널, 안내 박스, 정지 계정 배너(`bg-muted`) |
| Accent (10%) | `bg-primary`(indigo-600)/`ring` | 아래 reserved 목록만 |
| Destructive | `text-destructive`, `variant="destructive"`, `bg-destructive/10` | 거절 확정 버튼, diff의 삭제된 줄 배경, 실패 알림 |

Accent reserved for: (1) 검토 대기 개수 배지(헤더 A, 회차/설정집 트리 B·C) `bg-primary text-primary-foreground`, (2) 화면별 단일 기본 CTA — 초안 `에디터로 가져오기`, 수정안 `선택한 변경 적용`, 신규 문서 `설정집에 추가`, (3) 에디터 안내줄의 `검토하기` 링크, (4) 선택된 hunk의 `수락` 상태 표시, (5) 키보드 포커스 링. 그 외 클라이언트명·시각·종류 태그·필터 탭 비활성 항목에는 accent를 쓰지 않는다.

- `거절`은 목록·상세 모두 `variant="outline"`(거절은 되돌릴 수 없는 삭제가 아니라 이력 이동이므로 반복 노출 시 destructive 소음 방지). 다이얼로그 안 `거절` 확정 버튼만 `variant="destructive"`.
- 종류 태그(`초안`/`설정집`/`새 문서`/`수정안`)와 상태(`수락함`/`거절함`/`대기 중`)는 `Badge variant="secondary"` 또는 `outline`. 색만으로 상태를 전달하지 않는다(문자 라벨 필수).
- **diff 색 `[목업 확인 대기]`:** 목업은 빨강/초록을 썼으나 신규 시맨틱 색을 만들지 않는 원칙(12-UI-SPEC)에 따라 삭제 줄 = `bg-destructive/10` + 접두 `−`, 추가 줄 = `bg-primary/10` + 접두 `+`로 한다. 색맹 대응을 위해 접두 기호와 sr-only 라벨(`삭제됨`/`추가됨`)을 반드시 함께 둔다. 녹색 신규 토큰이 필요하면 사용자 결정 사항.
- 경고/안내 박스(정지 계정, 상한 도달, 원문 변경 알림)는 `bg-muted` + `Info`/`Lock` 아이콘 + `border-border`. 신규 노란색 금지. 오류만 `role="alert"` + destructive 톤.
- 목업의 주황(`--new`)·파랑 accent는 프로젝트 토큰이 아니므로 사용하지 않는다. 목업은 배치 확인용이다.
- 다크 모드: 모든 값이 CSS 변수 토큰이므로 별도 값 없음.

## Copywriting Contract

해요체. 외부 AI가 보낸 문자열(클라이언트명, 초안 본문, 제안 제목, diff 내용)은 모두 React 텍스트로만 렌더링한다(`dangerouslySetInnerHTML` 금지). 토큰·내부 ID·원문 오류는 어디에도 표시하지 않는다.

### A. 진입점 배지 (A / B / C)

| Element | Copy |
|---------|------|
| 헤더 링크 (A) | `AI 검토 대기` + 개수 배지(0이면 배지 생략, 링크는 항상 노출해 이력에 접근 가능). 99 초과 `99+`. 모바일(`< sm`)은 `Inbox` 아이콘 + 배지만, 텍스트는 `sr-only` |
| 헤더 링크 aria-label | `AI 검토 대기 {N}건` / 0건이면 `AI 검토 이력` |
| 회차 트리 배지 (B) | 숫자만. `aria-label="검토 대기 {N}건"`. 행 링크와 형제 요소(링크 안 링크 금지), 클릭 시 `/studio/review?work={id}&chapter={id}` |
| 설정집 트리 배지 (C) | 숫자만. `aria-label="검토 대기 {N}건"`. 클릭 시 `?work={id}&node={id}` |
| 접힌 폴더 합산 `[플래너 재량]` | 접힌 폴더는 하위 합계를 같은 배지로 표시, 펼치면 하위 행에만 표시 |
| 에디터 안내줄 (B) | `연결된 AI가 이 회차에 보낸 초안이 {N}건 있어요.` + 링크 `검토하기` (0건이면 줄 자체를 렌더링하지 않음) |
| 가져오기 직후 에디터 안내 | `초안을 에디터에 가져왔어요. 저장하면 본문에 반영돼요.` (`role="status"`, 안내줄 위치에 대체 표시, 다음 편집 또는 저장 시 사라짐) |

### B. 인박스 `/studio/review`

| Element | Copy |
|---------|------|
| 페이지 제목 (h1, 24px) | `AI 검토` |
| 페이지 설명 (14px muted) | `연결된 AI가 보낸 초안과 설정집 제안을 확인해요. 내가 수락하기 전까지 본문과 설정집은 바뀌지 않아요.` |
| 상태 전환 (Tabs) | `대기 중 {N}` / `이력` |
| 종류 필터 (Tabs) | `전체` / `초안` / `설정집` (각 탭에 건수) |
| 작품 필터 (Select) | 라벨 `작품`, 기본 `전체 작품` |
| 바로가기 범위 칩 (B/C 진입) | `{회차명}에 온 초안만 보는 중` / `{문서명}의 수정안만 보는 중` + 버튼 `전체 보기` |
| 행 제목 | 초안: `{작품명} · {회차 제목}` / 수정안: `{작품명} · {폴더/문서}` / 신규: `{작품명} · {제안 제목}` (작품 필터가 단일이면 작품명 생략) |
| 행 종류 태그 | `초안` / `설정집`, 설정집은 추가로 `수정안` 또는 `새 문서` |
| 행 출처 (caption) | `{클라이언트명} · {도착 시각}` — 시각: 1분 미만 `방금 전`, 1시간 미만 `{N}분 전`, 24시간 미만 `{N}시간 전`, 어제 `어제`, 그 외 `{M}월 {D}일`. `<time dateTime>` + `title`에 절대 시각 `YYYY. M. D. 오후 h:mm` (KST) |
| 이력 행 상태 | `수락함` / `거절함` + 처리 시각(caption `{M}월 {D}일 처리`) |
| 행 오른쪽 | 대기: `ChevronRight`(행 전체가 링크, 별도 `검토` 버튼 중복 금지. 시각 라벨 `검토`는 `md` 이상에서 텍스트로 함께 표시 가능) |
| 더 보기 | `더 보기` (outline, 페이지 크기 20 `[플래너 재량]`), 끝나면 caption `모든 항목을 불러왔어요.` |
| 이력 하단 caption | `수락·거절한 항목은 계속 보관돼요.` |
| 상한 도달 안내 (해당 작품만, 정보 박스) | `{작품명}의 검토 대기가 가득 찼어요 ({N}/{상한}건). 항목을 수락하거나 거절하면 연결된 AI가 다시 제안할 수 있어요.` (`{상한}`은 plan 확정값) |
| 정지 계정 배너 | 제목 `지금은 수락·거절할 수 없어요`, 본문 `계정이 제한되어 있어서 도착한 항목은 볼 수만 있어요. 제한이 풀리면 다시 검토할 수 있어요.` (`Lock` 아이콘, `bg-muted`, 인박스·상세 상단 공통) |

### C. 초안 검토 (kind=draft)

| Element | Copy |
|---------|------|
| 뒤로 가기 링크 | `← 검토 목록` (범위 진입이었다면 `← {회차명}으로` 도 함께 제공 `[목업 확인 대기]`) |
| 제목 (h1) | `초안 검토 · {회차 제목}` |
| 메타 `<dl>` | `출처` `{클라이언트명}` (+ caption 호스트 `claude.ai`), `도착` `{절대 시각}`, `분량` `{N,NNN}자`, `대상` `{작품명} · {회차 제목}` + 링크 `회차 열기` |
| 본문 미리보기 소제목 (h2, 18px) | `초안 내용` |

## Interaction Contract

**진입·내비게이션**
1. **A (헤더):** `SiteHeader`의 우측에 `AI 검토 대기` 링크를 둔다. 스튜디오 하위 모든 화면(작품 화면 포함)에서 보인다. 개수는 서버 렌더(작가의 모든 작품 합계 pending), 자동 폴링 없음. 수락·거절·가져오기 Server Action 후 `revalidatePath`로 갱신.
2. **B:** 회차 트리 행의 배지, 회차 에디터 상단 안내줄. 안내줄은 에디터 본문 바로 위, 저장 상태칩과 겹치지 않는 별도 줄(`bg-muted rounded-md px-4 py-2`). 0건이면 렌더링하지 않아 레이아웃을 밀지 않는다.
3. **C:** 설정집 문서 트리 행의 배지. 문서 편집 화면에는 안내줄을 두지 않는다(트리 배지만, 범위 최소화) `[목업 확인 대기]`.
4. B/C 배지는 행 링크와 형제 `<a>`이며 클릭 시 인박스를 범위 필터로 연다. 범위 칩의 `전체 보기`로 해제.
5. 인박스는 URL 쿼리가 곧 상태다. 필터 변경은 `router.replace`(히스토리 오염 방지), 항목 열기는 push.

**모바일 3탭 셸 안의 배치 `[목업 확인 대기: NEEDS USER CONFIRMATION]`**
- **권장안(M1):** 인박스와 상세는 `/studio/review`로 작품 셸(`[workId]/layout`) **밖**에 둔다. 따라서 3탭(설정집·회차 / 집필 / AI) 하단 내비가 보이지 않는 일반 전체 페이지이며 SiteHeader만 위에 남는다. 작품 화면에서 B/C 배지·안내줄·헤더 A를 누르면 이 페이지로 이동하고, 상단 `← {회차명}으로` 링크로 되돌아온다. 이유: A는 모든 작품을 가로지르는 전역 목록이라 한 작품의 탭 3개 구조에 속하지 않고, Phase 16에서 확정한 탭 3개 구조(`mobile-pane-state.ts`의 `StudioPaneId`)를 건드리지 않는다.
- 대안 M2: 4번째 탭 `검토` 추가 — 탭 3개 결정 변경이 필요해 비권장.
- 대안 M3: 현재 탭 위에 Sheet(전체 높이)로 인박스를 띄움 — 작품 안 맥락 유지는 되지만 URL·뒤로 가기·상세 깊이가 복잡해져 비권장.
- 가져오기 성공 후 모바일은 해당 회차 페이지로 이동하므로 초기 활성 탭이 `write`(집필)이고 삽입한 본문이 바로 보인다. 같은 회차에서 이미 열린 에디터가 있으면 기존 `notifyInsert()`로 집필 탭을 보장한다.

**인박스 레이아웃**
6. **데스크톱(`lg` ≥ 1024) `[목업 확인 대기]`:** 마스터-디테일 2열(`grid-cols-[minmax(320px,2fr)_3fr] gap-6`). 왼쪽 목록, 오른쪽 선택 항목 상세. 항목을 선택하지 않았으면 오른쪽에 빈 안내 `검토할 항목을 골라 주세요.`. 선택 행은 `aria-current="true"` + `bg-muted`. 상세 URL(`/studio/review/{id}`)로 직접 진입해도 같은 2열이 열린다.
7. **`< lg`:** 목록 페이지와 상세 페이지를 분리(1열). 목록 행 탭 → 상세로 push, 상세 상단에 `← 검토 목록`. 상세 하단에 고정 액션바(`sticky bottom-0 border-t bg-background p-4 pb-[calc(1rem+env(safe-area-inset-bottom,0px))]`): 모바일은 가로 2버튼 전폭(`거절` 1 : 기본 CTA 2).
8. 페이지 컨테이너는 Phase 12 관리 페이지 규약을 따른다: 목록 단독 `mx-auto max-w-2xl p-4 md:p-8`, 마스터-디테일은 `max-w-6xl`.
9. 행 구조: `<li>` > 전체가 하나의 `<Link>` (`min-h-11 rounded-md border p-4 flex flex-col gap-1`): 1줄 `[종류 태그] 제목(600, truncate)`, 2줄 caption `{클라이언트명} · {시각}`(및 이력은 상태 배지). 대기 중 첫 정렬은 도착 시각 최신순, 이력은 처리 시각 최신순.

**초안 가져오기 (D-P14-01, D-P14-03)**
10. `에디터로 가져오기` Server Action이 항목을 `accepted`로 전이하고(서버는 `chapters.content`를 쓰지 않음), 클라이언트가 회차 에디터를 열어 본문을 삽입한다. 상태 전이 실패 시 삽입하지 않는다(위 실패 문구).
11. 삽입 위치 `[목업 확인 대기]`: 에디터의 현재 커서 위치에 삽입(커서가 없으면 본문 끝). 기존 본문을 교체하지 않는다. 삽입은 에디터 undo 기록에 남아 `Ctrl/Cmd+Z`로 되돌릴 수 있다. 삽입 후 저장은 기존 에디터 저장 동작(자동/수동)이 하며 추가 확인 대화상자는 없다.
12. 가져오기에는 확인 대화상자를 두지 않는다(본문을 바꾸지 않는 비파괴 동작). 거절만 확인한다.
13. 같은 회차에 pending 초안이 여러 개(D-P14-02)이면 각각 독립 행이다. 한 초안을 가져와도 다른 초안은 대기로 남는다.

**수정안 검토 (D-P14-07, D-P14-08)**
14. diff는 서버가 **현재 원문 기준으로 계산**해 hunk 배열로 내려준다. 클라이언트는 hunk 선택 상태(수락/해제)만 가진다. 적용 시 서버가 원문 버전을 다시 확인하고 달라졌으면 재계산 결과와 함께 충돌 응답을 돌려준다(위 충돌 문구).
15. hunk 기본 선택은 모두 해제(명시적 수락 원칙). 한 번의 `모두 수락`으로 일괄 선택 가능. 선택은 페이지를 떠나면 저장하지 않는다.
16. 레이아웃: `md` 이상은 hunk마다 2열(`원문` | `수정안`), 미만은 세로 쌓기(원문 위, 수정안 아래). hunk 카드 헤더에 `변경 {i} / {N}`과 세그먼트 `건너뛰기 | 수락`. 각 패널은 변경 줄 앞뒤 문맥 2줄을 `text-muted-foreground`로 함께 보여준다. 줄 단위 diff, 줄 안 단어 하이라이트는 `[플래너 재량]`.
17. 수정안 신규 vs 수정은 인박스 행 태그(`새 문서` / `수정안`)와 상세 제목으로 구분한다. 신규 문서는 diff 없이 미리보기만 보여준다.
18. 잠긴 템플릿 문서(`is_locked`)는 제안 대상이 될 수 없으므로 서버가 제안 자체를 만들지 않는다. UI에는 잠금 문서에 대한 제안 상태가 존재하지 않는다(설정집 문서가 나중에 잠겨 수락 불가해진 경우만 위 `대상 문서 사용 불가`).

**정지 계정 (D-P14-15)**
19. 정지 계정은 인박스·상세를 읽기 전용으로 볼 수 있다(`checkWriteAccess` 결과가 거절이면 서버가 `readOnly`를 내려줌). 수락·거절·가져오기·충돌 재시도 버튼은 `disabled` + `aria-disabled` + 설명 caption(`aria-describedby`). 배너는 인박스와 상세 상단에 항상 보인다. 이력의 `다시 가져오기`도 같은 규칙으로 비활성이다. 탈퇴 계정은 접근 자체가 Phase 12 정책으로 차단되므로 화면 상태를 만들지 않는다.

**쌓임 제한 (D-P14-13)**
20. 상한 도달은 도구가 AI에게 오류를 돌려주는 것이 본질이고, 스튜디오에서는 인박스 상단에 작품별 안내 박스로만 알린다. 제안이 거부될 때 작가에게 별도 알림은 보내지 않는다.

**포커스·접근성**
21. 인박스 진입 시 `h1`에 `tabIndex={-1}` 포커스. 필터 탭 변경 후 포커스는 해당 탭에 유지, 결과 건수를 `role="status"`(`aria-live="polite"`)로 알린다(`{N}건`).
22. 상세 진입 시 `h1` 포커스. 데스크톱 마스터-디테일에서 행을 열면 상세 `h1`로 포커스를 옮긴다.
23. 거절 Dialog: 초기 포커스 `취소`, Esc로 닫기, 닫힐 때 트리거로 복귀(`ByokKeyCards` 패턴). 거절/적용 성공 후 포커스는 목록 페이지 상단 상태 영역(`tabIndex={-1}` `role="status"`)으로 이동한다. 데스크톱 2열이면 다음 대기 행이 있으면 그 행으로, 없으면 상태 영역으로.
24. 헤더 링크와 트리 배지는 `aria-label`에 건수를 포함. 배지 숫자는 시각적 전용(`aria-hidden`)이고 링크 이름이 건수를 말한다. 트리 배지 링크는 키보드 포커스 가능, 포커스 링 필수.
25. **diff 접근성:** 각 hunk는 `<section aria-labelledby="hunk-{i}-title">`. 패널은 `<div role="group" aria-label="원문">` / `aria-label="수정안"`. 삭제/추가 줄은 색에 더해 접두 `−` / `+`(`aria-hidden`)와 sr-only 텍스트 `삭제됨:` / `추가됨:`를 앞에 둔다. 문맥 줄은 sr-only `변경 없음:`. 세그먼트 `건너뛰기 | 수락`은 두 개의 `<button aria-pressed>`를 `role="group" aria-label="변경 {i} 적용 여부"`로 묶는다. 선택 요약은 `aria-live="polite"`. 키보드: Tab 순서는 hunk 순서대로 `건너뛰기 → 수락`, 방향키 전용 단축키는 만들지 않는다(스크린리더 충돌 방지). 단축키 없음.
26. 색 대비는 토큰(`text-foreground`/`text-muted-foreground` on `bg-card`/`bg-muted`) 기준 AA 이상. `bg-destructive/10`·`bg-primary/10` 위 본문색은 `text-foreground` 고정. 12px caption은 `text-muted-foreground`만 쓰고 틴트 배경 위에는 쓰지 않는다.
27. 모션: 장식 애니메이션 없음. 스켈레톤 펄스와 다이얼로그 전환은 `motion-reduce` 존중.
28. 클라이언트명은 공격자 입력이므로 행에서 `truncate`, 상세에서 최대 2줄 `line-clamp-2`, 항상 텍스트로만 렌더링한다. 동명 클라이언트 구분용으로 상세 메타에 호스트(`claude.ai`)를 caption으로 함께 표시한다. 연결이 해제된 클라이언트의 과거 항목도 저장된 클라이언트명으로 계속 표시하며 읽기 전용 제한은 없다.
29. 영구 보관(D-P14-14): 이력에는 삭제 UI·만료 안내·필터 기간이 없다. 항목 수가 많아지는 대비는 `더 보기` 페이지네이션뿐이다.
