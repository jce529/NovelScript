<decisions>
## Implementation Decisions (2026-10-02, 사용자 확정)

- **D-01 (BYOK 위치):** `/account`에는 제공자별 연결 상태·키 끝 4자리 **요약 + 링크**만 둔다. 등록/재검증/삭제는 기존 `/studio/settings/ai-providers`에서 한다.
- **D-02 (설정 문서 AI 범위):** 회차 AiPanel을 그대로 재사용한다(문서 제안 저장·본문 초안 삽입 포함). 현재 문서 내용이 컨텍스트이며, 초안 삽입 위치는 문서 텍스트 커서다. 과금 `ledger reason`은 `kb:<nodeId>`.
- **D-03 (파일 업로드 용도):** 세 방식을 제공한다 — (a) 선택한 카테고리 폴더에 설정 문서로 일괄 저장, (b) 이번 대화에만 첨부(저장 안 함, 최대 5개), (c) Jev 자동 분류 후 승인.
- **D-04 (Jev 분류 승인 UI):** 승인 창은 **기존 웹의 카테고리 트리를 그대로** 보여주고, Jev가 제안한 위치에 새 문서를 얹어 표시한다. 사용자는 트리 안에서 **드래그앤드롭으로 위치를 수정**하고, 수정이 끝난 트리를 승인하면 그 배치대로 실제 폴더에 저장한다. 승인 전에는 아무것도 저장하지 않는다. Jev가 확신하지 못한 문서는 "미분류"에 두고 사용자가 직접 배치해야 승인할 수 있다.
- **D-05 (서버 신뢰 경계):** 승인 시 서버는 `targetFolderId`를 소유자·작품·범위·카테고리·삭제 상태로 다시 검증하고, 폴더의 카테고리를 문서 카테고리로 쓴다(클라이언트가 보낸 카테고리를 믿지 않음). 폴더가 바뀌었으면 다른 폴더에 조용히 저장하지 않고 해당 파일을 실패로 보고한다.
- **D-06 (모바일):** 스튜디오 셸 한정. 작품 사이드바는 좁은 화면에서 접이식 "문서 목록"으로, AI 패널은 세로로 쌓이는 고정 높이(데스크탑만 sticky)로 바꾼다. 독자 화면·admin은 범위 밖.
- **D-07 (한도):** 업로드 일괄 저장 50개 / 파일당 100,000자, 대화 첨부 5개 / 파일당 30,000자, 확장자 `.md` `.markdown` `.txt`.

### Deferred

- Jev 분류 정확도의 오프라인 평가·그림자 운영 (Phase 15의 활성화 게이트와 동일 기준 적용 여부 결정 필요)
- 회차(chapter) 파일 일괄 가져오기
