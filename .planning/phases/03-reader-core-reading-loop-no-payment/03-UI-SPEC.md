# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope covered:** Discovery feed (grid, genre filter, sort/ranking-view toggle, trending badge), work detail page ([소개]/[회차] tabs, like button, 이어보기/읽기시작 CTA, report button), chapter viewer (vertical-scroll reading pane, top toolbar with TOC + settings, persistent bottom prev/next bar, locked-chapter inline message), font-size + theme (라이트/세피아/다크) controls, resume-reading surfaces (work detail button + cross-work "최근 읽은 작품" list), report flow (fixed-category form, available from both detail page and viewer). No payment/unlock UI — this phase only reads Phase 2's free/paid flag to decide lock-vs-open display.

**Design system continuity:** This phase extends, not re-themes, the `base-nova` system locked in `.planning/phases/02-studio-core-writer-loop-no-ai/02-UI-SPEC.md`. All chrome (buttons, forms, badges, dialogs) reuses Phase 2's tokens verbatim so Studio and the reader surface read as one product. The only new contract surface is the chapter-reading pane itself (adjustable font size, three-way theme), which is intentionally scoped to the viewer's content container only — exactly like Phase 2 scoped its editor-textarea line-height exception to editor surfaces only.

| Property | Value |

## Spacing Scale

Declared values (must be multiples of 4) — identical base scale to Phase 2, reused for consistency:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (badge internals, toolbar icon labels) |
| sm | 8px | Compact spacing between feed-card meta items (genre tag ↔ trending badge), form field internal padding |
| md | 16px | Feed grid gutter, default spacing between form fields, page content padding on narrow panels, TOC row indent |
| lg | 24px | Section padding (feed header, work-detail tab content, settings sheet padding), gap between major page regions |
| xl | 32px | Layout gaps between major regions on wide viewports (feed sidebar filters vs. grid, if used) |
| 2xl | 48px | Major section breaks (e.g. between work-detail header and tab content) |
| 3xl | 64px | Page-level top/bottom padding on empty-state screens |

Exceptions (reader-specific, mirrors Phase 2's precedent of naming component-height exceptions explicitly rather than forcing them onto the 8-pt token scale):

- **Viewer top toolbar height: 48px.** Fixed, always visible. Contains: back button (← to work detail), chapter title (center, truncated), TOC icon button, settings (⚙️) icon button (D-11).
- **Viewer bottom nav bar height: 56px**, matching Phase 2's "touch-safe" precedent (its chapter-list row was 44px for the same reason) — the bottom bar is the primary navigation control for continuous reading and must be comfortably tappable on mobile. Contains `이전화` (left, disabled/`ghost` styling when no previous chapter) — center chapter indicator (tap opens TOC sheet) — `다음화` (right, `default`/accent-filled when a next chapter exists, disabled/`ghost` when it's the last chapter). Individual buttons within the bar: minimum 44px tap height, matching the bar's own touch-safe rationale.
- **TOC panel row height: 44px** (touch-safe), matching Phase 2's chapter-list row convention exactly — readers tap TOC rows to jump chapters, same interaction class as Studio's drag-reorder rows.
- **Feed card cover image aspect ratio: 3:4** (portrait book-cover ratio) — not a spacing token but declared here since it drives the grid's row height; matches Naver Series/Ridibooks/Kakao Page cover convention (D-03).
- **Reading-pane horizontal max-width: 720px**, centered, with `lg` (24px) side padding below that width — long Korean prose at line-lengths beyond ~720px hurts readability; this is a reading-comfort constraint, not a token, and applies only inside the chapter content container.

## Typography

### Chrome typography (feed, detail page, forms, TOC, toasts) — reused verbatim from Phase 2

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 (regular) | 1.4 |
| Body | 14px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.3 |
| Display | 28px | 600 (semibold) | 1.2 |

**Role mapping for this phase's screens:**
- Label (12px): feed-card genre tag text, view/like counts, chapter-list row secondary text (word count/date), TOC row chapter number, form helper/error text.
- Body (14px): feed-card title (2-line clamp for long titles — Heading is reserved for page-level titles, not card titles, to avoid crowding a 3-column grid), synopsis excerpt (2-line clamp), tab labels, all button labels, TOC row chapter title, report form fields.
- Heading (20px): work detail page work title, "회차 목록" tab section header, "최근 읽은 작품" section title, empty-state sub-context where used.
- Display (28px): empty-state headings only ("아직 읽은 작품이 없어요", etc.) — same restriction as Phase 2.

### Reading-pane typography (chapter content — new this phase, viewer-scoped only)

| Property | Value |
|----------|-------|
| Adjustable sizes | 15 / 17 / 19 / 21 / 24px — 5-step button-group stepper (`가−` / numeric readout / `가+`), not a continuous slider |
| Default size | 19px (index 3 of 5) |
| Weight | 400 (regular) — no bold/semibold variant inside chapter prose |
| Line height | 1.9 — deliberately higher than the 1.7 used for Phase 2's plain-text editor textareas, since this is finished, read-only long-form prose (reading comfort), not active composition |
| Paragraph spacing | 1em (one blank-line equivalent) between paragraphs, matching standard Korean web-novel-viewer convention |

**Font-size control UI (D-11):** lives inside the settings sheet (bottom panel, opened via the toolbar's ⚙️ icon). Layout: label "글자 크기" · `가−` button (disabled at 15px) · numeric readout ("19px") · `가+` button (disabled at 24px). Selection persists only for the current session (no cross-device sync requirement in READ-03/READ-04 — 이어보기 persists chapter position only, not font/theme prefs).

## Color

Reuses Phase 2's token set and indigo accent override unmodified — no new global CSS variables, no re-theme.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (light `oklch(1 0 0)` / dark `oklch(0.145 0 0)`) | Feed page background, work-detail page background, viewer background in 라이트 theme |
| Secondary (30%) | `--secondary` / `--card` (light `oklch(0.97 0 0)` / dark `oklch(0.269 0 0)`) | Feed cards, work-detail tab content panel, TOC sheet background, settings sheet background, bottom nav bar background |
| Accent (10%) | `--primary` = indigo-600 (light) / indigo-500 (dark), unmodified from Phase 2 | Reserved EXCLUSIVELY for: (1) "이어보기"/"읽기 시작" primary CTA on work detail page; (2) "다음화" button in the viewer's bottom bar when active; (3) active/selected TOC row's left-border indicator + chapter-number tint; (4) liked (filled) heart icon on the like button; (5) the active font-size step and the active theme option (라이트/세피아/다크) in the settings sheet; (6) trending badge's flame/icon accent only (badge fill itself stays neutral — see below). Never applied to genre tags, lock badges, or any other decorative element. |
| Destructive | `--destructive` (light `oklch(0.577 0.245 27.325)` / dark `oklch(0.704 0.191 22.216)`), unmodified | Reserved EXCLUSIVELY for: the "신고하기" submit button in the report dialog + its confirm state. Flagging another user's content is the one serious/consequential write action in this phase (creates a queue entry Phase 7's admins act on), matching Phase 2's precedent of reserving destructive-red for the one deliberately-serious action per surface, not for every negative-sounding label. |

**Trending badge (D-01, Claude's discretion on visual treatment):** rendered as a neutral `Badge` (`variant="secondary"`, matching the genre tag's visual weight — NOT accent-filled, since a badge on every single card would violate the "accent = 10%, reserved for the few most important actions" rule if applied to N cards per page) with a small lucide `Flame` icon tinted accent-indigo, followed by an integer score 0–100 (e.g. "🔥 92"). Label copy is deliberately **not** "연독률" (that term implies the precise scroll-depth completion-rate stat this phase explicitly does not compute — see RESEARCH.md D-01 note) — use the neutral term "인기" (popularity) instead, with a `tooltip` on hover/long-press reading "조회수·좋아요·다음화 이동률을 종합한 점수예요" so readers understand it's a composite, not a literal completion percentage.

**Three-theme viewer (라이트/세피아/다크) — new this phase, scoped to the viewer's content container only, not global:**

Per RESEARCH.md's Don't-Hand-Roll guidance (no `next-themes` `ThemeProvider` is wired into `app/layout.tsx` yet, and D-11 scopes theming to "the viewer," not the whole site), theme switching is implemented as a local `useState`-driven class applied to the viewer's root container, not a site-wide provider:

| Theme | Trigger class (viewer-root-scoped) | Background | Text |
|-------|-------------------------------------|-----------|------|
| 라이트 (default) | none (uses existing `--background`/`--foreground`) | `oklch(1 0 0)` | `oklch(0.145 0 0)` |
| 세피아 | `.reader-theme-sepia` (new, scoped selector — add to `app/globals.css`, does not touch `:root`/`.dark`) | `oklch(0.94 0.02 85)` (warm cream) | `oklch(0.32 0.04 55)` (warm dark brown) | 
| 다크 | `.dark` (existing global class, applied to the viewer root element only — not `<html>`) | `oklch(0.145 0 0)` | `oklch(0.985 0 0)` |

**Why 세피아 (sepia), not just light/dark:** this is a deliberate borrow from Korean web-novel-platform convention — Ridibooks, Naver Series, and Munpia's viewers all ship a warm/eye-comfort "세피아" mode as a third default option alongside light and dark, distinct from a generic web app's binary light/dark toggle. Implementing only two themes would under-deliver against what readers of this genre expect from day one.

**Theme control UI:** three-way segmented control (not a dropdown — only 3 options, and immediate visual preview matters) inside the settings sheet, labeled 라이트/세피아/다크, active option accent-indigo per the Accent row above.

**Primary visual anchor:** On the discovery feed, the eye lands on the 3-column cover-image grid itself (covers are the dominant visual weight — accent color is deliberately minimal here per the trending-badge note above, so covers stay the focal point, matching Kakao Page/Naver Series feed conventions). On the work detail page, the eye lands on the accent-colored "이어보기"/"읽기 시작" CTA beneath the cover/title block. In the viewer, there is intentionally almost no accent color visible during reading itself (only the bottom bar's 다음화 button) — the reading pane should read as calm, low-chrome prose, consistent with D-13's rationale for dropping the bottom-sheet-popup pattern.

**Lock badge (D-06, paid chapter in TOC/chapter list):** uses `--muted-foreground` (not accent, not destructive) + a 12px lucide `Lock` icon next to the chapter title, matching Phase 2's locked-folder-indicator precedent exactly (same token, same icon-plus-label pattern, same "don't hide, show why" principle).
