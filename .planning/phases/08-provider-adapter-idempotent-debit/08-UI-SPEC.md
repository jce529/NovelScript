# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** 이 페이즈의 UI 변화는 AI 패널(`app/studio/[workId]/chapters/[chapterId]/ai-panel/AiPanel.tsx`) 안에 한정된다. 정상 생성 경로(말풍선, 초안 삽입, 문서 제안 저장, 다시 생성하기/거부하고 지우기, 토큰 소진 안내)는 **시각적으로 전혀 바뀌지 않는다**(PROV-01). 새로 추가되는 것은 (1) 패널 상태 알림 영역, (2) 안전 거절 안내 + 사유 접기, (3) 원인별 실패 문구 + 다시 시도, (4) 이미 처리된 요청 안내, (5) 전송 키 수명·중복 전송 차단, (6) 차감 후 잔액 갱신뿐이다.

**Source precedence.** CONTEXT.md D-05~D-10(잠긴 결정) → RESEARCH.md "UI Findings"(인라인 오류 영역이 실제로는 없고 toast뿐이라는 발견) → Phase 7 UI-SPEC의 토큰/관례 → 기존 AiPanel·ChatMessageBubble 클래스. 사용자에게 추가 질문 없이 작성함(모든 미결 항목은 CONTEXT의 Claude's Discretion 범위).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 아이콘–텍스트 간격, 제목–본문 사이(`gap-1`) |
| sm | 8px | 알림 내부 요소 간격(`gap-2`), 알림 액션 버튼 줄 간격 |
| md | 16px | — (패널 내 기존 사용 없음; 신규 요소에 쓰지 않음) |
| lg | 24px | 패널 섹션 간격(기존 `gap-6`, `p-6` 유지) |
| xl | 32px | 해당 없음 |
| 2xl | 48px | 해당 없음 |
| 3xl | 64px | 해당 없음 |

알림 컨테이너 padding: 12px(`p-3`) — 기존 ChatMessageBubble의 `wasCapped` 알림 박스(`rounded-lg bg-muted p-3`)와 동일하게 맞춘다.

Exceptions:
- 12px 알림 padding(위 기존 패턴 일치, 4의 배수).
- 아이콘 버튼(알림 닫기)은 32x32px(`size-8`) — 패널의 기존 프리셋 설정 아이콘 버튼과 동일. 패널 폭(384px) 제약상 44px 규칙의 예외로 기존 관례를 따른다. 사유 토글·다시 시도 버튼은 텍스트 버튼(`Button size="sm"`, 높이 28px 이상)으로 hit area는 텍스트 전체 폭.
- 알림 박스 border radius는 `rounded-lg`(기존 토큰).

## Typography

AI 패널은 이미 compact scale을 쓴다(`text-xl` 제목, `text-sm` 말풍선, `text-xs` 라벨/메타). 신규 요소는 이 스케일 안에서만 사용한다.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (알림 본문 문장) | 14px (`text-sm`) | 400 | 1.5 |
| Label (알림 제목, 버튼, 토글) | 14px (`text-sm`) | 500 (`font-medium`) | 1.5 |
| Meta (토큰 사용·잔액, 사유 설명, 사유 코드) | 12px (`text-xs`) | 400 | 1.5 |
| Heading (패널 제목 `AI 어시스턴트`, 기존 유지) | 20px (`text-xl`) | 600 (기존, 변경 금지) | 1.4 |

신규 요소의 weight는 400·500 두 가지뿐이다. 600은 기존 패널 제목에만 남는다. 숫자는 `tabular-nums`, 천 단위 구분은 `toLocaleString('ko-KR')`. 사유 코드(`SAFETY` 등)는 12px `font-mono`, 대문자 그대로. 긴 한국어 문장은 줄바꿈되며 `break-keep`을 적용한다.

## Color

기존 `app/globals.css` 시맨틱 토큰만 사용한다(라이트/다크 모두). 새 색상·팔레트 변경 없음.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `background` / `foreground` | 패널 표면, 알림 본문 텍스트 |
| Secondary (30%) | `muted` / `muted-foreground` / `border` / `secondary` | 모든 알림 박스 배경(`bg-muted`), 메타 텍스트, 사유 접기 영역 구분선, 기존 AI 말풍선(`bg-secondary`) |
| Accent (10%) | `primary` (indigo-600 / 다크 indigo-500) | 기존 `보내기` 버튼, 포커스 링만 |
| Destructive | `destructive` | 실패 알림(원인별 실패·차감 실패·잔액 부족·쓰기 제한)의 아이콘과 제목 텍스트만 |

Accent reserved for: `보내기` 버튼(기존), 키보드 포커스 링. 알림의 `다시 시도`·사유 토글은 accent를 쓰지 않는다(`variant="outline"` / `variant="ghost"`).

알림 변형별 색 규칙(색에만 의존하지 않고 아이콘+제목 문구로 구분):

| Variant | 박스 | 아이콘 | 제목 텍스트 |
|---------|------|--------|------------|
| `refusal` (안전 거절) | `bg-muted` + `border border-border` | `ShieldAlert`, `text-muted-foreground` | `text-foreground` |
| `processed` (이미 처리됨) | `bg-muted` + `border border-border` | `Info`, `text-muted-foreground` | `text-foreground` |
| `error` (실패, 차감 없음/차감 실패) | `bg-muted` + `border border-destructive/40` | `AlertCircle`, `text-destructive` | `text-destructive` |

안전 거절은 작가의 잘못을 뜻하는 "오류"가 아니므로 destructive 색을 쓰지 않는다. 다크 모드와 `bg-muted` 위 `text-destructive`의 대비를 렌더 상태에서 확인한다.

## Layout & Placement Contract

RESEARCH.md 발견: 현재 AiPanel에는 인라인 오류 영역이 없고 `toast.error`만 있다. D-07의 "기존 인라인 에러 자리"는 다음과 같이 **구체화**한다 — 새 말풍선 타입이 아니라, 패널 레이아웃의 고정 슬롯이다.

- **위치:** 채팅 로그(`chatLogRef` 스크롤 영역)와 입력 줄(`Input` + `보내기`) **사이**. 스크롤 영역 밖에 두어 로그 스크롤과 무관하게 항상 보인다. 패널의 기존 `gap-6` 흐름을 따른다.
- **슬롯은 한 번에 알림 1개.** 새 결과가 오면 교체된다. 비어 있을 때는 DOM에 렌더링하지 않는다(빈 여백 없음).
- **최대 높이:** 사유를 펼친 상태 포함 `max-h-48`(192px), 넘치면 알림 내부 `overflow-y-auto`. 채팅 로그(`flex-1 min-h-0`)가 줄어들 뿐 입력 줄은 밀려나지 않는다.
- **구조(위→아래):**
  1. 첫 줄: 아이콘(16px, `mt-0.5 shrink-0`) + 텍스트 블록(`flex-1`) + 닫기 `X` 아이콘 버튼(`size-8`, `aria-label="알림 닫기"`).
  2. 텍스트 블록: 제목(14px/500) → 본문(14px/400, 선택) → 메타 줄(12px/400 `text-muted-foreground`).
  3. 액션 줄(`flex gap-2 pt-2`): `다시 시도`(해당 변형만) / `거절 사유 보기`(거절만).
  4. 접기 영역(거절만, 펼쳤을 때): `border-t border-border pt-2`, 사유 코드 + 설명.
- **toast 정리:** `chatAction`의 `ok: false` 결과는 더 이상 `toast.error`로 표시하지 않고 이 슬롯에만 표시한다. 성공 경로의 `wasCapped` toast, 문서 제안 저장 toast는 변경하지 않는다(PROV-01 회귀 금지).
- **실행 중 표시:** 기존 `AI가 응답을 생성하고 있어요...` 문구 유지. 새 전송이 시작되면 슬롯의 기존 알림을 즉시 지운다.

## Interaction Contract

### 1. 전송 키 수명 (D-01, COST-01)

| 상황 | 키 | 페이로드 |
|------|----|---------|
| `보내기` / Enter로 새 전송 | 새 `crypto.randomUUID()` | 그 시점의 메시지·history·modelTier·genre·presetLevel·styleId·mentionedNodeIds·precedingText 스냅샷을 키와 함께 한 객체로 보관 |
| 실패 알림의 `다시 시도` | **같은 키** 재사용 | **같은 스냅샷** 재사용(그 사이 바뀐 모델·멘션·프리셋·본문은 반영하지 않음) |
| 성공 후 `다시 생성하기` | 새 키 | 새 스냅샷(새 생성 의도) |
| 실패 후 작가가 새 메시지 입력·전송 | 새 키 | 실패했던 user 턴은 history에서 제외 |

- **중복 전송 차단:** 전송 시작 시 첫 `await` 이전에 pending ref를 잠근다. 잠긴 동안 `보내기` 버튼 `disabled`, Input `disabled`, Enter 무시, `다시 생성하기`/`거부하고 지우기`/`다시 시도` 무시(기존 `isGenerating` 규칙 확장). 더블클릭·Enter 연타로 두 번째 `chatAction`이 절대 나가지 않는다.
- **네트워크 예외:** `chatAction` 자체가 throw(연결 끊김 등)하면 pending을 반드시 해제하고 `unavailable` 실패 알림 + `다시 시도`(같은 키·스냅샷)를 보여준다. 버튼이 영구 비활성으로 남으면 안 된다.
- 실패한 user 턴을 `다시 시도` 시 history에 **다시 추가하지 않는다**(말풍선 중복 금지).

### 2. 결과별 처리

| 결과 | 알림 변형 | user 말풍선 | 입력창 | 잔액 갱신 |
|------|----------|------------|--------|----------|
| 성공 | 없음(기존 그대로) | 유지 + AI 말풍선 추가 | 비움(기존) | 예 |
| 안전 거절 (D-05 A/B) | `refusal` | **제거**(거절된 요청이 다음 history로 재전송되지 않도록) | 거절된 원문을 입력창에 **복원**, 포커스 이동 | 예 |
| 이미 처리됨 (D-03) | `processed` | 제거 | 원문 복원 | 예 |
| 실패: rate_limited / unavailable / config (D-10) | `error` + `다시 시도` | 유지 | 비운 상태 유지 | 아니오(차감 없음) |
| 실패: 차감 실패(settlement, 원장 행 없음) | `error` + `다시 시도` | 유지 | 비운 상태 유지 | 아니오 |
| 실패: 잔액 부족(기존 사전 상한) | `error`, 다시 시도 없음 | 제거 | 원문 복원 | 아니오 |
| 실패: 쓰기 제한(Phase 7 `code`) | `error`, 다시 시도 없음 | 제거 | 원문 복원 | 아니오 |
| 실패: 로그인 필요·입력 검증 실패 | `error`, 다시 시도 없음 | 제거 | 원문 복원 | 아니오 |

- 안전 거절·이미 처리됨에는 `다시 시도`가 **없다** — 같은 키는 원장에 이미 기록돼 재전송해도 `processed`만 돌아온다. 작가는 복원된 입력을 고쳐 새 전송(새 키)한다.
- 거절 시 생성된 본문·초안·문서 제안·제공자 원문은 어떤 형태로도 렌더링하지 않는다(D-07, D-09). 말풍선을 만들지 않는다.
- **잔액 갱신:** 결과에 `remainingBalance`가 있고 차감이 기록된 경우(성공·거절·이미 처리됨) `router.refresh()`를 호출해 헤더 계정 패널(`site-header.tsx` → `account-panel.tsx`의 `보유 토큰`)을 서버 값으로 갱신한다. 반환값만으로는 헤더가 바뀌지 않는다(RESEARCH.md, Next.js Server Actions 가이드). `router.refresh()`는 AiPanel의 client state(`messages`, 입력, 알림)를 초기화하지 않아야 하며, 실행 중 새로 고침으로 에디터 본문이 사라지지 않는지 확인한다.

### 3. 안전 거절 사유 접기 (D-09)

- 트리거: `Button variant="ghost" size="sm"`, 라벨 접힘 `거절 사유 보기` / 펼침 `거절 사유 접기`, 우측 `ChevronDown`(펼침 시 `rotate-180`, `transition-transform`, `motion-reduce:transition-none`).
- 접근성: `aria-expanded`, `aria-controls="{notice-id}-reason"`. 기본 접힘. Enter/Space로 토글. 새 거절 결과가 오면 다시 접힘.
- 펼친 내용(이것만 표시): 한 줄에 사유 코드(`font-mono text-xs`) + 구분 `·` + 짧은 한국어 설명(`text-xs text-muted-foreground`). 입력 차단(A)이면 코드 앞에 `입력 차단` 라벨, 생성 중 차단(B)이면 `생성 중 차단` 라벨.
- 표시하지 않는 것: 잘린 생성 텍스트, `blockReasonMessage` 등 제공자 원문, safety rating 수치, 요청 ID.

사유 코드 → 설명 매핑(코드는 어댑터가 정규화한 allowlist 값만; 목록 밖 값은 `OTHER`로 표시):

| Code | 설명 |
|------|------|
| `SAFETY` | 유해할 수 있는 내용으로 판단됐어요. |
| `PROHIBITED_CONTENT` | 제공자가 금지한 유형의 내용으로 판단됐어요. |
| `BLOCKLIST` | 차단 목록에 있는 표현이 포함됐어요. |
| `SPII` | 민감한 개인정보가 포함된 것으로 판단됐어요. |
| `RECITATION` | 기존 저작물을 그대로 옮길 가능성이 있어 중단됐어요. |
| `IMAGE_SAFETY` / `IMAGE_PROHIBITED_CONTENT` / `IMAGE_RECITATION` | 제공자 이미지 정책에 따라 차단됐어요. |
| `OTHER` (그 외·알 수 없음) | 제공자 정책에 따라 차단됐어요. |

### 4. 접근성

- 슬롯 래퍼: `refusal`·`processed`는 `role="status"` `aria-live="polite"`, `error`는 `role="alert"`. 래퍼는 항상 마운트해 두고 내용만 교체해 스크린리더가 변경을 읽게 한다(빈 상태에서는 자식 없음).
- 거절·이미 처리됨·입력 복원 시 포커스를 입력창으로 이동. `error`+`다시 시도`에서는 포커스를 `다시 시도` 버튼으로 이동.
- 닫기 `X` 버튼: `aria-label="알림 닫기"`, 닫으면 포커스를 입력창으로. Escape는 쓰지 않는다(패널 내 드롭다운 Escape와 충돌 방지).
- 아이콘은 `aria-hidden`. 의미는 제목 문구가 전달한다.
- 모든 버튼에 기존 `focus-visible` 링 유지. 200% 확대에서 알림이 입력 줄을 가리지 않는다.

## Copywriting Contract

모든 문구는 해요체, 기존 패널 톤(`응답을 받지 못했어요` 등)과 일치. 토큰 단위는 **지갑 토큰**(차감액)이며 표기는 `N토큰`, 잔액 표기는 헤더와 같은 `보유 토큰 N`.

| Element | Copy |
|---------|------|
| Primary CTA | `보내기` (기존 유지) |
| Retry CTA (실패 알림) | `다시 시도` |
| Empty state heading | 해당 없음 — 채팅 빈 상태는 기존 문구 유지: `AI에게 말을 걸어보세요 — 본문을 이어 써달라고 하거나, 인물/장소 같은 설정을 같이 정해달라고 요청할 수 있어요.` |
| Empty state body | 해당 없음(알림 슬롯은 비어 있으면 렌더링하지 않음) |
| Error state | 아래 원인별 표 |
| Destructive confirmation | 해당 없음 — 이 페이즈에 파괴적 작업 없음(`거부하고 지우기`는 기존 동작, 확인 없음 유지) |

### 안전 거절 (`refusal`, D-08)

| Part | Copy |
|------|------|
| 제목 | `안전 정책에 따라 답할 수 없는 요청이에요` |
| 본문 | `표현을 바꿔 다시 시도해보세요.` |
| 메타 (차감 > 0) | `{n}토큰 사용 · 보유 토큰 {balance}` |
| 메타 (차감 = 0) | `차감된 토큰 없음 · 보유 토큰 {balance}` |
| 토글 | `거절 사유 보기` / `거절 사유 접기` |
| 사유 줄 | `입력 차단 · SAFETY · 유해할 수 있는 내용으로 판단됐어요.` (형식: `{입력 차단|생성 중 차단} · {CODE} · {설명}`) |

차감 0일 때 "0토큰 사용"이라고 쓰지 않는다 — 제공자 사용량 누락을 "실사용 0"으로 주장하지 않기 위함(RESEARCH.md).

| Part | Copy |
|------|------|
| 제목 | `이미 처리된 요청이에요` |
| 본문 | `같은 요청이 두 번 전송돼 한 번만 처리했어요. 이전 응답은 다시 불러올 수 없으니, 필요하면 새로 요청해주세요.` |
| 메타 | `보유 토큰 {balance}` |

### 실패 (`error`, 차감 없음 — D-10)

| Kind | 제목 | 액션 |
|------|------|------|
| `rate_limited` (429) | `지금 요청이 몰려 있어요. 1분 뒤 다시 시도해주세요.` | `다시 시도` |
| `unavailable` (5xx·타임아웃·네트워크·action throw) | `AI 응답을 받지 못했어요. 잠시 후 다시 시도해주세요.` | `다시 시도` |
| `config` (인증·모델 없음 등 4xx, 키 설정 누락) | `AI 기능에 문제가 생겼어요. 계속되면 문의해주세요.` | `다시 시도` |
| settlement 실패 (차감 기록 안 됨, 응답 비노출) | `토큰 차감에 실패해 응답을 표시하지 못했어요. 잠시 후 다시 시도해주세요.` | `다시 시도` |
| 잔액 부족 (기존) | `보유 토큰을 모두 사용해서 대화할 수 없어요.` | 없음 |
| 쓰기 제한 / 로그인 필요 (기존) | 서버가 준 기존 `error` 문구 그대로 | 없음 |
| 알 수 없음 (fallback) | `응답을 받지 못했어요. 잠시 후 다시 시도해주세요.` (기존 fallback) | `다시 시도` |

실패 알림에는 본문·메타 줄이 없다(제목 한 문장). HTTP 상태 코드, 제공자 이름, 에러 코드, 멱등 키는 작가에게 노출하지 않는다(D-11).
