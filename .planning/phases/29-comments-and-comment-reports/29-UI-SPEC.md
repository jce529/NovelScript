# Phase 29 - UI Design Contract

29-CONTEXT.md D-01~D-15와 `.planning/design/UI-DESIGN-BACKLOG.md`(독자 뷰어·댓글 신고·답글·댓글 권한 규칙·관리자 탭 구조·빈 상태), 목업 `AdminComments.dc.html`·`ViewerDesktop/Mobile.dc.html`을 근거로 한다. 승인은 인라인 계약 검토이며 렌더된 화면의 사용자 인수가 아니다.

## Spacing Scale

4px 아이콘/라벨 간격, 8px 촘촘한 간격, 16px 컨트롤 그룹·모바일 페이지 패딩, 24px 데스크톱 패딩·섹션 간격, 32px 큰 구분. 그 외 스케일 없음. 탭 대상은 최소 44x44px.

## Routes and Layout

### 독자 댓글 창 (뷰어 하단 바 `댓글 N`)
- 진입: 뷰어 하단 바 `이전 화 · 댓글 · 다음 화`의 `댓글 {개수}` 버튼. 데스크톱은 우측 패널(폭 400px, 본문 위에 겹침), 모바일(<768px)은 하단 시트(높이 약 80%, 끌어내려 닫기·`닫기` 버튼 병행). 열려도 본문 스크롤 위치·읽기 진행도는 유지된다.
- 구성(위→아래): 헤더(`댓글 {N}` · 정렬 `최신순`/`좋아요순` 토글 · 닫기) → 작성 영역(고정, 목록 위) → 댓글 목록.
- 댓글 행: 닉네임(작가 계정은 작가 이름 + `작가` 배지) · 상대 시각 · 본문 · 액션 줄 `좋아요 n` `답글` `신고`(본인 글은 `수정` `삭제`로 대체, 신고 숨김). 신고는 저빈도라 더보기 메뉴(`⋯`)에 두지 않고 텍스트 버튼으로 노출한다(터치 44px).
- 답글: 부모 댓글 아래 들여쓰기 1단(16px 좌측 여백 + `CornerDownRight` 아이콘). 부모당 답글 3개까지 보이고 나머지는 `답글 {n}개 더 보기` 펼침. 답글의 `답글` 버튼은 같은 스레드에 이어 쓰며 입력창 앞에 `@닉네임`을 자동 붙이지 않는다(멘션 없음).
- 자리표시: 본인 삭제 `삭제된 댓글`, 관리자 숨김 `관리자에 의해 숨겨진 댓글` (muted 텍스트, 액션 줄·좋아요 없음, 답글은 그대로 표시).
- 페이지네이션: 최초 20개, 하단 `댓글 더 보기` 버튼(무한 스크롤 아님, 포커스·스크롤 위치 유지).
- 반응형 375/390px: 가로 스크롤 없음, 액션 줄은 줄바꿈 허용.

### 작성 영역 상태
| 상태 | 표시 |
| --- | --- |
| 작성 가능 | 입력창 placeholder `댓글을 입력하세요`, 글자수 `0/800`, `댓글 등록` 버튼(빈 입력이면 비활성) |
| 비로그인 | 입력창 비활성 + `로그인하고 댓글을 남겨 보세요` + `로그인` 버튼(원래 회차로 복귀) |
| 본인 확인 없음 | 입력창 비활성 + `본인 확인 후 댓글을 쓸 수 있어요` + `본인 확인하기` 링크(계정 설정) |
| 댓글 정지 중 | 입력창 비활성 + `댓글 작성이 제한된 계정이에요 ({종료 일시 로컬 시간대} 까지)` / 영구면 `댓글 작성이 제한된 계정이에요` |
| 계정 정지 중 | `계정 이용이 제한되어 이 작업을 할 수 없어요. 기존 작품과 구매한 회차는 계속 볼 수 있어요.` (기존 `WRITE_SUSPENDED_MESSAGE`) |
| 작품 댓글 닫힘 | 입력창 없음 + `작가가 댓글을 닫았어요` (기존 댓글은 읽기 전용으로 계속 보이며 좋아요·신고·답글 숨김) |
| 스팸 제한 | `잠시 후 다시 시도해 주세요. 댓글은 1분에 5개까지 쓸 수 있어요.` (입력 유지) |

### 관리자 `댓글 신고` 탭 (`/admin`)
- 탭 구조는 Phase 7 개정을 따른다: `작품·회차 신고` · `댓글 신고` · `작가 재검토` · `제재 이력`. 탭·필터·페이지·선택 항목은 URL 상태이며 상세에서 돌아와도 유지.
- 큐: 상태 select(`미처리`(기본) · `처리 완료` · `기각` · `전체`), 오래된 순, 25건 단위 페이지. 행: 사유 배지 · 작성자 역할(독자/작가) · 신고 건수 · 상태 배지 · 본문 한 줄 요약 · `{닉네임} · {작품} {n}화 댓글` · 시각. 같은 댓글의 중복 신고는 한 행에 건수로 묶는다.
- 상세 `/admin/comments/[reportId]` (목록-상세 분할은 데스크톱 ≥1024px에서 2fr/1fr, 그 미만은 세로 스택): 대상 댓글 본문(일반 텍스트, 답글이면 `원 댓글: “…”`) · 신고 내역(사유별 건수; 신고자 닉네임은 비공개이며 화면에 없음) · 작성자 이력(`경고 n회 · 댓글 정지 n회 · 계정 정지 n회`) · 조치 폼. 뒤로가기는 탭·필터·페이지 유지.
- 조치 폼: 조치 선택 `댓글 숨김` / `경고` / `댓글 정지` / `계정 정지` / `기각`. `댓글 정지`는 기간 `1일` `7일` `30일` `영구`, `계정 정지`는 `7일` `30일` `영구`(프리셋 버튼; 자유 날짜 입력 없음). 기간 선택 시 종료 시각을 UTC·로컬로 프리뷰하고 전송값과 같아야 한다. 입력: `내부 사유`(최대 2000자)와 `작성자에게 전달되는 사유`(최대 500자) — 기각을 제외하고 필수. 안내문: `조치는 대상 계정에 알림으로 전달돼요. 작가 계정도 같은 기준으로 처리해요.`
- 확정은 확인 대화상자(대상·효과·사유 요약) 후 실행. pending 중 중복 제출 방지, 실패 시 입력·멱등 키 유지, 다른 관리자가 먼저 처리했으면 `다른 관리자가 이 항목을 변경했습니다. 새로고침 후 확인해 주세요.`
- 작가 계정 대상 `댓글 정지`/`계정 정지`도 동일하게 제공한다.

### 작가 스튜디오 최소 토글
- 작품 설정 위치(스튜디오 작품 홈의 설정 영역)에 `댓글 허용` 스위치 1개. 끄면 확인 문구 `독자가 이 작품에 댓글을 쓸 수 없게 돼요. 기존 댓글은 읽기 전용으로 남아요.` 설정 허브 화면은 Phase 32 소관이다.

## Interaction Contract

- 등록: 낙관적 삽입 없이 서버 성공 후 목록 맨 위(최신순) 또는 해당 스레드에 추가, 입력 비움. 실패 시 입력 유지 + 오류 메시지(aria-live). 등록 pending 중 버튼 비활성·스피너 자리 고정.
- 좋아요: 토글, 즉시 반영하되 서버 실패 시 롤백 + 토스트. 비로그인이면 로그인 안내.
- 수정: 본인 글에서 인라인 편집(입력창이 본문 자리를 대체) `수정 저장`/`수정 취소`, 수정된 댓글은 `(수정됨)` 표기.
- 삭제: 확인 대화상자 `이 댓글을 삭제할까요? 답글은 남아요.` → `삭제`(destructive).
- 신고: 대화상자에서 사유 4종 라디오(`욕설·비하·혐오` `스포일러` `광고·도배` `기타`) + `신고하기`. 이미 신고했으면 `이미 신고한 댓글이에요`. 본인 글에는 버튼 없음. 성공 토스트 `신고가 접수됐어요`.
- 키보드: 패널 열림 시 포커스 이동·Esc 닫기·닫힌 뒤 `댓글` 버튼으로 포커스 복귀, 대화상자는 기존 primitives의 포커스 트랩.
- 경고·댓글 정지·댓글 숨김 통지는 기존 AccountNotices(`운영 알림`)를 재사용하며 공개 사유만 표시(내부 사유·관리자·신고자 정보는 DTO·DOM에 없음).

페이지 텍스트는 실제 데이터·상태를 설명하며 디자인 설명이나 기능 홍보 문구를 두지 않는다.

**Focal point:** 댓글 창은 작성 영역 → 첫 댓글, 관리자 상세는 대상 댓글 본문과 조치 폼 제목. 굵기는 400·600 두 가지만 쓴다.

## Accessibility and States

이름 있는 아이콘 버튼 44x44 이상, 입력 라벨 명시, 보이는 포커스 링, 의미 있는 제목·목록(`ul`/`li`, 답글은 중첩 목록), 결과·오류 aria-live. 좋아요는 `aria-pressed`와 개수를 함께 낭독. 신고자 정보와 내부 사유는 비관리자에게 어떤 형태로도 노출되지 않는다. 로딩은 행 높이를 유지하는 스켈레톤. 200% 확대·375px에서 가로 스크롤 없음, 다크 모드 대비 확인.

## Registry Safety

기존 설치된 로컬 shadcn 컴포넌트만 사용한다. 서드파티 블록·레지스트리 설치·신규 디자인 의존성·네트워크 에셋 없음.
