# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope covered:** exactly four surfaces plus one ownership change.

1. **잠긴 회차 CTA (3 entry points)** — the viewer's locked body block (`components/reader/viewer-shell.tsx:73-81`, today's "결제 기능 준비중" placeholder), the viewer footer 다음화 button (`:85-103`), and the two locked-row lists (`components/reader/toc-sheet.tsx`, the 회차 tab of `app/works/[workId]/page.tsx`). All three gain the price in their label (D-02) and open the same modal (D-03).
2. **언락 확인 모달** — a new dialog (`components/reader/unlock-dialog.tsx`) that owns confirm (D-01), insufficient-balance (D-05/D-07), and in-flight states.
3. **언락 coordinator** — a page-scoped client provider (`components/reader/unlock-flow-provider.tsx`) that is the single owner of the modal, the `unlock=<chapterId>` resume marker, and the locally-unlocked chapter set that makes D-04's refresh-free render possible.
4. **비로그인 복귀 (D-12)** — the login-required toast now routes to `/login?next=…`; the login/callback/complete-email screens keep their current visual design and gain no new UI.
5. **Ownership change (Phase 5 amendment):** the top-up flow hook moves out of `AccountPanel` into a root-level `components/payment/payment-flow-provider.tsx`. See [Payment provider promotion](#payment-provider-promotion--phase-5-contract-amendment).

**Not covered (do not spec, do not build in this phase):** 대여(시간제 언락) UI, 구독제 UI (`REQUIREMENTS.md` PAY-04, v2), 결제내역/구매내역 페이지, 작가 정산/cash-out UI, any reader-facing display of the 90/10 split (D-11 — see [Forbidden UI](#forbidden-ui)). The 토큰 충전소 모달 itself is Phase 5's contract and is reused verbatim, not re-designed here.

**This document extends `.planning/phases/02-studio-core-writer-loop-no-ai/02-UI-SPEC.md`** (the base token contract, carried through Phase 3, 4, 04.1 and 5) **and `.planning/phases/05-real-payment-integration/05-UI-SPEC.md`** (number/currency formatting, dialog conventions, marker cleanup rules). Spacing/typography/color tokens are inherited verbatim unless explicitly marked **NEW** or **CHANGED**. This phase introduces **no new color values, no new font size, and no new component library.**

**Inherited exception — dialog titles render at 16px/500**, the `DialogTitle` primitive default, not Heading 20px. Every dialog already shipped in this repo does this (새 문서 만들기, 신고하기, QuickAdd, 토큰 충전소). Do not upsize the unlock dialog's title. No 5th font size is introduced by new prose.

**Weight reconciliation:** the declared inventory is 400 + 600. `font-medium` (500) appears **only** where a primitive or an already-shipped sibling already uses it: (1) `Button` labels, (2) `DialogTitle`, (3) the reused 보유 토큰 balance figure, (4) the 사용 토큰 price figure that mirrors it. Nothing else in this phase may add `font-medium`. In particular `10 토큰이 부족해요` is **400** — its prominence comes from position and color, not weight.

**🔴 NEW binding rule — the reader font-size context must not leak into unlock UI.** `viewer-shell.tsx` renders the prose container with `style={{ fontSize, lineHeight: 1.9 }}` where `fontSize` is the reader's 글자 크기 setting (D-11, Phase 3). The locked block lives inside that container today, and its `<p>` currently carries **no size class**, so it silently renders at 19–24px with 1.9 leading. Every text node in the locked block MUST declare its own size **and** leading class (`text-xl leading-[1.3]`, `text-sm leading-[1.5]`, `text-xs leading-[1.4]`). The locked block is chrome, not prose — the reader's font-size control must have zero effect on it. The same rule applies to anything rendered inside that container in future phases.

## Color

Inherited verbatim from Phase 2 — indigo accent (`--primary: var(--color-indigo-600)` light / `var(--color-indigo-500)` dark), `--destructive` unchanged, neutral surfaces unchanged. **This phase introduces no new color values and edits no token in `app/globals.css`.**

| Role | Value | Usage this phase |
|------|-------|------------------|
| Dominant (60%) | `--background` / `--popover` | Dialog surface (`bg-popover`), viewer page behind it, sheet surface |
| Secondary (30%) | `--secondary`, `--muted` | Modal summary block (`bg-secondary`, reused verbatim from `AccountPanel`), locked row hover (`hover:bg-muted`), disabled 이전화 button (already shipped) |
| Accent (10%) | `--primary` (indigo) | Reserved EXCLUSIVELY for, in this phase: (1) the modal's **primary CTA** (`{n} 토큰으로 열기` / `충전하기`); (2) the viewer locked-block **unlock CTA**; (3) the viewer footer **다음화** button (already indigo in shipped code — unchanged); (4) the TOC current-row left border (already shipped); (5) focus rings (`--ring`, same indigo). Nothing else. |
| Destructive | `--destructive` | **Not used in this phase.** Spending tokens is confirmed, not destructive: the confirm modal (D-01) *is* the safeguard, and per Phase 2's contract `--destructive` is reserved for delete actions only. A red 열기 button would misread as "이 회차를 삭제" at a glance. |

**Accent reserved for:** unlock/충전 primary CTA, viewer locked-block CTA, 다음화 button, TOC current-row indicator, focus rings. **Never** on: the `Lock` icon (always `text-muted-foreground`), the trailing price label, locked row backgrounds, the loading spinner (`text-muted-foreground`, it is passive status), or any badge.

**Primary visual anchor.** In the viewer locked state the eye lands on the centered `Lock` + `유료 회차예요` block in the empty prose area, then drops to the single indigo CTA beneath it — it is the only saturated element on an otherwise neutral page. In the modal the eye lands on the title, scans the two-row summary (low-contrast `bg-secondary`, deliberately read as context), and lands on the indigo CTA in the footer.

**🔴 NEW binding rule — the modal must inherit the reader theme.** `viewer-shell.tsx` applies `THEME_CLASS[theme]` (`''` / `reader-theme-sepia` / `dark`) to its own root `<div>`, but a base-ui `Dialog` portals to `document.body` — outside that div. A dialog opened from a dark-themed viewer would render in light chrome. Binding fix: the active theme class MUST be applied to the portalled `DialogContent` (or the portal container). This works because `app/globals.css` defines the theme variables on the `.dark` / `.reader-theme-sepia` **selector itself**, so `bg-popover`/`text-foreground` on that element resolve from it. Do not solve this by hard-coding colors, and do not skip it — a white modal flashing over a dark reader at 2am is the single most visible defect this phase can ship. `reader-theme-sepia` only overrides `--background`/`--foreground`, which is the intended (partial) effect and is acceptable.

## Surface 1 — 잠긴 회차 CTA (three entry points)

All three obey the same four rules:

1. **A locked target is a `<button type="button">`, never an `<a>`/`<Link>`.** Navigation must not fire before the modal (D-03). Free chapters and already-unlocked chapters keep their existing `Link`/`<a>`.
2. **The price is in the label** (D-02), not only in a tooltip or icon.
3. **The `Lock` icon is `text-muted-foreground` and `aria-hidden`** — the visible price text carries the meaning; the button gets an explicit `aria-label` (see [Accessibility](#accessibility)).
4. **No pre-emptive 잔액 부족 styling.** Rows never render a "부족" badge or a disabled state based on balance — balance is only checked in the modal, against a fresh server quote.

### 1a. Viewer locked body (`viewer-shell.tsx:73-81`)

Replaces the "결제 기능 준비중" placeholder verbatim.

```

유료 회차예요                          text-xl font-semibold leading-[1.3]
30 토큰으로 열면 바로 이어서 읽을 수 있어요.   text-sm leading-[1.5] text-muted-foreground
[ 30 토큰으로 열기 ]                    Button, primary, h-11, w-full max-w-[280px]
```

Block: `flex flex-col items-center gap-2 py-8 text-center` (`py-24` shrinks to `py-8` because the block now has a CTA and no longer needs to fill dead space).

**Success behaviour (D-04):** the block is replaced by the prose in place — `setState` only. No `router.refresh()`, no re-fetch, no navigation. The content string comes from the unlock action's response.

### 1b. Viewer footer 다음화 (`viewer-shell.tsx:85-103`)

### 1c. TOC sheet rows (`toc-sheet.tsx`) and 회차 tab rows (`work-chapter-list.tsx`)

Both render the identical row contract at `h-11`:


### 1d. 회차 tab 이어보기 / 읽기 시작 CTA

If the CTA's target chapter is locked, append the price: `읽기 시작 (30 토큰)` / `이어보기 · 3화부터 (30 토큰)`, and the element becomes a `<button>` that opens the modal. Otherwise unchanged.

### 1e. Author viewing their own paid chapter

The author sees their own paid chapter exactly as a free chapter: no `Lock`, no price, no modal, plain link, prose renders. **No "내 작품" badge, no "무료 열람" notice** — that is new UI outside this phase's scope, and the author already knows.

## State Machine

Exactly five states. No others may be introduced — in particular there is **no** `success` state and **no** `error` state (success closes the modal; errors are toasts).

| State | Renders | Dismissible? | Exits |
|-------|---------|--------------|-------|
| `closed` | nothing | — | locked CTA press (logged in) → `checking` · `unlock=<chapterId>` marker on mount + sufficient quote → `checking` |
| `checking` | header + spinner (`min-h-32`) | Yes (X, Esc, backdrop) | quote ok → `confirm` · quote short → `insufficient` · quote fails → `closed` + error toast |
| `confirm` | header + summary + helper + [취소][{n} 토큰으로 열기] | Yes | CTA → `unlocking` · 취소/dismiss → `closed` |
| `unlocking` | same layout, CTA spinner-disabled, X hidden | **No** | `unlocked`/`already_unlocked` → `closed` + content applied + toast · `insufficient_balance` → `insufficient` · `price_changed` → `confirm` (new price + notice) · other error → `closed` + error toast |
| `insufficient` | header + summary + shortfall + [취소][충전하기] | Yes | 충전하기 → `closed` here, 충전소 modal opens (marker written first) · 취소/dismiss → `closed` |

### Transitions in full

1. **Locked CTA press, logged out** → no modal. `toast.error('로그인이 필요해요.', { action: { label: '로그인하기', … } })` — the shipped reader precedent — with the action navigating to `/login?next=<current path+search, with unlock=<chapterId> merged>` (D-12).
2. **Locked CTA press, logged in** → `checking`. The provider requests a fresh quote (current price + current balance) from the server. Never trust list-render-time balance.
3. **`confirm` CTA press** → `unlocking`. The action is called with `chapterId` + `expectedPrice` (the number that was on screen).
4. **`unlocked` / `already_unlocked`** → identical handling: modal closes, `toast.success('{n}화를 열었어요.')` fires exactly once per dialog session, the provider records the chapter in its unlocked set and updates the balance from `remainingBalance`. Then:
   - target is the chapter currently open in the viewer → content swaps in place, **no navigation, no refresh** (D-04);
   - target is any other chapter (TOC, 회차 tab, 다음화) → `router.push` to that chapter's viewer **only now**, after the unlock succeeded (D-03).
5. **`price_changed`** → back to `confirm` with the new price and the notice line. No charge occurred.
6. **`insufficient_balance`** (either from the quote or from the action losing a race) → `insufficient` with the server's `shortfall`.
7. **충전하기 press** → merge `unlock=<chapterId>` into the current URL (`URL`/`URLSearchParams`, never string concatenation), close this modal, open Phase 5's 충전소 modal (D-05).
8. **Top-up credited** (Phase 5's polling resolves) → the unlock coordinator sees the surviving `unlock=` marker, re-quotes, and **re-opens `confirm`** (D-06). It **never** calls the unlock action automatically — D-01's confirmation is required every time. If the new balance is still short, it re-opens `insufficient` instead.
9. **Login return** → same as (8): marker present → re-quote → `confirm`. Logging in is not purchase approval.
10. **`not_available` / `not_paid`** → modal closes, `toast('지금은 볼 수 없는 회차예요.')` / for `not_paid` simply navigate (the chapter turned free — treat as an open link, no toast).
11. **Any other failure** → `closed` + `toast.error('회차를 열지 못했어요. 잠시 후 다시 시도해주세요.')`.

### Resume marker contract

| Marker | Owner | Meaning |
|--------|-------|---------|
| `unlock=<chapterId>` | `unlock-flow-provider.tsx` | "the user was trying to open this chapter" — a **UI hint only**, never a permission, never a price source |
| `topup=<orderId>` / `topupFail=1` | `payment-flow-provider.tsx` (Phase 5 contract) | untouched by this phase |

- **Merge, never concatenate.** Always `new URL(window.location.href)` + `searchParams.set('unlock', id)`.
- **Strip exactly one key.** On consuming `unlock`, delete only that key and `history.replaceState` the rest — the page may be carrying `topup`, tab state, or referral params (inherited Phase 5 rule; dropping the whole query string is a contract violation).
- **Detection is a mount `useEffect` reading `window.location.search`, not `useSearchParams()`** on the client (inherited Phase 5 rule — the provider is mounted broadly and would drag route trees out of prerendering). The **server** page `app/works/[workId]/page.tsx` may read `searchParams.unlock` normally; that is a different mechanism and is required by the next rule.
- **Tab restoration.** On `/works/[workId]`, when `searchParams.unlock` is present the server sets `Tabs defaultValue="chapters"`. Without this, D-03/D-06's "목록 화면으로 복귀" lands the user on 소개 and the promise is broken.
- Marker is cleared on: successful unlock, explicit 취소, or the coordinator deciding the chapter is already accessible.

### Payment provider promotion — Phase 5 contract amendment

**`05-UI-SPEC.md` mounts `use-topup-flow` inside `AccountPanel`. Phase 6 SUPERSEDES that ownership rule.** The viewer (`app/works/[workId]/chapters/[chapterId]/page.tsx`) renders `ViewerShell` only — there is no `SiteHeader`, therefore no `AccountPanel`, therefore nothing would consume `?topup=` or own the dialog after a Toss round-trip that started in the viewer. D-06 would be unimplementable.

Binding resolution:

- `components/payment/payment-flow-provider.tsx` is mounted once in `app/layout.tsx` and is the **single** owner of the top-up hook, the `TokenTopUpDialog`, the `?topup=`/`?topupFail=` markers, and the client-side balance.
- `AccountPanel` keeps its `+` button and its visual contract unchanged; it now calls `openTopUp()` from the provider.
- `UnlockDialog` never renders or imports `TokenTopUpDialog` — it asks the provider to open it.
- Everything else in Phase 5's UI contract (four states, static awaiting copy, no timeout, polling rules, forbidden UI) is unchanged. **Two hook instances racing for one marker remains forbidden** (Phase 5 Pitfall 7).

## Copywriting Contract

All strings are 해요체, matching the shipped product voice (`로그인이 필요해요.`, `신고가 접수되었어요.`, `결제가 취소되었어요`).

| Element | Copy |
|---------|------|
| **Primary CTA — unlock** | `{n} 토큰으로 열기` (e.g. `30 토큰으로 열기`) |
| Primary CTA — in flight | `여는 중이에요` |
| Primary CTA — insufficient state | `충전하기` |
| Secondary button | `취소` |
| Dialog title | `이 회차를 열까요?` |
| Dialog description | `{n}화 · {제목}` (e.g. `3화 · 폭풍전야`) |
| Dialog X — 접근성 이름 (`sr-only`) | `닫기` — never `Close` |
| Summary row — spend label | `사용 토큰` |
| Summary row — balance label | `보유 토큰` (reused verbatim) |
| Permanence helper (confirm) | `한 번 열면 언제든 다시 볼 수 있어요.` |
| Quote-loading (sr-only) | `잔액을 확인하고 있어요` |
| **Shortfall line (D-07, exact)** | `{shortfall} 토큰이 부족해요` — no trailing period, figure from the server |
| Insufficient helper | `충전을 마치면 이 회차를 이어서 열 수 있어요.` |
| Price-changed notice | `가격이 바뀌었어요. 새 가격을 확인해주세요.` |
| Viewer locked block — heading | `유료 회차예요` |
| Viewer locked block — body | `{n} 토큰으로 열면 바로 이어서 읽을 수 있어요.` |
| Viewer footer — locked next (D-02, exact pattern) | `다음화 (30 토큰)` |
| 회차 tab CTA — locked target | `읽기 시작 (30 토큰)` / `이어보기 · {n}화부터 (30 토큰)` |
| Locked row trailing label | `{n} 토큰` |
| Toast — unlock success (`toast.success()`) | `{n}화를 열었어요.` |
| Toast — 로그인 필요 (`toast.error()`, shipped precedent) | `로그인이 필요해요.` + action `로그인하기` → `/login?next=…` |
| **Error state** — unlock failed (`toast.error()`) | `회차를 열지 못했어요. 잠시 후 다시 시도해주세요.` |
| Error state — chapter withdrawn (`toast()`) | `지금은 볼 수 없는 회차예요.` |
| **Empty state** | **None new.** The two lists already ship their own empty states (`아직 공개된 회차가 없어요` on the 회차 tab; the TOC is only reachable when chapters exist). A 0-balance wallet is not an empty state — it is the `insufficient` path above. Do not build a zero-state. |
| **Destructive confirmation** | **None exists.** Nothing in this phase deletes anything. The D-01 confirm modal is a *spend* confirmation, deliberately rendered in accent, not `--destructive` (see [Color](#color)). |

Voice rules: 해요체 throughout; no `~하십시오`/`~합니다`; `열기`/`열었어요` for unlock (never `구매`, `결제`, `해제`, `언락` in user-facing copy — 결제 belongs to the 충전 flow, and this action spends already-purchased tokens); `토큰` never `코인`/`캐시`/`포인트`.

## Forbidden UI

The checker and auditor should treat any occurrence as a contract violation.

- **Any reader-facing mention of the 90/10 split, 작가 정산, 플랫폼 수수료, or the author's credit** (D-10/D-11 — the split is a ledger fact, not a reader-facing product feature, and the ratio is provisional).
- **Any 환불 / 구매 취소 / 소장 해제 affordance.** Unlocks are permanent and irreversible in v1 (D-08).
- **Any 대여 / 기간제 / 구독 option, price, or teaser** (D-09; PAY-04 is v2).
- **Any 구매내역 / 결제내역 link or page** (deferred).
- **Auto-opening the 충전소 modal** when the balance is short (D-05 requires an explicit 충전하기 press).
- **Auto-calling the unlock action** after login return or top-up return (D-01 requires re-confirmation both times).
- **`router.refresh()` or a re-fetch to reveal unlocked content** in the viewer (D-04 — the action already returned the content).
- **A "잔액 부족" badge, disabled state, or dimmed styling on list rows** based on the client's balance.
- Multi-select / 일괄 구매 ("전체 회차 구매") UI — not in scope.
- Any timer, countdown, attempt counter, or progress bar in `unlocking`.

## Accessibility

- **Locked rows and CTAs are real `<button type="button">`** with an explicit accessible name: `aria-label="{n}화 {제목}, 유료 회차, {price} 토큰"`. The `Lock` icon is `aria-hidden="true"` (the shipped `aria-label="유료 회차"` on the icon is removed — it now duplicates the button label).
- The viewer footer locked next button: `aria-label="다음화, 유료 회차, 30 토큰"`.
- **Dialog:** `DialogTitle` is the accessible name; `checking` body is `role="status"`; the shortfall line is `role="status" aria-live="polite"` so a screen reader announces the change when `confirm` → `insufficient` without a re-open.
- `unlocking` suppresses dismissal (see state table); the state is short-lived and always terminates.
- **Focus after a viewer unlock:** the locked block (which contained the focused CTA) is destroyed when the prose appears. The prose container MUST carry `tabIndex={-1}` and receive focus after the swap — otherwise focus falls to `<body>` and keyboard/screen-reader users lose their place. This is the one focus rule an implementer is most likely to miss.
- Focus after a list unlock: navigation occurs, so normal route focus handling applies.
- Both footer buttons are 44px tall and thumb-reachable; locked list rows stay at 44px.
- Selection/lock state is never signalled by color alone — the `Lock` icon plus the visible price text carry it.
- Motion: the spinner keeps animating under `prefers-reduced-motion` (essential status feedback); no new entrance animation beyond the dialog primitive's.
- The modal inherits the reader theme (see [Color](#color)) so contrast ratios hold in 다크/세피아.

## Handoff Notes for Planner / Executor

1. **The three entry points share one provider instance per page.** Do not let `ViewerShell`, `TocSheet`, and `WorkChapterList` each own a dialog — the resume marker would then have multiple consumers, the exact failure Phase 5 Pitfall 7 describes.
2. **Provider ownership is layered:** `PaymentFlowProvider` (root layout, owns `topup`) → `UnlockFlowProvider` (reader pages, owns `unlock`). The unlock provider asks the payment provider to open the 충전소; the reverse dependency is forbidden.
3. **Phase 5 must ship first** for transitions 7–8; everything else (locked CTAs, modal, unlock action, D-12 return path) is implementable and testable against a wallet balance without Phase 5, per `06-RESEARCH.md` A-9.
4. **`lib/unlocks/types.ts` must be client-safe** (no `server-only`, no `node:*`, no Supabase import) — the dialog imports the result union as a type and any shared price/label helper as a value. This is the Turbopack failure that broke the chapter editor in Phase 04 Plan 04-06.
5. **The reader font-size and theme leaks are real, shipped-code hazards**, not hypotheticals — see the two 🔴 rules in [Typography](#typography) and [Color](#color). Verify both in the live checkpoint with 글자 크기 최대 + 다크 테마.
6. **`getPublicChapter`/`listPublicChapters` gain a viewer-scoped `locked`** (D-13's `chapter_bodies` boundary); the UI contract above assumes `locked === false` for owned chapters and for the author. If the data layer keeps the global `price_tier !== null` meaning, every rule in Surface 1 breaks.
7. Per `CLAUDE.md`, a browsable mockup artifact of the unlock modal (all four visible states) and the viewer locked block must accompany this spec before the phase's UI deliverable is considered complete.
