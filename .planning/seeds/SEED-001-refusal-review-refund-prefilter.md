# SEED-001: 안전 거절 검토·환불 루프 + 사전 필터 (자체 LLM 데이터셋 기반)

## Why This Matters

현재(Phase 8 D-06) 제공자 안전 거절은 실사용량대로 차감되고 보상이 없다. 소설 플랫폼 특성상
폭력·범죄·성인 묘사 등 정상 창작이 과잉 거절되는 경우가 많아 작가 입장에서 억울한 차감이 생긴다.

- 사전 필터로 명백히 막을 입력은 제공자 호출 전에 차단 → 비용·차감 없음
- 필터를 통과했지만 거절된 입력은 검토 후 환불 → 작가 신뢰 확보
- 검토 결과(유해 / 과잉 거절) 라벨이 붙은 데이터가 쌓임 → 필터 개선 + 장기적으로 자체 LLM(파인튜닝·안전 분류기) 학습 자산

## Design (합의된 변형안)

| 상황 | 처리 |
|---|---|
| 사전 필터에 걸림 | 제공자 호출 없이 차단, 차감 없음 |
| 필터 통과 후 제공자 구조화 거절(D-05 A·B) | D-06대로 차감 후 검토 대기열 등록 (즉시 보상 없음) |
| 관리자 판정: 진짜 유해 | 필터에 추가, 보상은 차감액 환불 수준이 상한 |
| 관리자 판정: 과잉 거절(정상 창작) | 필터 미추가, 환불, 프롬프트·제공자 설정 개선 자료로 사용 |

- 사전 필터는 문자열 블랙리스트가 아닌 임베딩 유사도 / 경량 분류기. 같은 방식으로 near-duplicate 중복 보상 방지.
- 일일/계정당 보상 상한, 신규 계정 제외.
- 모델이 정상 완료하며 문장으로 거절하는 경우(D-05 C)는 범위 밖임을 명시.

**기각된 원안:** "필터를 우회해 거절된 입력에 바운티 지급" — 유해 입력 제작에 인센티브를 주고,
보상 > 차감액이면 크레딧 파밍 루프가 생기며, 과잉 거절까지 필터에 들어가 정상 작가를 막게 되므로 기각.
