# NovelScript 이용약관 책임구조 및 저작권 리스크 대응안

작성일: 2026-09-26

---

## 1. 배경 — 저작권 리스크 검증 요약

- **시장공백론 재검토**: "AI 소설 창작 플랫폼"이라는 시장 자체는 비어있지 않음(노벨피아, NovelAI 등 기존 플레이어 존재). 실제 공백은 **신뢰·수익화 체계의 부재**에 있음 → NovelScript의 차별화 지점은 "책임있는 AI 플랫폼" 포지셔닝.
- **"상업 API만 쓰면 회피된다"는 가정은 기각**: 학습 단계의 저작권 리스크는 회피되지 않고 산출(생성물) 단계로 이동함. 일반 상용 API(Gemini 등)는 생성물에 대한 책임을 이용자에게 전가하는 구조.
- **"프롬프트+검수+3-Strike로 충분하다"는 가정도 과장됨**: 비문언적 유사성(표절이지만 문장이 다른 경우)은 사전 탐지가 사실상 불가능. 사후 조치(신고 기반)만 현실적으로 가능.

### API 티어 전환 계획
| 단계 | 내용 |
|---|---|
| Phase 1 (MVP) | Google Gemini API(일반 티어) |
| Phase 2 (유료화) | Vertex AI Indemnified Services 전환 검토 (면책 플랜) |
| Phase 3 (스케일) | 멀티모델 라우팅 (OpenAI Business, Claude Enterprise 등) |

### BYOK(Bring Your Own Key) 화이트리스트
- 1급: 면책계약 체결된 API만
- 2급: 투명성 요건 충족 API
- 3급: 공개 API (제한적 허용)

## 2. 이용약관 책임구조 — 법적 근거

### 핵심 논리: "AI 생성이라도 최종 게시는 작가 행위"

**근거:**
- 저작권법 제102~104조 (OSP 책임 제한) — OSP가 침해를 실제로 인식하지 못했고, 인식 즉시 필요한 조치(삭제·차단)를 취했다면 책임 감경·면제.
- 정보통신망법 제44조의2 (임시조치) — 권리침해 주장 시 30일 임시조치(비공개) 후 재게시 여부 판단.
- 저작권법상 침해 성립 시점은 "복제·공중송신" 행위 — 이를 실행하는 주체는 게시 버튼을 누른 이용자. AI는 초안 생성 도구일 뿐.

**한계 (반드시 인지할 리스크):**
- 약관의 규제에 관한 법률 제7조 — 사업자의 **고의 또는 중과실**로 인한 책임을 미리 면제하는 조항은 무효. 포괄 면책 조항은 무효 처리 가능.
  → 면책 조건은 항상 "회사가 침해 사실을 알지 못했고, 안 이후 신속히 조치했을 때"로 한정해야 함.
- AI 관여도가 높을수록(프롬프트만 주고 전량 AI 생성 후 무수정 게시) "이용자의 실질적 창작·검수 행위"를 부정당할 가능성 → 게시 전 검수를 강제하는 UX가 이 법적 논리를 뒷받침하는 데 필수.

### 이용약관 조항 구조 (5개 조항)

1. **AI 도구 이용 및 결과물 책임 귀속**
   "AI는 창작을 보조하는 도구이며, 최종 검토·수정·게시 행위는 이용자 본인이 수행한다. 게시된 콘텐츠에 대한 저작권법상 책임은 게시한 이용자에게 귀속된다."

2. **표시-삭제 절차 (Notice-and-Takedown)**
   신고 접수 → 임시조치(비공개) → 이의제기 기간 → 재게시/삭제 결정.

3. **위반 시 계정 제재 (3-Strike)**
   경고 → 일시정지 → 영구정지 단계.

4. **손해배상 및 구상권**
   "회사가 이용자의 콘텐츠로 인해 제3자에게 손해배상을 한 경우, 귀책사유가 있는 이용자에게 그 금액의 상환을 청구할 수 있다."
   단, 회사의 고의·중과실이 있는 부분은 구상 범위에서 제외 (약관법 위반 소지 회피).

5. **회사의 면책 범위와 한계**
   포괄 면책이 아니라 "회사가 인식하지 못한 침해에 대해서는"이라는 조건부 문구로 한정.

## 3. 구상권 행사 범위 — a/b 병기 확정안

| 유형 | 판단 기준 | 구상권 행사 |
|---|---|---|
| (a) 고의적 침해 | 원작 그대로 붙여넣기, 타인 저작물 도용 등 명백한 고의 | 100% 행사, 예외 없음 |
| (b) AI 생성물 무검수 게시 | 게시 직전 검수 확인 절차를 거쳤음에도 미검토 게시 | 과실로 보고 구상권 행사 |

**전제 조건 (b)**: 회사는 게시 직전 시점에 "AI 생성 내용을 검토했는지, 타인 저작물과 유사성이 없는지"를 명시적으로 고지·확인받아야 함. 이 확인이 없었다면 회사도 주의의무를 다하지 않은 것으로 볼 여지가 있어 구상 범위가 축소됨.

### 제품 요구사항 (UI-SPEC 반영 필요)
- AI 생성 → 편집 화면에서 즉시 게시 불가.
- "게시" 버튼 클릭 시 별도 확인 모달: "AI가 생성한 내용을 검토하셨습니까? 타인의 저작물과 유사한 내용이 포함되지 않았는지 확인해주세요" + 체크박스 동의.
- 동의 로그(타임스�탬프, 동의 여부)를 서버에 기록 — 추후 구상권 행사 시 증거자료로 활용.
- **이용약관과 UI-SPEC에 동일한 문구로 반영해야 정합성 확보.**

## 4. 자사 LLM 학습을 위한 데이터 이용권 — "파운데이션 작가 프로그램"

### 설계 배경
서비스 운영(호스팅·전시·유통) 라이선스와 "AI 학습에 사용" 목적은 별개의 이용행위. 기존 UGC 약관의 포괄 라이선스 조항에 학습 목적을 끼워넣으면 약관법 제3조(중요 내용 설명의무) 위반 소지. → **별도 특약 + 옵트인 방식**으로 분리.

옵트아웃(기본 동의) 대신 옵트인을 채택하는 이유: "책임있는 AI 플랫폼" 포지셔닝과의 정합성. 몰래 기본 동의시켜 자사 AI 학습에 쓰는 구조가 알려지면 차별화 포지셔닝 자체가 훼손됨.

### 자격 요건 (성과 게이팅) — 4가지 기준 동시 충족

| 기준 | 제안 임계치 | 목적 |
|---|---|---|
| 완결 여부 | 완결작 또는 최소 30화 이상 연재 지속 | 문체 일관성 있는 완성된 데이터 확보 |
| 인기 검증 | 누적 조회수 1만 이상 또는 구독 500 이상 | 독자 검증을 거친 콘텐츠만 선별 |
| 품질 검증 | 평점 4.0/5.0 이상 (최소 평가수 확보) | 저품질 초안 배제 |
| 침해 이력 없음 | 3-Strike 무이력 | 학습 데이터 자체의 저작권 오염 방지 |

네 조건 동시 충족 시에만 프로그램 자격 부여 → "아무 글이나 긁어가지 않는다, 검증된 우수작만 동의 하에 선별적으로 활용한다"는 메시지 확립. 사업계획서 차별성 섹션에 활용 가능.

### 동의 시 혜택 — 양방향 토큰 환율 우대

- **원화 → 토큰 충전**: 기본 환율 대비 우대율(+α%) 적용, 동일 결제금액으로 더 많은 토큰 지급.
- **토큰 → 원화 환전**: 기본 수수료/환율 대비 우대, 정산 시 더 유리한 비율 적용.
- 우대율(α)은 재무모델링 후 확정 — 예상 자격 충족 작가 비율 × 우대폭을 사업계획서 비용 항목(마진 축소분)으로 반영 필요.

### 별도 특약으로 분리하는 이유
- 메인 이용약관에 포함 시 프로그램 조건·우대율 변경마다 전체 약관 개정 동의 재취득 필요.
- 별도 특약(부속 프로그램 약관)으로 두면 독립적으로 개정·운영 가능.
- "필수 동의 조항"과 "선택적 유상 프로그램"은 법적 성격이 다르므로 분리가 약관법상 적절.

### 필수 명시 단서 조항
1. **동의 철회의 효력 범위**: 철회 시 이후 신규 학습분부터 제외되며, 이미 학습에 반영된 모델 파라미터에서 개별 삭제는 기술적으로 불가능함을 명시. (탈퇴 후 "왜 내 문체가 남아있냐" 분쟁 방지)
2. **혜택의 성격 규정**: "데이터 제공의 대가"가 아닌 "우수 창작 활동에 대한 우대 혜택"으로 문구화 — 대가성이 강하면 용역·고용 관계로 오인될 소지 방지.
3. **자격 기준 공개**: 심사 기준을 수치로 투명 공개 — "자의적 선별" 논란 방지.
4. **2차적저작물 리스크 관리**: 특정 작가 스타일을 직접 지목해 재현하는 기능은 만들지 않거나, 만들 경우 별도 라이선스·수익배분 계약 필요.
5. **TDM 면책조항 미비 고지**: 한국은 AI 학습에 대한 저작권법상 명시적 면책조항이 아직 입법되지 않음(2023년 개정안 계류 중). "법이 허용해서"가 아니라 "약관상 개별 동의가 유일한 법적 근거"임을 사업계획서에도 명시.
