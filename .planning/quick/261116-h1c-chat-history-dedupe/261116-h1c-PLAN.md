# 01 — 반영된 초안 중복 제거 · 서버 길이 상한

## 배경

2026-11-16 AI 호출 비용 점검에서 나온 개선안 1번이다.

- `chatHistoryTurnContent`(`lib/ai/prompt.ts`)는 AI 턴마다 `[REPLY]` 텍스트에 초안·설정 문서 전문을 붙인다. 작가가 초안을 본문에 넣으면 같은 글이 `precedingText`와 대화 기록에 두 번 실린다.
- `chatActionSchema`에는 `precedingText`·`chatHistory` 항목이 없다. 서버는 `input.precedingText`·`input.chatHistory`를 검증 없이 `chat()`에 넘긴다.
- 서비스 키 차감은 `Math.min(잔액, 계산액)`이다. 입력이 매우 길고 잔액이 적으면 실제 벤더 비용이 차감액보다 커진다. 서버 상한이 필요한 이유다.

## 2026-11-16 수정 — 기억 손실 우려 반영

처음 안은 "최근 20턴만 전송, 최근 6턴보다 오래된 초안·문서 본문은 생략"이었다. 이 방식은 세션 초반에 작가가 말로 정한 지시가 21턴째부터 사라진다. 그래서 다음과 같이 바꿨다.

- 이 plan(01)은 **정보를 잃지 않는 것만** 한다: 본문에 이미 있는 초안의 중복 제거와 서버 상한.
- 오래된 턴은 잘라내지 않고 **요약으로 접는다** — plan 02(`261116-h1c-02-PLAN.md`)에서 다룬다.
- 매 턴 조금씩 바뀌는 슬라이딩 축약은 쓰지 않는다. 기록 앞부분이 턴마다 바뀌면 제공자의 프롬프트 캐시(개선안 2번)가 깨진다.

## 결정

| 항목 | 값 | 근거 |
|---|---|---|
| 반영 판정 | `precedingText`가 초안(앞뒤 공백 제거)을 부분 문자열로 포함 | 별도 플래그 없이 순수 함수로 판정. 넣은 뒤 고친 초안은 자동으로 전문 유지 |
| 서버 턴 상한 | 40턴 | plan 02 적용 후 정상 사용은 16턴을 넘지 않는다 |
| 서버 턴당 길이 상한 | 40,000자 | 설정 문서 제안 상한 20,000자 + 여유 |
| 서버 본문 길이 상한 | 실행 시 확인 | 회차 본문·설정 문서의 기존 저장 상한을 찾아 그 값 이상으로 둔다. 없으면 200,000자 |
| 40턴 초과 시(plan 02 적용 전) | 클라이언트가 가장 오래된 턴부터 뺀다 | plan 02가 들어가면 이 경로는 요약 실패 시의 마지막 안전장치로만 남는다 |

## Task 1 — 축약 함수 (TDD)

`lib/ai/prompt.ts`에 추가한다. 서버 전용 코드를 import하지 않는다.

```ts
export const CHAT_HISTORY_SERVER_MAX_TURNS = 40;
export const CHAT_TURN_MAX_CHARS = 40_000;

export function compactChatHistory(
  messages: { role: 'user' | 'assistant'; text: string; draft?: string | null; proposal?: DocumentProposal | null }[],
  precedingText: string,
): ChatTurn[]
```

규칙:

1. 작가 턴은 `text` 그대로.
2. AI 턴의 초안: 앞뒤 공백을 뺀 초안이 비어 있지 않고 `precedingText`에 포함되면 `(제시한 본문 초안 — 본문에 반영됨)`, 아니면 지금과 같은 전문 형식.
3. AI 턴의 설정 문서 제안: 지금과 같은 전문 형식.
4. 결과가 `CHAT_HISTORY_SERVER_MAX_TURNS`를 넘으면 뒤에서 그만큼만 남긴다.
5. `chatHistoryTurnContent`는 그대로 둔다(다른 호출부·기존 테스트 보존). 전문 형식은 이 함수를 재사용한다.

테스트(`tests/ai/prompt.test.ts`): 반영된 초안 축약, 고친 초안 전문 유지, 설정 문서 제안 전문 유지, 41턴 입력에서 40턴 반환과 마지막 항목 보존, 같은 입력의 결과 동일, 빈 초안·`null` 처리.

## Task 2 — 패널 연결

`AiPanel.tsx`:

- 전송부(`chatHistory: base.map(...)`)를 `compactChatHistory(base, p.precedingText)`로 바꾼다. `p.precedingText`는 전송 시점 스냅샷이므로 재시도 때 결과가 같다.
- 비용 추정이 대화 기록을 입력에 넣고 있으면 같은 함수로 맞춘다. 넣고 있지 않으면 건드리지 않고 SUMMARY에 적는다.
- 화면에 보이는 말풍선(`messages` 상태)은 바꾸지 않는다. 축약은 전송 내용에만 적용된다.
- 재생성(`handleRegenerate`)·설정 문서 편집기 경로(`nodeId`)도 같은 전송부를 쓰는지 확인하고, 따로 조립하는 곳이 있으면 함께 바꾼다.

## Task 3 — 서버 검증 (TDD)

`actions.ts`의 `chatActionSchema`에 추가한다.

```ts
precedingText: z.string().max(PRECEDING_TEXT_MAX_CHARS),
chatHistory: z.array(z.object({ role: z.enum(['user', 'assistant']), content: z.string().max(CHAT_TURN_MAX_CHARS) })).min(1).max(CHAT_HISTORY_SERVER_MAX_TURNS),
```

- `chat()`에는 원시 `input`이 아닌 파싱된 값을 넘긴다.
- 마지막 턴이 `user`가 아니면 거부한다.
- 검증 실패 응답은 이 액션이 지금 스키마 실패에 쓰는 형태를 그대로 따른다. 새 오류 형태를 만들지 않는다.
- 테스트(`tests/ai/chat-action.test.ts`): 41턴·턴 길이 초과·본문 길이 초과·잘못된 role·마지막 턴이 assistant인 경우에 제공자 mock과 지갑 조회가 호출되지 않는다.

`document-plan.ts`·`document-regenerate.ts`가 같은 액션을 거치지 않고 기록을 받는 경로가 있으면 같은 상한을 적용한다.
