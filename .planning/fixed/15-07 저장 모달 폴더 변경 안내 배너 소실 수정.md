# 15-07: 저장 위치 변경 안내 배너 소실 수정

## 증상

모달에서 폴더를 고른 뒤 다른 탭에서 그 폴더를 삭제하고 저장하면, 저장은 막히고 폴더 선택이 최상위로 재충전되지만 "저장 위치가 변경되었어요. 다시 선택해주세요." 배너가 잠깐 보였다가 사라졌다. 사용자는 폴더가 왜 바뀌었는지 알 수 없었다(Phase 15 15-09 Task 2 UAT에서 발견, BUG-08).

## 원인

`doSave`가 `folder_changed`에서 배너를 띄우고 폴더 목록·선택값을 갱신하면, Base UI `Select`가 프로그램으로 바뀐 값에 대해 같은 값으로 `onValueChange`를 한 번 더 호출한다(`reason: "none"`, 새 값 == 현재 `selectedFolderId`). 폴더 `Select`의 핸들러는 값이 바뀌었는지 확인하지 않고 `setBanner(null)`을 호출해 방금 띄운 배너를 지웠다. Codex `gpt-6-luna` 리서치로 Base UI 소스의 호출 경로를 정리하고, 임시 로그로 호출 스택·`reason`을 추적해 확정했다(사용자 선택은 `reason: "item-press"`).

## 수정

- `lib/kb/select-change.ts` `isSelectionChange(next, current)` — 값이 달라졌을 때만 선택 변경으로 본다.
- 폴더·템플릿 `Select`의 `onValueChange` 첫머리에서 같은 값이면 반환한다(템플릿은 같은 패턴이라 함께 방어).
- `eventDetails.reason` 기반 구분은 쓰지 않았다(닫힌 상태 타이핑 탐색도 `none`이면서 값이 바뀜).

## 검증

- `select-change`·`save-document-plan-modal` 테스트 7건, `tsc --noEmit`, eslint 통과.
- 브라우저: 같은 race를 재현해 배너가 폴더 재설정 이후에도 유지됨을 DOM 변화 기록으로 확인했고, 사용자가 폴더를 직접 `조연`으로 바꾸면 배너가 지워짐을 확인했다.
- 한계: 모달의 `Select`·`useEffect` 상호작용은 기존 SSR 목 테스트로 재현할 수 없어 자동 테스트는 순수 함수까지만 있다.
