# 07-05: 신고 테스트 잔여물 정리

## 증상

`tests/reader/reports.test.ts`가 공유 테스트 DB에 "테스트 작품" 대상 신고와 작품·KB 행을 남겨 관리자 신고 큐에 가짜 항목(열린 신고 102건)이 쌓였고 UAT와 운영 확인을 방해했다.

## 원인

Phase 3 테스트는 신고 큐 소비자가 없던 시절에 작성돼 신고·작품 행을 정리하지 않았다. 계정 삭제는 `deleteUser` 반환 `error`를 읽지 않아(`.catch`로는 잡히지 않음) 실패해도 조용히 지나갔다. 신고가 `profiles`를 참조해(FK) 계정도 삭제되지 않았다.

## 수정

- `scripts/lib/report-fixture-cleanup.mjs`: 명시한 신고·작품·계정 ID만 대상으로 신고 → KB 노드 → 작품 순으로 한 트랜잭션에서 삭제하고 잔여 건수를 확인. 관리자 감사 연결·제재 이력·비테스트 계정·존재하지 않는 신고 ID·ID 미지정이면 거부.
- `reports.test.ts`는 만든 작품·신고 ID를 추적해 `afterAll`에서 위 정리를 수행하고 `deleteTestUserStrict`로 실패를 전파. `tests/helpers/db.ts`에 오류를 던지는 `deleteTestUserStrict`를 추가(기존 `deleteTestUser`는 원장 행이 남는 다른 테스트가 많아 best-effort 유지 — Phase 9 06-01 계열 이슈).
- 과거 잔여물용 `scripts/cleanup-reader-report-fixtures.mjs`(기본 dry-run, `--execute --expect-db` 필요).
- **과거 잔여물 실삭제(2026-10-02, 사용자 승인):** 테스트 계정 6,368개와 종속 행(작품 4,192, 신고 110, KB 노드 53,567, 회차 3,553, 원장 7,221 등)을 FK 그래프 기반 200계정 단위 트랜잭션 32배치로 삭제. 관리자 감사 11·제재 2·검수요청 1과 연결된 테스트 계정 3개는 보존. 삭제 후 신고 0건. 백업 없이 삭제했으며 복구 불가.

## 검증

- `reports.test.ts` 실행 전후 원격 DB `reports` 건수 110 → 110(잔여물 0). 독립 연결 DB 테스트(가시성·정리 후 0건·타 작품 불변·FK로 삭제 막힐 때 오류 전파·가드 단위 테스트) 통과.
- 정리 후 전체 `npm test` 1147개 통과, `tsc`·lint 통과.
