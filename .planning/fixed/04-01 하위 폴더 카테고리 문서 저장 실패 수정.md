# 04-01: 하위 폴더 카테고리 문서 저장 실패 수정

> 이 버그는 Phase 15(Jev 선계획 기반 문서 생성)로 승격돼 재설계로 해결됐다. 설계 원문은 `.planning/phases/15-jev-ai/15-DESIGN-SOURCE-04-BUG-01.md`에 보존한다(Phase 15 PLAN·CONTEXT가 참조).

## 증상
같은 카테고리에 하위 폴더(예: `인물` → `서브인물`)가 있으면 AI 문서 제안 "문서로 저장하기"와 @멘션 빠른 추가가 `카테고리 폴더를 찾을 수 없어요.`로 실패했다.

## 원인
`resolveCategoryFolderId`가 같은 작품·카테고리 폴더가 하나뿐이라고 가정하고 `.maybeSingle()`을 썼다. 하위 폴더도 부모와 같은 `category`를 가져 두 행이 나오면 에러가 나 `null`이 반환됐다.

## 수정
Phase 15에서 `.maybeSingle()` 가정을 폴더 후보 기반 루트 해석으로 교체했다(8d49025). 저장 위치를 사용자가 고를 수 있게 했다: 빠른 추가는 `저장 폴더` 선택, 문서 제안은 Jev가 폴더·템플릿을 추천하고 서버가 `targetFolderId`를 재검증한다.

## 검증
`15-HUMAN-UAT.md` 브라우저 UAT PASS: 빠른 추가로 `서브인물`에 문서 생성, 문서 제안 저장 후 DB에서 parent가 `서브인물`임을 확인.
