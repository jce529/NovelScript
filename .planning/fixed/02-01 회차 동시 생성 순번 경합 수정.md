# 02-01: 회차 동시 생성 순번 경합 수정

## 증상

같은 작품에서 회차 생성 요청이 거의 동시에 들어오면(두 탭, 더블클릭) 한 쪽이 `chapters_work_order_uniq` 위반으로 실패하고 사용자에게 DB 원문 오류 메시지가 그대로 노출됐다. 데이터 손상은 없고 생성 실패 UX 문제였다.

## 원인

`createChapter`가 `MAX(order_index)` 조회와 INSERT를 별개 요청으로 실행해 잠금이 없었다. 두 요청이 같은 최대값을 읽어 같은 순번을 계산했다. 실패 시 `error.message`를 그대로 반환했다.

## 수정

- `create_chapter_atomic(p_owner_id, p_work_id, p_title, p_folder_id)` RPC 추가(0020). 작품 행을 `FOR UPDATE`로 잠근 뒤 삭제 회차를 포함한 `max(order_index)+1`로 INSERT하고 ID를 반환한다. `SECURITY DEFINER`, 고정 `search_path`, 브라우저 세션은 `auth.uid()`가 소유자와 같아야 하고(서비스 롤은 서버 액션이 세션에서 얻은 ID로 호출), `user_can_write`·소유권·폴더·제목을 함수 안에서 검사한다. `public`/`anon` 실행권 회수, `authenticated`/`service_role`에만 부여.
- `createChapter`는 기존 사전 검사를 유지하고 순번 조회·직접 INSERT를 RPC 호출로 교체. RPC 오류·예외·비정상 응답은 DB 원문 없는 문구로 변환.
- 번호는 0018(Phase 11 예정)·0019(Phase 3) 다음인 0020. 원격 Supabase DB에 적용함.

## 검증

- 신규 `order-race.database.test.ts` 7개: 동시 6회 생성이 0~5로 연속, 잠금 대기 후 다음 순번, 롤백한 요청은 순번 미소비, 작품별 독립, 삭제 회차 순번 유지, 타 소유자·세션 불일치·anon·잘못된 폴더·정지 계정 거부, DB 오류 문구 비노출. 적용 전에는 함수 부재로 실패함을 확인.
- `tests/chapters`·`tests/admin/sanctions.test.ts` 86개 통과(skip 0), `tsc`·eslint 통과. 이후 전체 `npm test` 1147개 통과.
