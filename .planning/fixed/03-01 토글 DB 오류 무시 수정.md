# 03-01: 토글 DB 오류 무시 수정

## 증상
RLS 거부·DB 오류·FK 위반으로 INSERT/DELETE가 실패해도 세 토글이 성공 상태를 반환해, 새로고침하면 원래 상태로 돌아갔다.

## 원인
03-04 구현이 select → insert/delete 단순 형태라 `error`를 읽지 않았다.

## 수정
- 조회·RPC 오류, 예외, 비정상 payload를 안전한 문구의 `error`로 반환하고, 상태를 알 수 없으면 상태 필드를 생략한다(`lib/reader/toggle.ts`).
- 액션은 `ok: false`와 `revalidatePath` 미호출로 처리하고, UI는 기존 실패 토스트로 문구를 표시한다.
- 03-02(원자 RPC)와 같은 커밋 `5a7cd57`로 구현했다.

## 검증
- `tests/reader` 전체와 `tests/admin` 21파일 353 테스트 통과(DB 동시성 테스트 skip 0), lint·tsc 통과(2026-10-02).
- 브라우저(로그인 세션): 좋아요가 정상 반영·유지됨을 확인했다.
- 미확인: 실제 DB 쓰기 실패를 브라우저에서 유발해 토스트를 보는 것. 코드(`like-button.tsx`의 `ok:false` → `toast.error`)와 액션 테스트로 대체했다. 네트워크 500 강제 시에는 서버 액션 예외가 error boundary로 번지는 점을 관찰했다(이 버그 범위 밖).
