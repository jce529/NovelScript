# 08-06: 동시 유료 생성 지갑 직렬화

## 증상

같은 작가가 AI 생성을 동시에 여러 번 보내면(여러 탭, 재생성 연타) 잔액이 넉넉하지 않을 때 일부 요청이 모델 호출이 끝난 뒤 정산에서 `insufficient balance`로 거절됐다. 사용자는 응답을 받지 못하고 플랫폼은 이미 모델 비용을 지불했다. 이중 차감은 원장 제약으로 일어나지 않았다.

## 원인

preflight(잔액 읽기)와 정산(`apply_wallet_delta`) 사이에 잔액 예약이 없고, `debitAmount = min(스냅샷 잔액, 비용)`은 다른 요청이 그 사이 차감한 사실을 모른다. 같은 키의 마지막 잔액 경합만 검증됐고 서로 다른 요청의 동시 실행은 다루지 않았다.

## 수정

확정 정책(사용자 선택 A): 지갑별 직렬화.

- `0021_ai_generation_locks.sql`: 지갑별 lease 테이블(RLS, anon/authenticated 권한 없음)과 service-role 전용 RPC `acquire_ai_generation_lock`(DB 시각 기준, 만료된 lease만 회수)·`release_ai_generation_lock`(토큰 일치 시에만 해제).
- `paid-generation.ts`: preflight를 원장 조회 → lease 획득 → 잔액 조회 순으로 변경. 점유 중이면 공급자 호출 전에 `generation_in_progress` 안내, 획득 오류는 fail-closed. ctx의 멱등 `release()`를 settle이 모든 결과에서 호출하고, 잔액 부족·지갑 없음 등 조기 종료에서도 해제. `chat()`·재생성은 `finally`로 추가 해제(문서 계획 분기는 `chat()`의 finally가 커버). 해제 RPC 실패는 로그만 남기고 TTL로 복구.
- 시간 경계(정책 A): 공급자 호출 120초 상한(`PROVIDER_CALL_TIMEOUT_MS`, Gemini `abortSignal`·OpenAI/Anthropic `signal`+`timeout`, `maxRetries: 0`)과 lease TTL = 상한 + 60초(180초). 갱신(B안) 없음.
- `generation_in_progress` 종류와 문구를 재시도 가능한 알림으로 추가.

## 검증

- `paid-generation-lock.database.test.ts`: 독립 연결 동시 획득은 1건만 성공, 다른 지갑 병행, 토큰 조건 해제, 만료 회수 후 구 토큰 해제 거부, 권한. `paid-generation`·`chat-idempotency`·`regenerate-document` 테스트에 점유·해제·fail-closed 케이스 추가, 기존 "같은 키 동시 2회 호출" 기대를 직렬화 정책에 맞게 갱신.
- `tests/ai tests/admin tests/chapters tests/reader` 930개 통과(DB skip 0), 이후 전체 `npm test` 1147개 통과, `tsc`·eslint 통과. 0021은 원격 Supabase DB에 적용함.
- 한계: lease 만료 시점에 이미 발송된 외부 요청의 중복 과금은 완전히 배제하지 못한다. 배포 중 구버전 요청은 lease를 잡지 않으므로 롤링 배포 구간의 직렬화는 보장되지 않는다. 공급자별 취소 후 과금 여부와 배포 플랫폼 실행 시간 제한은 미확인.
- 후속: Phase 11 11-04/11-05가 BYOK 분기를 넣을 때 service 유료 분기에만 lease를 유지하고 BYOK 제외 회귀 테스트를 추가해야 한다.
