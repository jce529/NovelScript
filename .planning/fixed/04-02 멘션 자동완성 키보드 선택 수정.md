# 04-02: @멘션 자동완성에서 Enter가 선택 대신 줄바꿈

## 증상

원고 편집기에서 `@오수`를 입력하면 자동완성 목록에 `오수진 / 인물`이 떴지만, Enter를 눌러도 멘션이 선택되지 않고 원고에 줄바꿈만 들어갔다. 마우스 클릭으로만 선택이 가능했다.

## 원인

`MentionAutocomplete`는 cmdk `Command`(`shouldFilter={false}`)를 Popover 안에 렌더했지만 포커스는 계속 원고 textarea에 남아 있었다. cmdk의 키보드 탐색은 `Command`가 키 입력을 직접 받을 때만 동작하는데, textarea와 자동완성 목록 사이에 키보드 연결이 없어 Enter가 textarea의 기본 줄바꿈 동작으로 처리됐다.

## 수정

- 자동완성이 열려 있는 동안 textarea의 `keydown`을 가로채 위/아래 방향키로 후보를 순환하도록 했다.
- Enter/Tab은 활성 후보를 선택하고, Escape는 목록을 닫는다.
- 후보가 없을 때 Enter는 textarea의 기본 줄바꿈 동작을 그대로 유지한다.
- cmdk의 선택값을 후보 ID로 제어해 키보드 이동과 화면 강조 항목을 일치시켰다.
- 한글 IME 조합 중인 Enter(`keyCode 229`, `isComposing`)는 가로채지 않는다.
- 키 판정 로직을 `lib/ai/mention-keyboard.ts`의 순수 함수로 분리했다.

## 검증

- 자동: `npx vitest run tests/ai/mention-keyboard.test.ts` 9개 통과, `npx tsc --noEmit` 통과, 변경 범위 eslint 통과.
- 브라우저(2026-09-23, 재현용 작품 `e33f73fb-c36f-402e-9f20-1622aa04a01f` / 챕터 `30822040-ac4d-4960-b32e-f4179a1cfb29`):
  - `@오수` 입력 후 Enter → 첫 후보(오수진) 선택, 트리거 텍스트 제거, "멘션된 문서"에 추가됨, 줄바꿈 없음.
  - `@인` 입력 후 ↓ 방향키로 두 번째 후보로 강조 이동, Tab으로 선택됨.
  - `@장` 입력 중 Escape → 목록 닫힘, 원고 내용 변화 없음.
  - 트리거 없는 상태에서 Enter → 정상적으로 줄바꿈 입력됨.
  - `CompositionEvent`(compositionstart/update/end)와 `keyCode 229`, `isComposing: true`인 keydown을 dispatch해 IME 조합 확정 시나리오를 재현 → 핸들러가 `preventDefault`하지 않고 텍스트도 변경되지 않음(가로채지 않음 확인).
