# 18-02: 비로그인 홈 피드 타임아웃

## 증상
공유 DB(0033~0036 적용 뒤)에 연결한 앱에서 로그인하지 않고 `/`을 열면 서버 오류 화면이 뜬다. 서버 콘솔에는 `canceling statement due to statement timeout`이 `listFeed`에서 발생한다. 같은 피드가 로그인한 상태에서는 정상이다(authenticated의 제한시간이 더 길다). 공유 DB 마이그레이션 적용 직후 스모크에서 발견했다(2026-11-05).

## 원인
0036이 `works_public_read`와 `chapters_public_read`를 값싼 조건에서 행마다 `world_work_public_meta_visible(...)`을 부르는 조건으로 바꿨다. 이 함수는 `STABLE SECURITY DEFINER`라 인라인되지 않고, 안에서 `world_work_reader_visible`을 중첩 호출해 한 번에 works·chapters를 4번 안팎 조회한다. 피드는 works에 chapters를 붙여 읽으므로 호출 수가 (작품 수 + 회차 수)에 비례한다. 공유 DB에서 작품 511개·회차 625개가 anon에게 보이는 규모에서 단순화한 쿼리가 1.4초였고 실제 경로는 anon 제한시간(약 3초)을 넘었다. 개발 데이터에는 발행 회차가 거의 없어 드러나지 않았다.

## 수정
정책의 의미는 바꾸지 않고 호출당 비용만 줄이는 `0050_feed_public_read_cost.sql`(A+D안).
- `world_work_base_visible(uuid)`: chapters 정책용 한 번 조회 헬퍼(작품이 삭제·가지 초안이 아님). 회차 행이 이미 발행·미삭제라서 "발행 회차 존재"는 항상 참이므로 그 조건을 뺐다.
- `world_work_public_meta_visible`: 중첩 호출 없이 한 질의로 재작성(0036과 같은 진리표).
- `chapters_public_read`: 새 헬퍼를 쓰도록 교체.
- 부분 인덱스 `chapters_work_published_idx (work_id) where is_published and deleted_at is null`.
- 피드 캐싱과 페이지 크기 축소(D의 나머지)는 하지 않았다. 부족하면 추가한다.

## 검증
- DB 테스트(일회용 `anzafn…`, `--mode disposable`): `public-read-cost.database` + `visibility.database` **29/29 통과**. 32개 조합의 진리표 동등성, anon 노출, 정책 본문에 중첩 호출 없음, 인덱스 존재, 헬퍼 EXECUTE 권한을 고정한다. 테스트 쪽 결함 두 개(차단 작품 시드의 `works_admin_blind_shape` 제약 위반, 함수 머리글 이름을 중첩 호출로 세던 검사)를 고쳤다.
- EXPLAIN(격리 스키마, 작품 500·발행 회차 1,000, 롤백): anon 피드 쿼리 **225ms → 22ms**(약 10배), buffers 11,010 → 8,010.
- 공유 DB 적용(2026-11-11, 승인): `apply-pending-migrations.mjs --allow-shared`로 0050 한 파일, 416ms 성공. 적용 뒤 쿠키 없이 `localhost:3000/`을 세 번 요청해 **모두 HTTP 200**(이전 500), 서버 로그에 timeout 없음. 개발 서버 응답 시간(첫 25초, 이후 6.3초·3.8초)은 컴파일과 약 600KB 렌더가 섞여 DB 시간의 근거로 쓰지 않는다.
- 수용한 위험: 새 헬퍼는 정책이 호출자 권한으로 평가되므로 anon에게 EXECUTE가 필요하다. 기존 `world_work_reader_visible`·`world_work_public_meta_visible`도 이미 anon에게 열려 있어 같은 종류의 존재 여부 질의가 가능했다. 새 헬퍼는 발행 회차가 없는 미삭제 작품에도 참을 돌려줘 범위가 조금 넓지만, 작품 ID가 v4 UUID라 추측이 어렵고 제목·내용은 노출하지 않는 불리언이다. Phase 14 병합 때 Codex 검토가 같은 지적을 냈다.
