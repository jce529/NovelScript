# 15-05: 재생성 링크 가드 KB 문서 허용 수정

## 증상
링크 없는 인물 제안을 저장 모달에서 "기본 인물 템플릿"으로 다시 생성하면, 모델이 정상 응답을 줘도 "문서를 다시 생성하지 못했어요"로 매번 거부됐다.

## 원인
BUG-04 수정의 링크 가드가 "재생성 링크 대상 ⊆ 원본 링크 대상"만 검사해, 템플릿의 관계 칸을 KB 실존 문서 링크로 채우는 정상 재생성까지 막았다. KB 존재 여부는 조회하지 않았다.

## 수정
- 원본에 없던 새 링크 대상이 있을 때만 KB를 조회해, 본인의 이 작품 file 문서(5개 카테고리+`custom`)와 계정 공유 file 문서에 모두 실존하면 허용한다. 하나라도 없거나 조회 오류면 거부(fail closed). 다른 작품·사용자·삭제·폴더·템플릿 스텁은 제외.
- 프롬프트에 링크 가능한 KB 문서 이름(작품·계정 각 최대 200개, 자기 이름 제외)을 알려 "목록에 없는 이름은 링크 없이 일반 텍스트로"라고 지시한다. 목록이 없거나 조회 실패면 새 링크 금지 문구로 대체.
- 이름 유지·본문 제목 검증·원본 자기 링크 보존은 그대로.

## 검증
- 단위 테스트 8건 추가(통과/거부/범위 제외/조회 오류/조회 생략/자기 링크 보존/프롬프트 목록·금지 문구), `tests/ai tests/kb tests/studio` 62파일 643 통과, tsc·lint 통과.
- 실제 DB에 같은 필터로 조회해 실존 문서는 찾고 없는 이름은 못 찾음을 확인.
- 브라우저(2026-10-02, 테스트 DB): 링크 없는 원본을 `기본 인물 템플릿`으로 재생성·저장 성공(링크는 `[[강진욱]]`뿐, KB 실존). 링크 있는 원본(`[[강진욱]]`·`[[박도현]]`)을 `UAT링크없음`으로 재생성·저장 성공(저장본 링크 KB 실존, 제목 유지). 테스트 문서는 삭제함.
- 미확인: 계정 템플릿 `인물` 재생성(Gemini 429), 반복 안정성(성공 각 1회), 200개 초과 문서 작품의 목록 누락.
- 범위 밖(별도 결정): 가드 거부 뒤 같은 템플릿으로 재시도 시 "같은 요청이 두 번 전송돼…"가 먼저 뜨는 문제 — 거부된 유료 생성의 재시도 과금 정책이 필요.
