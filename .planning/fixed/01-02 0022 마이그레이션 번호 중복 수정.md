# 01-02: 0022 마이그레이션 번호 중복 수정

## 증상
`0022_account_deletion_purge.sql`(Phase 1)과 `0022_template_readonly_backfill.sql`(Phase 2)이 공존해 `numbering.test.ts`가 실패했다.

## 원인
병렬 phase가 같은 번호를 잡았다. 06-01과 같은 유형이다.

## 수정
사용자 결정으로 의존이 없고 코드 참조가 0건인 purge를 빈 번호 0028로 `git mv`(SQL 본문 변경 0줄). 0023이 backfill 0022 뒤에 와야 하는 조건과 15개 파일의 backfill 참조는 그대로 유지. 번호 가드는 예외 없이 엄격하게 유지.

## 검증
`numbering.test.ts` 통과, 전체 suite에서 중복 실패 해소. `apply-migration.mjs`는 이력을 기록하지 않아 DB 영향 없음. 공유 DB에 purge가 이미 적용됐는지는 사용자가 확인해야 한다(이 작업은 어떤 DB에도 적용하지 않음).
