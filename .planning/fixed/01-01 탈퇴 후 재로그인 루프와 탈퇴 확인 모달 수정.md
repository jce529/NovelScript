# 01-01: 탈퇴 후 재로그인 루프와 탈퇴 확인 모달 수정

## 증상

- "계정 탈퇴하기"가 확인 없이 즉시 실행됐다.
- 탈퇴한 계정으로 같은 Google 계정에 다시 로그인하면 로그인은 되지만 보호 페이지(설정 등)로 이동할 때마다 `/login`으로 튕겼다. 몇 번을 로그인해도 반복되고 새 계정으로 가입할 방법이 없었다.

## 원인

- 탈퇴가 `profiles.deleted_at`과 `pen_name_bio`만 갱신하는 soft delete였다. auth 사용자와 소셜 연결(`auth.identities`)이 그대로라 재로그인하면 같은 user id로 세션이 만들어지고, 모든 보호 경로가 `isAccountActive`로 로그아웃시켰다.
- `/auth/callback`은 세션 교환 직후 탈퇴 여부를 확인하지 않았다.
- 탈퇴 버튼이 확인 없는 단순 `<form action>`이었다.
- 부수 문제: BYOK 키(Vault 시크릿 포함)와 필명이 탈퇴 후에도 남았다.

## 수정

정책(2026-10-09 사용자 확정): 재로그인 시 새 계정으로 가입, BYOK 키·개인정보만 삭제, 지갑·원장·작품·주문은 append-only(D-08)로 보존.

- `0022_account_deletion_purge.sql`(원격 적용): `purge_account_data(p_owner)` — BYOK 시크릿·키·검증 로그 삭제, 필명·소개 비움, `deleted_at`은 최초 시각 유지, `auth.identities` 삭제. 멱등, service_role 전용.
- `softDeleteAccount`: `purge_account_data` → `auth.admin.deleteUser(id, true)`(이메일 익명화) 순서. 사전 검증에서 soft delete만으로는 identity가 남는다는 것을 확인해 identity 삭제를 DB 함수에 넣었다. 오류는 던지고 재시도하면 이어서 끝난다.
- `deleteAccountAction`은 `{ok, message}`를 반환. 실패하면 세션을 유지해 같은 버튼으로 재시도할 수 있다.
- `DeleteAccountButton` 확인 모달: "정말 탈퇴할까요?", 되돌릴 수 없음·삭제/보존 항목 안내, 취소에 초기 포커스, 처리 중 중복 클릭·닫기 방지, 실패 문구.
- `/auth/callback`: 탈퇴 표시만 된 기존 계정이 로그인하면 그 자리에서 탈퇴를 마무리하고 세션을 버린 뒤 `/login?error=account_deleted`로 보낸다. 별도 일회성 정리 스크립트는 필요 없었다.

## 검증

- `tests/auth` 25건(DB 테스트 5건: 개인정보·BYOK·identity 정리, 지갑/원장 보존, 같은 이메일 재가입, 멱등, 레거시 반쯤 삭제 계정 마무리, 프로필 없음 시 실패 / UI·callback 테스트), `sanctions.database`·`byok-db` 25건 통과, `tsc --noEmit`·eslint 클린.
- 실계정(Google) 확인: 옛 새작가 계정이 로그인하자 callback이 탈퇴를 마무리(identity 0, 이메일 해시, auth soft delete, 잔액 10857 보존)했고, 같은 구글 계정이 새 계정(reader, 잔액 0, 필명 없음)으로 가입됐다. `/account`에서 확인 모달 표시·취소 초기 포커스·취소 시 닫힘을 브라우저로 확인했다.
- 미확인: 모달에서 "탈퇴하기"를 눌러 끝까지 가는 경로를 실계정으로 누르지는 않았다(해당 경로는 자동 테스트와 DB 검증으로만 확인). 기존 로그인하지 않는 테스트 계정 12개는 `deleted_at`만 찍힌 채 남아 있으나 접근 경로가 없다.
