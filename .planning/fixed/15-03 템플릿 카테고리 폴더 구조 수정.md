# 15-03: 템플릿 카테고리 폴더 구조 수정 (일부)

> Phase 15 `BUG-03`의 검증 완료 부분이다. 브라우저에서 확인하지 못한 항목은 `.planning/phases/15-jev-ai/bugs/BUG-03-*.md`에 남겼다.

## 증상

"인물" 문서의 저장 모달 "템플릿 변경" 목록에 장소·사건·세력·아이템 템플릿이 그대로 나오고, 작품/계정에 같은 이름이 있으면 두 번씩 보였다. 다른 카테고리 템플릿을 고르고 "다시 생성하기"를 누르면 재생성 결과가 검증에서 탈락해 실패했다.

## 원인

`listTemplateOptions`가 `category`를 기본값 판정과 캐노니컬 이름에만 쓰고 작품/계정 템플릿 폴더의 파일을 카테고리 필터 없이 전부 추가했다. 템플릿 파일 노드는 전부 `category='template'`이라 어느 문서 카테고리용인지를 담는 필드가 스키마에 없었다.

## 수정

컬럼을 추가하지 않고 **폴더 위치가 카테고리**가 되도록 구조를 바꿨다(작품·계정 각각 `template/인물·장소·사건·세력·아이템`, 잠금).

1. 마이그레이션 `0012`: 모든 템플릿 루트에 카테고리 폴더 5개를 만들고 이름=카테고리 파일을 이동한다. 커스텀 이름 파일은 루트에 둔다. 재실행 안전. `create_work`/`ensure_account_template_root`도 같은 구조를 만들도록 갱신.
2. 서버: 템플릿 루트 조회에 `parent_id is null` 추가, `listTemplateOptions`/자동 오버라이드가 카테고리 폴더 직속 파일만 사용, `createFolder`가 템플릿 트리의 새 폴더를 거부, `createNode`가 카테고리 폴더 직속 템플릿만 허용하고 캐노니컬 원문을 시드, `moveTemplateFile(Action)` 추가.
3. UI: KB 트리에서 템플릿 루트·카테고리 폴더의 새 폴더 버튼 숨김, 템플릿 전용 생성 다이얼로그, "카테고리 폴더로 이동" 다이얼로그, 저장 모달·문서 만들기의 템플릿 선택을 작품/계정/기본 그룹으로 분리.

## 검증

- 테스트 DB에 `0012` 적용 후 `verify-0012.sql` [B]/[C] B1~B8 전부 0행, 카테고리 폴더 10,935 = 루트 2,187 × 5, 재적용 후에도 동일, `create_work`/`ensure_account_template_root` 신규 경로 통과.
- 브라우저 UAT(2026-09-29): 작품·계정 `template` 트리 구조와 잠금·버튼(루트 무버튼, 카테고리 폴더는 "하위 문서 추가"만), 카테고리 폴더에서 템플릿 생성(원문 시드, `<% tp.file.title %>` 유지)과 이름 충돌 안내, "카테고리 폴더로 이동"(셀렉트가 이름 표시, `장소`로 이동 성공), 저장 모달 목록의 3그룹·인물용만·기본값 "(기본)", 문서 만들기 다이얼로그의 제목 치환.
- 미검증(BUG-03 문서에 남김): 미분류 표시, 이동 후 다른 카테고리 문서의 목록 반영, 목록 전 항목 재생성, AI 추천 후보.
- 한계: 이 테스트 DB에는 이름=카테고리 파일이 없어 `0012`의 파일 이동·내용 보존(B4) 경로는 검사할 대상이 없었다.
