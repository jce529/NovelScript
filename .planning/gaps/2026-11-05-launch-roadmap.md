# 출시까지의 순차 목표와 우선순위 (2026-11-05)

> 제안 문서다. ROADMAP·STATE는 이 문서를 근거로 사용자가 정한 뒤에 고친다. 시점 스냅샷이며, 출처는 ROADMAP·REQUIREMENTS·STATE·`gaps/2026-10-23-manual-gate-results.md`·`gaps/2026-11-03-shared-db-catchup-plan.md`다.
> "출시"는 PROJECT.md 정의를 따른다: 커뮤니티에서 모은 베타 유저(작가·독자)로 반응을 검증하는 MVP. ROADMAP Launch Gate는 "베타·내부 테스트는 제외, **서비스 공개 전**에 충족"이라고 못 박고 있어 출시를 두 단계로 나눈다.

- **베타 출시(폐쇄·초대):** 법무 게이트 없이 가능. 핵심 루프(작가: 설정집·에디터·AI·발행 / 독자: 탐색·뷰어 / 지갑)가 실서버에서 사람 검증을 통과한 상태.
- **공개 출시:** 베타 조건 + 법무 게이트 + 실결제(Toss) + 운영 안정성.

## 1. 지금 출시를 막는 것 (사실)

1. **만든 것이 공유 DB에 없다.** 공유 DB는 0001~0021·0028뿐이고 master보다 마이그레이션 16개(0010·0022~0027·0029·0030·0032~0039)가 뒤처져 있다. Phase 3 독자 상태, Phase 4 작품별 AI 지시, Phase 5 충전 단계, Phase 7 관리자 보강, Phase 11 정산, Phase 12~13 MCP, Phase 18 세계수가 실서버에서 동작하지 않는다. 적용 순서·리허설은 끝났고 **백업이 없어** 보류 중이다.
2. **사람 검증이 쌓여 있다.** 에이전트가 기능 점검은 했지만(10-23) 사람 승인은 아니다. 03-19(독자 흐름), 04-12(AI 패널), 07-15(관리자), 16-03, 18-12, 12-06 #7~#9, BYOK 10-10·11-08·11-12.
3. **결제가 막혀 있다.** 05-07이 Toss 키 종류 불일치(`test_gck_` vs 필요한 `test_ck_/test_sk_`)로 막혀 있고, 실결제는 가맹점 심사(외부 대기열, 통상 2주 이상)가 크리티컬 패스다.
4. **법무는 시작 전이다.** LEGAL-01~04 전부 Not started. 변호사라는 외부 대기열이라 늦게 시작할수록 출시일이 밀린다.

## 3. 출시 후로 미루는 것 (v1.2+ 후보)

독자 공간(랭킹 창, 연재 목록, 내서재, 검색, 작가 페이지, 명예의 전당), 댓글, 완독 데이터(스크롤 진도·완독률·연독률), 작가 허브(대시보드·경제 관리·정산·설정 허브), 결제 확장(대여·정주행·구독·결제 내역), Phase 6의 대여·정주행·소장함·정산 화면, 관리자 확장(제재 이력·정산 보류), 에셋 스토어, 세계수의 스토어 연동(WTREE-11~13)과 스포일러 잠금(WTREE-09), Lore 위키(READ-06), MCP prompts·resources(MCP-10·11), SLM 자동 검수.

> 주의: 이 중 일부(검색, 내서재, 작가 페이지, 댓글)는 독자가 "플랫폼"으로 인식하는 최소 기대일 수 있어 공개 출시 범위에 넣을지 결정이 필요하다(4절).

## 4. 순차 목표

**Stage 0 — 지금 (사람 작업, 병행)**
1. Toss: 새 API 개별 연동 키(`test_ck_`/`test_sk_`) 확인, 가맹 심사 상태 확인.
2. 변호사 자문 의뢰(우선순위 A 항목).
3. 백업 방법 결정(Pro 업그레이드 또는 내보내기 스크립트).

**Stage 1 — 베타 준비 (게이트: "초대한 사람이 실서버에서 핵심 루프를 끝까지 쓸 수 있다")**
1. 공유 DB 따라잡기(P0).
2. 배포 환경과 OAuth·환경변수 확정.
3. 핵심 루프 사람 검증 일괄 처리(03-19, 04-12, 16-03, 07-15, 18-12, 12-06 #7~#9).
4. 알려진 결함 정리(Phase 17 UAT, 타입체크·린트 기준선).

**Stage 2 — 베타 운영 중 병행 개발**
1. Phase 14 완료와 Claude 실연동 인수.
2. ~~Phase 19 작품 홈(목업 포함)~~ 구현 완료 → 실화면 UAT는 Stage 3의 Phase 20과 함께 확인(후순위).
3. 토큰 환산값 조정 → Toss 샌드박스 결제 검증.
4. BYOK 사람 검증(실제 키).
5. 베타 사용 데이터로 Phase 15 Jev 활성화 판단.

**Stage 3 — 공개 출시 준비 (게이트: 법무 + 실결제 + 운영)**
1. 법무 게이트 4개 완료, 약관·처리방침 게시.
2. Toss live 전환.
3. Phase 20 모바일 실기기 + Phase 19 작품 홈 실화면 UAT(데스크톱·375px).
4. 운영 안정성: 백업·복구 절차, 오류 모니터링, 비용 상한(이 항목은 ROADMAP에 없고 이 문서가 제안하는 것이다).
5. 공개 범위 결정(독자 공간 최소 세트 포함 여부).

**Stage 4 — 출시 후**: 3절 목록을 새 마일스톤으로 요구사항 ID와 함께 정의.

## 5. 결정이 필요한 것

1. **베타를 먼저 낼지, 공개까지 한 번에 갈지.** 베타 먼저가 위험이 작고 법무 대기와 병행된다.
2. **백업:** 베타 전 공유 DB는 데이터가 테스트뿐이라 백업 없이 진행하기로 했다(2026-11-05). 공개 출시 전에는 실제 사용자·결제가 생기므로 Pro 또는 자체 내보내기를 다시 결정한다.
3. **공개 출시 범위:** 독자 공간 최소 세트(검색·내서재·작가 페이지)와 댓글을 공개 전에 넣을지, 출시 후로 미룰지.
4. **ROADMAP 반영:** 이 순서를 ROADMAP의 Execution Order와 새 phase(운영 안정성, v1.2 마일스톤)로 옮길지.
