# AI 연결 확장 목표

상태: 목표·범위 합의, 구현 미착수
작업 브랜치: `codex/multi-provider-byok`
기존 MVP 진행 브랜치: `master`

## 1차 목표: 멀티 AI 제공자 연결 + BYOK

NovelScript 편집기 안에서 기존 Gemini와 다른 AI 제공자를 선택하고,
사용자 자신의 API 키로 AI 집필 기능을 사용할 수 있게 한다.

### 구현 범위

- 기존 Gemini 연결을 유지하면서 공통 AI 인터페이스와 제공자별 어댑터를 도입한다.
- 초기 추가 제공자는 앞선 설계의 OpenAI·Claude를 기준으로 한다.
- 제공자·모델 선택과 모델별 지원 옵션·사용량·비용 처리를 분리한다.
- BYOK 키 등록·검증·암호화 저장·교체·삭제 기능을 구현한다.
- 키의 소유권을 서버에서 검증하고, 저장한 키를 클라이언트나 로그로 반환하지 않는다.
- 서비스 키 모드와 BYOK 모드를 분리한다. BYOK는 기본적으로 서비스의 AI 토큰을 차감하지 않는다.
- 기존 대화·설정집 참조·본문 초안·설정 제안 기능을 유지한다.
- 제공자 오류·사용 한도·타임아웃·사용 기록과 중복 정산 방지를 처리한다.

### 완료 기준

- [ ] Gemini 및 추가 제공자에서 편집기 대화·초안 생성 흐름이 동작한다.
- [ ] 사용자별 BYOK 등록부터 선택·호출·교체·삭제까지 연결된다.
- [ ] 타인의 키 사용·키 노출·BYOK 이중 과금이 차단된다.
- [ ] 서비스 키의 비용 제한·정산과 기존 기능 회귀 테스트가 통과한다.
- [ ] 실제 API 연결 검증 결과와 남은 환경 제약을 구분해 기록한다.

### 구현 순서

공통 인터페이스 및 Gemini 전환 → 추가 제공자 어댑터 → BYOK 저장·인증 →
결제 모드·사용 기록 → 설정/AI 패널 → 통합·회귀 검증.

## 2차 목표: 기존 구독 AI와 연결

1차 목표 이후 진행한다. 사용자가 평소 사용하는 구독 AI에서 NovelScript의
작품·회차·설정집을 활용하고 결과물을 저장할 수 있게 한다.

### 구현 범위

- MCP 등 각 제공자가 공식 지원하는 연결 경로를 검토하고 구현한다.
- 작품 목록, 회차·설정집 조회, 초안 저장, 설정 변경안 제안 도구를 제공한다.
- NovelScript 계정 연결·사용자별 권한 범위·연결 해제를 구현한다.
- 생성 결과는 검토 가능한 초안/제안으로 저장하고 기존 본문을 자동 덮어쓰지 않는다.
- 제공자별 지원 범위와 설정 과정을 안내한다.
- 구독 AI 연결을 일반 API 호출 권한으로 취급하지 않는다.

### 완료 기준

- [ ] 지원 대상 구독 AI에서 공식 연결 절차로 NovelScript에 접속할 수 있다.
- [ ] 사용자가 자신의 작품·설정집을 읽고 생성 결과를 초안으로 저장할 수 있다.
- [ ] 타인 작품 접근·무단 덮어쓰기·연결 해제 후 접근이 차단된다.
- [ ] 별도 모델 API 호출이 필요한 경로와 기존 AI에서 생성하는 경로가 명확히 구분된다.
- [ ] 실제 지원 클라이언트에서 전체 흐름을 검증한다.

지원할 클라이언트와 배포 방식은 2차 착수 시 공식 지원 여부를 다시 확인해 확정한다.
모든 구독 서비스를 일괄 지원한다고 가정하지 않는다.

## 단계 간 경계

- 1차에서는 API 기반 연결과 BYOK에 집중한다. MCP·구독 계정 연결은 2차 범위다.
- 복사·가져오기 방식은 별도 후보이며 현재 확정한 1차 필수 범위에 추가하지 않는다.
- 두 단계 모두 기존 MVP와 사용자/작품/회차 모델을 재사용한다.
- 본 문서의 목표 확정은 구현 완료를 의미하지 않는다.
