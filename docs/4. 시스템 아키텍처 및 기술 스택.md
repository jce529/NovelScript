본 플랫폼은 초기 구축 및 유지보수 비용을 최소화(Pay-as-you-go)하면서도, 대규모 트래픽과 무거운 AI 추론(Inference) 워크로드를 견딜 수 있는 **서버리스(Serverless) 및 로컬 퍼스트(Local-First) 아키텍처**를 채택한다.

### 4.1. 프론트엔드 및 상태 관리 (Frontend & State Management)

복잡한 텍스트 에디터와 AI 챗봇이 유기적으로 얽힌 웹 IDE 환경을 쾌적하게 구현한다.

- **프레임워크:** **React / Next.js** (반응형 웹 기반의 텍스트 에디터 및 대시보드 구축)
    
- **호스팅:** **Vercel** (서버리스 웹 호스팅으로 트래픽 폭증 시 자동 스케일아웃 대응)
    
- **상태 관리 (Local-First):** **Zustand**
    
    - **인메모리(In-Memory) 처리:** 유저가 타이핑하며 생성하는 마크다운 위키 링크(`[[ ]]`) 파싱 및 관계도 업데이트를 서버 통신 없이 브라우저 메모리 단에서 즉각 처리하여 쾌적한 UX(Zero-Latency)를 제공한다.
        
    - **휘발성 방어:** Zustand `persist` 미들웨어를 활용해 메모리 상태를 브라우저 `localStorage/IndexedDB`에 실시간 캐싱하여, 브라우저 종료 및 새로고침 시 데이터 유실을 방어한다.
        
    - **일괄 저장 (Batch Save):** 서버(DB) 트랜잭션 비용을 최소화하기 위해, 유저의 입력이 멈춘 후(Auto-save) 또는 명시적 저장 시점에만 백엔드로 데이터를 전송한다.
        

### 4.2. 백엔드 및 데이터베이스 (Backend & BaaS)

'노벨 토큰(Robux형 경제)'의 무결성 보장과 AI 설정집 데이터를 효율적으로 관리한다.

- **BaaS 플랫폼:** **Supabase** (서버 인프라 직접 관리 없이 DB, 인증, 스토리지 활용)
    
- **메인 데이터베이스:** **PostgreSQL** (결제 트랜잭션, 토큰 환전 등 금융 수준의 무결성 보장)
    
- **커넥션 풀링(Connection Pooling):** 서버리스 환경의 DB 커넥션 고갈을 막기 위해 **PgBouncer / Supavisor**를 필수적으로 경유하여 트래픽 병목을 해소한다.
    

### 4.3. AI 파이프라인 및 코어 알고리즘 (AI Pipeline & Algorithms)

LLM의 연산 비용(토큰)을 극단적으로 최적화하고 할루시네이션을 방어한다.

- **관계 지역성(Relationship Locality) 캐싱 알고리즘:**
    
    - 문서 간 양방향 링크(`[[ ]]`)의 가중치(Degree)와 최신성(Time Decay)을 점수화하여 프롬프트 캐싱 우선순위를 결정한다. 자주 참조되는 핵심 설정집은 캐시에 상주시키고, 오래된 단발성 설정은 방출(Evict)하여 비용을 최적화한다.
        
- **pgvector 기반 암묵적 RAG:**
    
    - Supabase의 `pgvector` 확장을 활용해 마크다운 문서를 벡터 임베딩으로 저장한다. 작가의 현재 타이핑 문맥을 분석하고 '관계 지역성 가중치'를 곱합 하이브리드 검색을 통해, 가장 적합한 설정 문서를 자동으로 AI 컨텍스트에 주입한다.
        
- **실시간 AI 어시스트 (Ghost Text):**
    
    - 디바운싱(Debouncing) 기법을 적용하여 작가의 타이핑이 일정 시간 멈출 때만 API를 호출한다.
        
    - 비용이 높고 연결이 불안정한 WebSocket 대신, SSE (Server-Sent Events)를 도입하여 백엔드에서 생성된 텍스트를 프론트엔드로 끊김 없이 단방향 스트리밍한다.
        
- **완독률/연독률 산출 알고리즘 (스크롤 심도 기반):**
    
    - **유효 완독 판별:** 프론트엔드에서 유저의 스크롤 속도와 위치를 실시간 트래킹하여, 방치형 허수 체류(오래 열어두고 자리 비움)나 광클 스킵(비정상적으로 빠른 스크롤)을 필터링한다. 유효한 속도로 본문 하단에 도달했을 때만 백엔드에 '유효 완독 1스택'을 전송한다.
        
    - **랭킹 점수화:** 단순 조회수(클릭)를 배제하고, 회차별 유효 완독 수와 다음 화로 이어지는 '연독률'을 합산 점수화하여 실시간 랭킹(Trending Now)에 반영한다.
        
    - **콜드 스타트 방지 (신인 작가 보호):** 신규 작품은 일일 메인 노출 쿼터제를 적용해 초기 노출 기회를 공평하게 부여한다. 단, **최소 10화(또는 누적 5만 자) 이상** 연재된 작품만 '루키 쿼터존' 등 메인 홈의 기본 트래픽 노출 대상이 되며, 그 이전 단계(1~3화)의 연독률이 현저히 저조한 작품은 추천 알고리즘에서 빠르게 제외한다.
        
- **경량 모델(SLM) 비동기 필터링 큐 (사전 방역 파이프라인):**
    
    - **인프라:** **Google Cloud Run** 등의 서버리스 함수 환경에 경량화 텍스트 비교/분류 모델(SLM)을 띄워, 원고 제출(Submit) 시 비동기 워커 큐(Worker Queue)를 통해 저비용으로 사전 필터링한다. 원고는 제출 즉시 노출되지 않고 대기(Pending) 상태로 전환된 뒤 큐에서 순차 검수된다.
        
    - **검증 항목 1 — 시놉시스-본문 정합성:** 유저가 제출한 시놉시스/하이라이트와 실제 등록된 원고 본문을 경량 모델로 비교하여 내용이 일치하는지 판별한다. 일치 시 메인 노출 승인, 불일치 시 '보류(Hold)' 상태로 전환하고 운영 대시보드로 이관한다.
        
    - **검증 항목 2 — 기존 IP 표절 여부:** 등록된 원고에서 기존 유명 IP의 고유명사·설정과의 표절 패턴을 경량 모델로 탐지하여, 저작권 리스크가 있는 콘텐츠를 사전에 걸러낸다.
        
    - **블라인드 로그 및 휴먼 리뷰 (3-Strike Out 제재 체계):** AI 검수에서 이상 징후가 발견되거나 독자 신고가 누적되면 해당 회차는 즉시 노출이 차단(Blind)되며, 계정에 '위반 의심 로그'로 기록된다. 이 로그는 운영 직원 대시보드로 이관되어 직원이 직접 검토하며, 오탐지일 경우 해제하고 실제 위반일 경우 '확정 패널티'로 전환한다. 미해결 로그 및 확정 패널티가 일정 수치를 초과하거나 확정 패널티가 3회 이상 누적되면 계정을 영구 정지한다.
        

### 4.4. 보안 및 데이터 무결성 (Security & Data Resilience)

BYOK(Bring Your Own Key) 생태계의 치명적 리스크인 API 프록시 어뷰징을 방어한다.

- **API Key Vault:** 유저가 등록한 외부 LLM API 키는 Supabase Vault(또는 AWS KMS)를 통해 DB에 강력하게 암호화되어 저장된다.
    
- **레이트 리미트 & 서킷 브레이커:** 백엔드 엣지(Edge) 단에서 IP 및 세션 기반의 엄격한 API 호출 제한(Rate Limiting)을 걸어, 해커의 봇 타격을 통한 API 요금 폭탄을 원천 차단한다.
    
- **데이터 복구력:** PostgreSQL의 시점 복구(PITR) 기능을 지원하며, 테이블 설계 시 논리적 삭제(`Soft Delete`, `deleted_at`)를 기본 채택하여 유저의 실수로 인한 설정집 영구 삭제를 방지한다.
